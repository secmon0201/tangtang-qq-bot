# QQ 本地数据机器人

这是一个运行在 Windows 本机的 NoneBot2/OneBot v11 QQ 群机器人。QQ 登录由本机 NapCatQQ 完成，机器人只接收 OneBot 事件并将聚合数据保存在本地 SQLite。

全部有效文档见：[文档总览](docs/README.md)。完整的安装、启动、关闭、命令、热更新、被动互动、活动、备份和故障排查说明见：[安装与运行](docs/运维-安装与运行.md)。AI 和代码维护者先阅读 [AGENTS.md](AGENTS.md)。

Git 提交范围、目录职责和上游独立更新方式见：[Git 与上游](docs/运维-Git与上游.md)。整个自研 QQ 机器人使用同一个主仓库，NTE 排行榜、帮助图和指令接管作为其中一个独立模块一起提交；`GsUID.Core` 和 UID 插件仓库只记录版本，不复制进主仓库。

枝江直播日程防护见：[枝江直播防护](docs/功能-枝江直播防护.md)；本地百科和梗库见：[本地知识库与梗库](docs/功能-本地知识库与梗库.md)。

## 群组任务范围

- `A海岸`：1128870029、1077416717、1083457871、1090284567、278824712。这些群聊是后续 A海岸功能任务的默认范围。

## 安全边界

- 不要把 QQ 密码、验证码、Cookie 或 OneBot token 提交到 Git。
- 账号密码曾在对话中暴露时，应先修改密码。
- NapCat/个人 QQ 自动化存在账号风控和平台规则风险；本项目不绕过验证码、滑块或设备验证。
- 数据库不保存群聊原文；A海岸发言统计只保存 QQ 号、最后昵称、每日发言次数和消息去重标识。

## 安装

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

编辑 `.env`：

- `MANAGED_GROUP_IDS`：最多 10 个群号，逗号分隔。
- A海岸发言统计固定为本说明顶部列出的五个群，不能通过环境变量或 `#功能范围` 修改；五个群必须保留在 `MANAGED_GROUP_IDS` 中。
- `DUPLICATE_GROUP_IDS`：查重允许使用的群号子集；不填写时继承全部管理群。
- `GAME_GROUP_IDS`：游戏插件允许响应的群号子集；不填写时继承全部管理群。
- `GAME_API_GROUP_IDS`：异环游戏接口（`#nte`）允许响应的群号子集；不填写时继承全部管理群，且与小游戏范围相互独立。
- `ACTIVITY_GROUP_IDS`：跨群活动允许使用的群号子集；不填写时继承全部管理群。
- `BOT_OPERATOR_IDS`：超级管理员 QQ 号，可执行跨群查重、白名单管理，并仲裁所有活动。
- `ACTIVITY_ADMIN_IDS`：额外指定的活动管理员 QQ 号；活动有效群内的群主和群管理员默认也拥有活动管理员权限。活动管理员可创建活动，并修改、取消、提前结束自己创建的活动；进行中的活动仅超级管理员可修改。
- `ACTIVITY_ADMIN_BLACKLIST_IDS`：活动管理员黑名单。名单成员即使是活动有效群的群主或群管理员，也不会获得活动管理员权限。
- 游戏功能统一由本地 GenshinUID Core 及其游戏插件提供；当前只启用异环（唯一前缀 `#nte`），Core 未启用时游戏接口静默不响应，可用 `#游戏接口 状态` 查看。
- `REPORT_OUTPUT_MODE=local_image`：查重、白名单列表和机器人状态默认用本地 Pillow 绘制 PNG 后发送，不调用生成式 AI；改为 `text` 可恢复文字输出。
- `REPORT_DIR=data/reports`：图片临时保存在这里，默认保留 24 小时后自动清理。
- `REPORT_FONT_PATH`：可选中文字体路径；Windows 默认自动尝试 `C:\Windows\Fonts\msyh.ttc`。
- `AVATAR_BASE_URL`：头像来源模板，默认使用 QQ 头像地址；渲染到头像时按刷新周期按需探测，失败继续使用旧图。
- `AVATAR_CACHE_DIR=data/avatar_cache`、`AVATAR_TIMEOUT=5`、`AVATAR_CACHE_TTL=604800`：头像缓存目录、请求超时和最长本地回退保留时间。
- `AVATAR_REFRESH_INTERVAL_SECONDS=3600`、`AVATAR_REFRESH_COOLDOWN_SECONDS=900`：成功探测间隔和失败退避；不发送 QQ 消息，只请求头像源。
- `AVATAR_REFRESH_MAX_PER_CALL=24`、`AVATAR_REFRESH_CONCURRENCY=2`：单次最多刷新数量和并发数，防止集中请求。
- `GSUID_ENABLED=true`：启用本地 GenshinUID Core 游戏生态。
- `GAME_API_ENABLED=true`：异环游戏接口（`#nte`）的运行热开关默认值；`#游戏接口 开启|关闭` 修改后实时同步回本文件。
- `GSUID_CORE_DIR=GsUID.Core`、`gsuid_core_port=8765`：Core 本地目录和监听端口。
- `BOT_COMMAND_PREFIX=#`、`BOT_REQUIRE_MENTION=false`：群内和私聊的全部机器人命令统一使用 `#指令 [参数]`；权限仍按普通用户、活动管理员、超级管理员的既有规则判定。
- `BOT_RESPONSE_DELAY_MIN_SECONDS`、`BOT_RESPONSE_DELAY_MAX_SECONDS`：普通互动（表情、随机/三连复读、@确认）发送前的随机延迟，默认 2-5 秒；过期 120 秒的被动消息会丢弃。
- `BOT_COMMAND_RESPONSE_DELAY_MIN_SECONDS`、`BOT_COMMAND_RESPONSE_DELAY_MAX_SECONDS`：`#` 指令和小游戏反馈发送前的随机延迟，默认 1-2 秒；业务状态会先更新，不会因等待延后处理。
- `BOT_ONEBOT_API_MIN_INTERVAL_SECONDS`：全部 OneBot API 调用的最小间隔，避免突发请求。
- `STATS_REALTIME_ENABLED=true`：启用 A海岸实时计数；默认开启。关闭后不加载监听和排行榜命令。
- `QQ_GROUP_ACTIVITY_ENABLED`、`QQ_GROUP_ACTIVITY_URL`、`QQ_GROUP_ACTIVITY_METHOD`、`QQ_GROUP_ACTIVITY_PAYLOAD`：QQ 群管理页私有接口采集配置。由于 QQ 没有公开稳定的“昨日/近七日”接口，未确认真实请求前必须保持关闭，不能填猜测地址。

不要在 `.env` 中配置 QQ 密码。先在本机安装并登录 NapCatQQ，在 NapCat 中配置反向 WebSocket：

```text
ws://127.0.0.1:8080/onebot/v11/ws
```

如果修改了 `HOST` 或 `PORT`，反向 WebSocket 地址也要同步修改。NapCat 的具体配置字段以当前版本文档为准。

## 运行

普通用户的双击入口统一放在根目录的 `启动工具` 文件夹：

- `启动工具\01-启动全部.bat`：启动 GsUID Core、机器人、NapCat QQ、NTE 登录隧道和 watchdog。
- `启动工具\02-重启全部.bat`：关闭后重新启动整套运行环境，并保留隧道是否启用的选择。
- `启动工具\03-关闭全部.bat`：关闭 watchdog、隧道、可安全确认归属的 NapCat QQ、机器人和 Core。

普通 Python 代码更新只需双击 `启动工具\11-仅重启机器人.bat`，不会重启 NapCat 或 QQ。全部快捷入口见 [`启动工具/README.md`](启动工具/README.md)。QQ 若要求扫码、滑块或设备验证，仍需在弹出的 NapCat/QQ 窗口中手动完成。完整关闭只处理本次启动记录、已连接到本机 OneBot 端口或命令行明确匹配 `NAPCAT_QQ_ID` 的 QQ，不会调用 `NapCat.Shell\KillQQ.bat` 或关闭无法确认归属的其他 QQ。

完整的 PowerShell 手动启动、测试、停止和故障排查流程见：[安装与运行](docs/运维-安装与运行.md)。

```powershell
.\scripts\start.ps1 -Foreground
```

后台运行：

```powershell
.\scripts\start.ps1
Get-Content .\logs\bot.out.log -Wait
```

停止、备份和开机启动任务：

```powershell
.\scripts\stop.ps1
.\scripts\backup.ps1
.\scripts\install-task.ps1
```

## 命令

群内和私聊的常规命令统一写作 `#命令 [参数]`。普通用户、活动管理员和超级管理员使用同一种前缀，机器人在命令匹配后按原有权限规则判定是否执行；例如：`#报名517`、`#报名 517`、`#报名：517` 或 `#报名#517`。

- `查重1 群号1 群号2 [群号3 ...]`
- `查重2 起点群号 目标群号1 [目标群号2 ...]`
- `查重3 群号1 群号2 [群号3 ...]`
- `查重4 起点群号 目标群号1 [目标群号2 ...]`
- `白名单 添加 QQ号 [备注]`
- `白名单 删除 QQ号`
- `发言排行 日|周|月|总`（A海岸群内所有用户可用，仅当前群）
- `A海岸发言排行 日|周|月|总`（A海岸群内所有用户可用，合并五群；超级管理员私聊可查询 `总` 榜）
- `机器人状态`
- `全局通告 [@全体] [人物] <内容>`（仅超级管理员可用；将通告内容渲染为图片后发送到全部 A 海岸群，可选人物表情包，省略时随机，默认不 @ 全体，加入 `@全体`/`@all` 标记才 @ 全体）
- `全局图片公告 [@全体]` / `图片公告 [@全体]`（仅超级管理员可用；回复一张图片后发送指令，或将指令与图片放在同一条消息中，群发到全部 A 海岸群）

- 管理员：`整点报时 范围 添加|移除|列表 QQ群号`
- `活动帮助`
- `活动大厅`
- `活动详情 ID`
- `查看名单 ID`
- `获奖名单 ID`（或 `查看获奖名单 ID`）
- `报名 ID`、`取消报名 ID`
- `我的活动`
- 管理员：`创建活动`、`修改活动`、`提前结束`、`取消活动`

当前运行配置已启用 GenshinUID Core，但只启用 NTEUID：对外统一使用 `#nte`，裸 `nte` 仅作为上游兼容入口；`gs`/`ww`/`yh` 均不响应。原神 `gs` 和鸣潮 `ww` 已停用，不纳入功能测试。Core 未启用时，游戏命令均不注册。

查重结果少于 100 名时不分页。超过 100 名时，执行首页查重会自动生成并合并发送全部页面图片，群里只显示一个可折叠的合并转发窗口；如果 NapCat 不支持合并转发，则自动逐页发送。仍可附加“页 2”单独查看某一页，分页快照保留 5 分钟，期间不会重新扫描群成员。

`查重1` 会让所有指定群互相查重，适合恢复原来的全量查重方式。例如：`查重1 1067772451 1128870029 1077416717`。`查重2` 的第一个群是“起点群”，后面的群是“目标群”，只检查起点群成员是否存在于目标群中；只在多个目标群之间重复、但不在起点群中的成员不会显示。例如：`查重2 1067772451 1128870029 1077416717`。旧命令 `查重` 保留为 `查重2` 的兼容别名。省略群号时使用全部管理群；`查重1` 将所有管理群互相查重，`查重2` 将配置列表中的第一个群作为起点群。图片报告顶部会显示 `1️⃣`、`2️⃣`、`3️⃣` 对应的群，成员行只显示重复群编号，不重复打印群名和群号。
`查重3` 与 `查重1` 相同，但会忽略查重白名单；`查重4` 与 `查重2` 相同，但会忽略查重白名单。只有全局操作者可以执行这四个命令。旧命令 `查重` 保留为 `查重2` 的兼容别名。省略群号时，`查重1/查重3` 使用全部管理群互相查重，`查重2/查重4` 使用全部管理群并把配置列表中的第一个群作为起点群。图片报告顶部会显示 `1️⃣`、`2️⃣`、`3️⃣` 对应的群，成员行只显示重复群编号，不重复打印群名和群号。

发言排行榜和其他用户卡片均显示头像与 QQ 昵称；排行榜不显示 QQ 号。昵称与头像可变，但统计以 QQ 号作为内部唯一键，因此不会因改名或换头像而拆分记录。A海岸总榜还会显示该用户的唯一归属群聊：取该用户在当前统计窗口内发言次数最高的一个完整群名；次数并列时按 A海岸固定群顺序判定。头像按 QQ 号缓存，网络不可用时显示本地占位头像；图片由本地 Pillow 绘制，不调用生图模型或网络 AI，失败时自动回退为文字。

A海岸统计只监听五个固定群的实时消息并仅累加次数，不读取或持久化消息内容；不会补拉历史消息。日榜为当天、周榜为本周一至今、月榜为当月一日至今、总榜为全部已累计日期，均取前 100。群内榜只计算当前群，A海岸榜才合并五群；超级管理员可私聊使用 `#A海岸发言排行 总` 查看总榜。启动时会清除旧统计中不属于 A海岸的聚合和去重键，其他群之后也不会进入统计表。白名单的查看与维护也允许超级管理员私聊执行。查重命令只接受 `DUPLICATE_GROUP_IDS` 中的群号，本地小游戏在 `GAME_GROUP_IDS` 中响应，异环游戏接口（`#nte`）默认在全部管理群响应并可用 `GAME_API_GROUP_IDS` 单独控制；所有机器人命令统一使用 `#` 前缀，不要求 @ 机器人。

## 跨群活动

跨群活动只在 `ACTIVITY_GROUP_IDS` 中的群响应。超级管理员、`ACTIVITY_ADMIN_IDS` 中的活动管理员，以及活动有效群内的群主和群管理员都可以创建活动；`ACTIVITY_ADMIN_BLACKLIST_IDS` 中的成员不会获得自动活动管理员权限。活动管理员只能管理自己创建的活动，机器人所有者可以仲裁全部活动。自动识别的群管理员需在活动有效群内使用管理命令；配置的活动管理员可私聊管理。`取消活动` 是保留审计和报名记录的软删除，不物理删除活动。活动功能不需要踢人、禁言、审批或其他高权限操作。

创建活动使用“字段名：内容”的多行格式。活动开放群内可直接发送；超级管理员和活动管理员也可私聊创建：

```text
创建活动 活动名：周末联动
开始时间：2026-07-20 20:00
结束时间：2026-07-20 22:00
类型：通报
说明：周末团建
参与群：1067772451,278824712
隐私：公开
```

示例：

```text
创建活动 活动名：跨群抽奖
开始时间：2026-07-20 20:00
结束时间：2026-07-20 22:00
类型：抽奖
说明：报名抽奖
奖项：一等奖=1；二等奖=2
参与群：1067772451,278824712
隐私：脱敏
```

状态会按北京时间自动从“未开始”变为“进行中”，到结束时间后变为“已结束”；抽奖会在结束时本地开奖并保存结果。创建、修改、取消、开始、结束等状态变化会通过本地 SQLite 待发送队列广播到活动涉及的群，QQ 暂时断线时会在下次维护周期重试。

`活动帮助` 会发送普通用户版合并转发：第一页是方便阅读的本地帮助图片，第二页是可直接复制的文字命令。活动 ID 是机器人创建成功后显示的数字，例如 ID 为 `500` 时，普通用户可直接发送 `报名517`、`报名 500` 或 `活动详情：500`。活动管理员使用 `活动管理员帮助`，超级管理员使用 `超级管理员帮助`。

`修改活动` 同样按行填写，第一项为 `活动ID：517`；可只写需要变更的字段，未填写或留空的字段保持原值。例如：`活动ID：517`、`活动名：新标题`、`结束时间：2026-07-20 22:30` 各占一行。进行中的活动仅超级管理员可以修改，普通用户和活动管理员均不能修改；更新后会向所有参与群发送最新活动信息。修改参与群时，退出的群只收到“该活动已不支持本群”的图片，新加入和原有群收到完整的活动更新图片。旧的竖线格式继续兼容。

新建活动 ID 从 `500` 起连续编号；已经创建的旧活动保留原 ID，不会被重新编号。

常用操作：

```text
活动大厅
活动详情 1
报名 1
取消报名 1
查看名单 1
获奖名单 1
我的活动
修改活动 活动ID：517
活动名：新标题
结束时间：2026-07-20 22:00
说明：新说明
隐私：公开
提前结束 1
取消活动 1 时间调整
```

活动图片、名单图片和大厅图片均由本机 Pillow 按数据直接绘制，不调用生图模型、互联网大模型或 Token 服务。报告使用浅粉、白色、莓红与淡紫的本地主题，并带有克制的蝴蝶结、心形和饰牌元素；标题、字段标签、正文和操作示例以不同字重与颜色区分。创建、修改、开始、结束和取消活动的跨群通知也使用本地详情图片；图片会包含活动 ID 与例如 `报名 500` 的操作示例，不发送纯文字通知。

结束的抽奖活动详情不会再把所有获奖者塞进“开奖结果”字段。机器人会将“详情图 + 按奖项分区的获奖名单图”合并转发；名单中每位获奖者独占一行。普通成员在活动群查看时看到脱敏 QQ，活动创建者和机器人所有者可在任一受管理群或私聊中发送 `获奖名单 ID` 查看完整 QQ 信息。名单页较多时同样使用合并转发。

所有活动命令以 `#` 开头，且活动 ID 可与命令紧贴、用空格、中文冒号或第二个 `#` 分隔，例如 `#报名517`、`#报名 517`、`#报名：517`、`#报名#517`。普通用户、活动管理员和超级管理员在群内及私聊使用同一格式，命令按既有角色权限检查。报名成功时，机器人会在原消息添加“续标识”表情并引用回复当前人数；重复报名仍只添加续标识。取消报名时，机器人会在原消息添加“续标识”和“疑问”表情。活动大厅、详情、开始、结束和通知属于公开信息，仍直接发送到群内；详情和通知会提示使用 `#查看名单 ID` 查看当前人数和名单。超级管理员和 `ACTIVITY_ADMIN_IDS` 中的活动管理员可通过私聊创建活动或管理自己创建的活动；无论从哪里操作，目标群都必须属于 `ACTIVITY_GROUP_IDS`。

名单中的跨群 QQ 号默认脱敏；活动创建者和机器人所有者可查看完整号码，当前群内成员可查看自己所在群的完整号码。报名名单超过一页时使用合并转发窗口，NapCat 不支持时自动逐页发送。头像仅按 QQ 号从配置的头像地址缓存到本地，下载失败会显示占位头像。

### QQ 群活跃概况采集边界

NapCat 的 `get_cookies(domain="qun.qq.com")` 只在内存中返回短期群网页 Cookie 和 `bkn`，采集器不会保存 Cookie、密码或群聊原文。采集器支持 GET/POST、超时和一次重试，并只保存本地 SQLite 中的活跃人数、成员 QQ/昵称、活跃值、排名、日期、窗口和运行状态。

QQNT 当前版本和 NapCat 已公开动作没有提供“成员数据 -> 群数据 -> 昨日活跃概况/近七天活跃概况”的标准 OneBot 动作。该页面接口属于 QQ 私有接口，可能随 QQNT 版本变化；因此项目不写死未经验证的 URL。只有从 QQNT 管理页面实际请求中确认 URL、请求方法和 JSON 字段后，才可以在 `.env` 中填写：

```dotenv
QQ_GROUP_ACTIVITY_ENABLED=true
QQ_GROUP_ACTIVITY_URL=https://已确认的接口地址
QQ_GROUP_ACTIVITY_METHOD=POST
QQ_GROUP_ACTIVITY_PAYLOAD={"gc":"{group_id}","bkn":"{bkn}","date":"{day}"}
```

A海岸实时统计已启用；QQ 群后台活跃概况采集仍保持关闭。不要将 `get_group_honor_info` 当作统计替代品，它返回的是群荣誉榜，不是本地累计的发言次数。

## 群内小游戏

小游戏使用独立的群内状态和 SQLite 战绩，不要求机器人拥有禁言、踢人或其他群管理权限。所有对局只在当前群内生效，不显示 QQ 号或群号；总榜以临时群标记关联群头像和群名称。

超级管理员在目标群发送 `#游戏开` 或 `#游戏关` 管理开关，默认关闭时所有小游戏指令均保持静默。开启后，普通群友直接使用 # 指令：

```text
#游戏列表                 # 合并转发图片菜单：总清单 + 四个游戏详情页
#装填 / #开枪             # 俄罗斯转盘
#装弹 / #丢给 @群成员     # 定时炸弹
#装弹成语 / #装弹 成语     # 成语接龙炸弹，省略时长则默认 120 秒
#装弹成语 180             # 成语接龙炸弹，时长 60-600 秒
四字成语 #丢给 @群成员    # 成语接龙炸弹传递格式
#骰子                     # 幸运骰局
#猜数 / #猜 123           # 猜数字
#转盘榜 / #转盘总榜       # 俄罗斯转盘群榜 / 总榜
#炸弹榜 / #炸弹总榜       # 定时炸弹群榜 / 总榜
#骰子榜 / #骰子总榜       # 幸运骰局群榜 / 总榜
#猜数榜 / #猜数总榜       # 猜数字群榜 / 总榜
```

原版定时炸弹、俄罗斯转盘、幸运骰局与猜数字每局最长 120 秒；成语接龙炸弹仅由 `#装弹成语` 或 `#装弹 成语` 开局，省略时长时同样为 120 秒，给出时长则为 60-600 秒并按设定时长爆炸。成语模式第一句可使用任意有效四字成语；之后每句首字必须等于上一句末字，且必须使用真实 @ 其他群成员的格式 `四字成语 #丢给 @群成员`。两种炸弹模式共用“传奇接盘侠”和“传奇炸弹人”战绩。俄罗斯转盘按阵亡次数产生“传奇耐死王”；幸运骰局以 1-120 的不重复点数产生“传奇欧皇”和“传奇非酋”；猜数字从 0-999 中选定一个数字，猜中次数产生“传奇智力王”，猜错次数产生“传奇小🐽”。所有榜单的参局次数只作注释，不参与排序或破同分。

超级管理员可在目标群发送 `#清游`，再于 60 秒内发送 `#确认` 永久清空该群的小游戏对局、参与记录和累计战绩；发送 `#取消` 放弃。该管理操作在小游戏关闭时也可使用。`#游戏关` 只会结束进行中的对局，并让该群历史暂时不出现在各游戏总榜；记录不会删除，重新 `#游戏开` 后会按原战绩继续累计并重新计入总榜。

俄罗斯转盘和猜数字每局会随机安排 2 至 3 次事件；原版定时炸弹每局 3 至 5 次；幸运骰局每局 5 至 10 次。首次事件不会早于开局 15 秒；除成语接龙炸弹外，后续事件至少相隔 10 秒，并且必须先有一次有效游戏互动才会继续触发。成语接龙炸弹首次事件同样在开局 15-35 秒后触发，后续事件冷却改为至少 30 秒，且仍须先有一次有效传递；事件数量不再固定，但最多为开局时长 ÷ 30 次（60 秒最多 2 次，120 秒最多 4 次，600 秒最多 20 次）。因此同一次互动不会连续触发两条随机事件。俄罗斯转盘包含“同生共死、反弹、弹仓偏移、意外失误、手指抽筋”；原版定时炸弹包含“烫手加速、时间失控、定点追踪、惯性反弹、黑洞投递、逆向快递”；成语接龙炸弹在保留这六种事件的基础上，额外包含“旧词回响、首字回环、词条作废、自由开篇、孤立开篇”。成语默认禁止重复，词条作废会额外封禁被划掉的词；旧词回响只改变下一手的接龙锚点，不能让历史词重复出现。幸运骰局包含“后悔药、滋蹦的大手、命运互换、大小反转、王座易主、双倍好运、双倍倒霉、镜像骰面、连号追击、非酋救济、欧皇税、高台跃迁、深渊试炼、幸运折半、末位逆袭、双生骰面”；猜数字包含“发散思维、温差提示、数字回声、数位透视”。惯性反弹、黑洞投递、逆向快递、首字回环、词条作废、王座易主、双倍好运、双倍倒霉、高台跃迁、深渊试炼、双生骰面、发散思维、意外失误和手指抽筋属于触发式事件，抽中时保持静默，下一次有效互动才揭示结果。

所有小游戏指令都必须以 `#` 开头；`#开枪` 与 `# 开枪`、`#丢给 @群成员` 与 `# 丢给@群成员` 都可使用。俄罗斯转盘允许同一成员在同一把枪中连续开枪，但每局只记一次参局；幸运骰局仍限制每人每局一次投掷，定时炸弹仅允许当前持有者传递。

## GenshinUID 游戏扩展

完整的游戏插件命令、测试结论、维护和 AI/Token 说明见：[异环游戏接口](docs/功能-异环游戏接口.md)。

按上游推荐架构，游戏功能由独立的 GenshinUID Core 进程承载，当前项目的 NoneBot 进程只负责 OneBot/QQ 接入和 Core 连接。首次安装或更新使用：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\scripts\install_gsuid.ps1
```

安装脚本会拉取并更新 `gsuid_core`、GenshinUID、XutheringWavesUID 和 NTEUID 到本地 `GsUID.Core`，安装官方 NoneBot2 Core 连接器，刷新 `config/upstream-lock.json`，并写入本地 Core 初始配置。第三方源码不复制进本项目仓库；脚本发现上游仓库存在本地改动时会直接停止。

启用后按以下顺序启动：

```powershell
.\scripts\start_gsuid_core.ps1
.\scripts\start.ps1 -Foreground
# 另一个窗口启动 NapCatQQ
```

Core 使用本机 `8765` 端口，QQ/NapCat 仍使用现有的 `8080` OneBot WebSocket。当前 AI 总开关关闭；游戏插件只按自身功能访问普通游戏数据服务。

关闭时先停止 NapCat，再停止本项目机器人，最后在 Core 窗口按 `Ctrl+C`，或执行 `.\scripts\stop_gsuid_core.ps1`。

## 可选图形管理器

图形管理器只管理 NoneBot 和 NapCat QQ；完整环境优先使用 `启动工具` 中的中文快捷入口。需要图形配置界面时运行：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\scripts\build_manager.ps1
```

生成的单文件程序位于 `dist\QQBotManager.exe`。将它放在项目根目录或保留在 `dist` 目录中运行。管理器会读取项目根目录的 `.env` 和 `NapCat.Shell`，提供：

- 一键启动机器人和 NapCat；
- 实时显示机器人日志、HTTP 地址和 OneBot WebSocket 地址；
- 修改管理群、操作者 QQ、机器人 QQ、NapCat 路径和统计时间；
- 打开 NapCat 目录、WebUI 和内置帮助；
- 只停止管理器自己记录的机器人和 NapCat QQ 进程树。

如果管理器发现已经运行的机器人，会接管而不会重复启动。发现已有 QQ 时，只有 OneBot 的目标 `self_id` 或进程参数明确匹配 `NAPCAT_QQ_ID` 才会接管；普通 QQ 或无法确认账号的 QQ 不会被纳入停止管理，管理器会继续按目标 QQ 调用 NapCat。不要使用 `NapCat.Shell\KillQQ.bat`，它会强制关闭所有 QQ 进程。

管理器会从 `NapCat.Shell\config\webui.json` 和 NapCat 启动输出自动识别 WebUI Token。点击“打开 NapCat WebUI”时会自动生成带 Token 的本机地址，Token 不会显示在界面日志中，也不会写入管理器状态文件。

如果 NapCat 日志出现“没有 `-q` 指令指定快速登录”，说明使用的是旧版管理器；请先关闭旧的管理器窗口，再运行最新的 `dist\QQBotManager.exe`。如果管理器日志出现 `_MEI...\bot\plugins\*.py`，也应使用最新构建版本，新的打包方式会直接按模块加载插件。
