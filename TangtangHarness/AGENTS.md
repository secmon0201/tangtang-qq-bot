# TangtangHarness 维护约定

用户已选择自建 Harness。新框架直接使用 asyncio、FastAPI、SQLite 和 OneBot 协议，不依赖 NoneBot 或 DSH。

Harness 制作、修复与维护先读本目录的 [维护技能](skills/tangtang-harness/SKILL.md)，按任务加载对应流程。技能权威源留在本目录，用 `skills/link-local-skill.ps1` 联接到本地 Codex；后续编辑权威源，不维护目录外副本。

- 所有新代码、配置、资源、依赖、运行文件、脚本和测试留在本目录。
- 旧 `bot`、启动脚本、配置、数据库及进程保持独立；不得为了迁移修补旧框架。
- 可以移植成熟业务算法和素材，运行时禁止 `import bot.*` 或 NoneBot。
- 以实际功能和 bug 修复为主；不引入防御性编程、过重门禁、通用插件平台或额外审计兜底。重大安全或性能问题可以提出。
- 纯工具路由直接执行业务并交付结果，不调用聊天模型，不触发间接 AI 整理；工具定义不整体加入人格前缀。
- 群内普通自然语言聊天和工具请求须呼叫娅娅或真实 @ 机器人；明确业务命令仍直接可用。主动聊天与免呼叫续聊独立保存开关，不因迁移或修复自动开启。
- 模型、Core、语音及本地工具的技术错误只写后台日志、请求/工具记录和本机控制台，不向 QQ 公开故障消息；参数澄清和正常业务状态仍可回复。语音合成或发送失败继续回退业务文字。
- NTE/鸣潮使用上游原生行为。主 Core 连接是唯一命令发送者，兼容连接只接旧订阅；不得修改上游源码、配置或数据库来实现迁移兼容。
- 请求在发送边界保存，缓存与成本依据供应商实际 usage；未知值保持未知。
- 默认 observe，无模型调用和 QQ 写操作。回放、预览、离线实验也保持零调用。
- 外部网络、健康与重连放在有间隔的独立后台任务，不阻塞无关业务。
- 服务启停经过公共生命周期控制器和文件锁，先保存期望状态；显式关闭不得被守护撤销。Harness 守护状态和事件使用独立 `data/supervisor.db`，只恢复归属确认且期望开启的缺失进程；活进程的断线或不就绪只记录，不自动杀进程重启。语音继续尊重各保存开关与 `stopped.flag`。
- Harness 的 Windows 当前用户守护计划任务直接调用自有 `pythonw.exe` 无窗口入口，每分钟与登录时检查；子检查限时 45 秒，任务限时 50 秒供失败记录落库。守护启用时统一负责语音恢复，内部语音后台仅检查健康；停用时仍尊重语音关闭意图。不得直接调度 PowerShell，或操作旧 NoneBot 看门狗、QQ 登录及外部无关进程。
- QQ、B站扫码、验证码和设备验证由用户操作。Core、语音与正式生产接管另行实机验收。
- 改动完成运行本目录行为测试与前端构建；提交前继续运行仓库要求的校验，不绕过旧校验或修改旧源码解决既存失败。

功能来源见 [迁移台账](docs/旧功能迁移台账.md)，运行与数据边界见 [迁移与运行边界](docs/迁移与运行边界.md)。

服务意图、计划任务、恢复退避与事件口径见 [服务守护](docs/服务守护.md)。
