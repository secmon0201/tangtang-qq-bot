# 上下文缓存主干

聊天默认使用 `extra.context_mode=cache_first`。目标是让同一会话、模型和窗口的下一次输入完整保留上一次输入及原样模型输出，只追加新消息和真实送达状态。供应商实际缓存仍以返回 usage 为准，本地连续追加不能冒充上游命中。

## 单一主路径

固定人格和精简输出协议 → 持久化原样模型日志 → 本轮新消息、必要工具事实和明确媒体 → 原样模型输出 → QQ 送达事实。

每个群、私聊、模型档案分别保存活动日志。思考等级属于请求参数，不属于模型身份；切换思考等级不会新开上下文。同档案的旧思考等级缓存首次读取时按来源事件顺序合并到统一日志，保留原始记录。预览只读取；实际发送边界保存输入。失败、沉默不会使下一轮重复灌入同一批消息。模型原样输出用于保持输入和输出连续性，与 `turns` 中已确认送达的业务历史分开；只有真实 QQ 回执才能确认“已经说过”。部分送达和失败追加状态，不重写旧输出。

模型日志保存在 Harness 自有 Store settings。请求 telemetry 保存布局、日志键、epoch、采用/排除来源和切换原因；完整内容只在实际 payload 与日志状态中保存，避免在各层 telemetry 重复复制。重启后复用同一日志；私聊闲置释放只影响活动态，不删除永久消息。

## Responses 原生推理状态

成功 Responses 请求的实际 `output` 单独保存在本地 `generated_response:<request_id>` 档案，并记录完整、部分/未确认或未返回的状态，以及输出来自完整终态还是已完成项事件。SSE 优先使用 `response.completed` 的完整输出；若中转的终态未带输出，则按 `output_index` 保留已收到的 `response.output_item.done` 项。存在已开始但未完成的项时不能视为完整批次。可见正文仍按原本终态正文或流式文本生成，不因补齐归档而变化。失败流不提交原生输出到活动日志。正文继续供 QQ 交付使用，原生推理项不发送到 QQ，也不在 usage 或 telemetry 中复制密文。

新生成批次仅在档案使用 Responses、`reasoning_effort` 非空且不是 `none`，并且 `extra_body.include` 显式包含 `reasoning.encrypted_content` 时进入原生输入日志。当前配置不会因代码升级自动增加此 include，也不自动改变推理设置。当前 `none` 的纯正文日志仍走正文输入路径；真实 low/none 对照由操作者正常聊天积累数据。

同一模型档案继续使用统一日志。只有完整输出同时含加密 reasoning 和 assistant message，且整批仅由这两种项构成时才原样回放；保留顺序、ID、status、summary、encrypted_content 和消息 content/annotations，不把它们改写成思考文字。已进入日志的原生批次成为冻结历史，后续切换思考档位或移除 include 仍原样回传，避免把旧原生项重新改写成正文。原生输出与原始输入、QQ 回执属于同一事件组，容量切换整组保留，遗忘、过滤和范围撤销仍整窗重建。回放的 assistant 正文必须与保存的生成正文一致，避免同时传入重复正文。

没有加密推理项、批次不完整，或含 function/tool/未知输出类型时，只归档实际收到的数据并保持正文路径；当前聊天未提供原生工具调用协议，不能截取一半调用链或擅自执行这些工具。未报告的状态保持未知。容量估计优先采用该批供应商已报告的 reasoning token；缺少时仅使用密文文本的本地容量估计，不能当作真实 token 或缓存计数。密文容量与真实 token 的对应关系仍由实际 input usage 校准。

这是 Harness 的协议接收、保存和条件回放能力；中转能否返回密文、接受原样回放并保持上游账号路由，仍需实际响应与供应商说明确认。不会自动调用模型做能力探测，也不使用 `previous_response_id` 假定中转已经保存上轮状态。

## 明确取舍

QQ 交付解析与原样模型日志分开。纯 JSON/JSON 代码块按协议解析；模型先输出正文、再附带完整协议对象时，仅在前面的正文与 `messages` 内容一致时去重提取，正文和语音元数据使用同一解析结果。普通 JSON 示例及 `messages` 内的代码保持原样；活动模型日志仍保留实际收到的原始生成内容，不为修正 QQ 展示重写旧输入。

当前/引用图片在进入日志前解析成模型图片输入。Windows 代理 DNS 的 Fake-IP 兼容只覆盖 `multimedia.nt.qq.com.cn` 的 HTTPS 443 与 `198.18.0.0/15`，其他非公网地址继续拒绝，保留格式、大小和重定向限制。新收到的 GIF 转为 PNG 首帧并标注首帧；发送边界不对历史 GIF 额外启用此转换。图片下载失败保存脱敏具体原因，不能把未发送图片的请求归因于模型识图能力。

新模式停止自动记忆抽取、认知整理、成长学习、画像生成/复核、群摘要、AI 压缩和话题采集注入。旧后台队列保留记录，但不发模型请求。人格中不再要求模型每轮输出学习字段。旧导入资料、画像、群状态、对白例子和动态表情候选不自动进入请求。

显式记忆查看、更正、遗忘、恢复及其他本地工具继续使用现有业务处理器。NTE/鸣潮、B站订阅、排行榜、语音合成和 QQ 收发不依赖这些 AI 整理。群呼叫、主动发言、续聊、个人资料范围和群开关沿用原有准入规则。

普通聊天不自动切备用模型，保持当前选定档案。需要更换档案时使用独立模型日志与真实容量，不能把另一个模型的缓存计入当前模型收益。缓存亲和键继续由档案开关决定，不默认声称中转支持。

图片保留当前消息与明确引用；缓存主路径不反复回灌上一条群图片或上一条用户图片。语音可用状态只在建立窗口或变化时追加；历史原样语音输出仍是生成记录，QQ 送达事实说明最终是否送达。

## 容量和撤销

`cache_input_budget_tokens` 默认 `null`，表示自动使用当前档案的 `context_limit - max_output_tokens - 1024`。保存正整数时作为人工上限，仍受档案可用容量约束；单次显式预算也受容量约束。档案容量为空时停止构造并提示补齐，不根据模型名称猜测。旧 `input_budget_tokens` 只供 legacy 布局使用。

容量来源是模型档案配置，填写供应商已确认的限制；页面展示“档案配置”并不表示 Harness 已证明中转站支持该值。预算是增长上限，不会通过填充、预热或付费探测把窗口补满。

活动日志超过硬水位（默认预算的 90%）时一次性换 epoch，以总输入约 50% 预算为目标，保留最近连续的完整事件组。一个组包含原样输入、生成输出和送达事实；不再受 `recent_rounds` 的 8 轮上限约束，该字段仅供 legacy 使用。某个较大的最近组无法装入目标时结束后缀选择，不越过它捞取更早的零散组。没有逐轮滑动裁头，没有后台模型摘要。永久源事件、原始请求、已送达历史均保留。固定人格和当前完整事件组优先保留；自身超容量时记录失败，不静默截断用户请求。

真实请求返回的归一化总输入 usage 用于校准后续容量判断。校准只改变估算和切窗决策，不修改已存输入、生成输出或送达事实；预览只读。供应商缺少或不明确的用量保持未知，不能从本地估算补写 `input_tokens`、`cached_tokens` 或命中率。请求 telemetry 分开展示原始本地估计、校准后的容量估计与实际供应商 usage。

校准按档案、渠道、tokenizer、实际估算器及文本/图片类别隔离，最多保留最近 9 个有效样本；同一 payload 去重。仅接受已知正整数总输入用量，以及 0.25～4 的真实/本地估计比值；已有至少 3 个可比样本时，偏离中位数两倍以上的样本不参与校准。判断当前容量时选择本地规模相差不超过四倍、图片占比相差不超过 15 个百分点的样本中位数，同时修正高估和低估。没有可比样本时退回原本地估算；这些都是容量估计，不是远端缓存命中证据。

新收到的群消息最多采用最近 30 条；略过旧积压的键明确记录为 `raw_event_backlog_limit`，不能把略过消息算作已采用。已进入日志的历史不会因为这一限制在普通轮次中变化。

遗忘、过滤或聊天范围撤销命中活动日志时，清空整个活动日志并建立新 epoch，记录原因。后续模型回答可能已经改写被撤销资料，只删除原始轮次无法可靠移除这些派生内容。重建保留已处理消息游标，仅采用当前允许的新消息和必要工具事实，避免重新回灌旧积压；永久源事件、原始请求和已确认历史仍在 Store 中保留。人格变化也建立新基座。业务可见性优先于缓存。

每个活动日志保存过滤名单、遗忘限制摘要和聊天范围修订号；这些策略变化时也整窗重建，即使原始资料轮次已被容量切换丢弃，仍能清除近期回答中的派生资料。聊天范围修订号仅在既有事件从允许聊天改为禁止时递增；首次观察、纯工具分类和恢复允许不会制造逐轮冷启动。无需保存无限的来源依赖图。

## 验证与回退

模型响应诊断保存在请求 `telemetry.model_diagnostics`：只记录返回的请求标识、允许的后端/渠道标识、实际响应模型、状态及脱敏后的结构化错误。`response.failed`、`response.incomplete` 和 HTTP 错误保留具体 code/type/message；已返回的真实 usage 仍保存，缺失的 token 与缓存保持未知。断流或客户端超时保留此前已收到的响应标识，不把部分正文当作成功回复；不自动重试收费请求。

low/none 的收益使用真实聊天请求评估：从配置切换时间分段，区分首批新日志请求、后续连续输入及失败用量覆盖，比较零命中频率、缓存 token、按 token 加权的缓存比例、失败率和耗时，不把失败未知缓存计作零。此对照检验推理设置与真实运行结果的关联，不能证明“缺少 reasoning 项导致零命中”。原生回放按上述显式条件启用；人工添加思考文字不能替代原生状态。验证原生状态的收益，需要中转支持并在同一 low 设置下另行对比是否原样回传这些项。

`scripts/verify_cache_spine.py --source <源码目录>` 使用临时数据库、合成模型与模拟 QQ 回执，观察连续输入、容量重建、重启、撤销、失败、送达和后台调用次数，不访问真实模型或 QQ。

缓存 token、未缓存 token、费用和字段覆盖继续由现有账本记录；读取界面、预览和回放零调用。真实缓存收益要在固定实际模型、渠道、参数与相同工作量下验证，计入后台、失败尝试和新窗口冷启动费用。

显式设置 `extra.context_mode=legacy` 可进入隔离的旧构造器，恢复旧功能布局；它不会混入新主路径。完整源码基线另有事务备份。回退需保留当前遗忘和过滤状态，不能复活被撤销资料。
