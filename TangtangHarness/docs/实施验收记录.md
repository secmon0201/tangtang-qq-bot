## B 站订阅与推送恢复

现场订阅开关及各推送开关已启用，轮询间隔为 60 秒，但两个 UID 配置未保存；旧库已有 8 个目标的游标，因此轮询时间持续刷新却没有实际订阅和通知。根因是配置迁移只读取 `.env` 明写字段，遗漏旧 `bot/config.py` 中 `os.getenv` 的默认订阅列表。

显式配置迁移现在用 AST 读取 `ASOUL_BILI_TARGET_UIDS` 和 `ASOUL_BILI_COMMENT_TARGET_UIDS` 的字符串默认值，不执行旧源码、不绑定旧配置单例；`.env` 显式空值优先，源码没有字面量默认值时不生成列表。新增测试覆盖默认导入、显式空值及无默认值，配置迁移测试 7 项通过。生产仅补齐缺失的 8 个订阅目标和 5 个评论目标。

恢复后后台取得 12 条真实 QQ 成功回执，涉及 4 个通知与 3 个群。公开抓取验证取得 8 个目标的 49 条动态和 7 个直播间数据。看板分别显示实际订阅配置与已存游标，避免将历史游标数量误判为当前订阅数量。

首次排查的登录凭证 `check_valid` 返回 `false`，关注接口返回 `-101`；公开数据可用并不代表登录有效。状态命令 `#bili_status` 验证登录有效性，验证接口失败显示未知；凭证失效不表示公开数据推送全部不可用。后续登录恢复见下节。

## B 站 WEB 扫码结果修复

用户随后完成的第一次扫码未通过真实认证验收。只读检查发现凭证更新时间已变化，必要字段仍为空；原登录库的 WEB 轮询丢弃了响应 Cookie，造成确认扫码后空凭证保存却报告成功。该二维码再次查询返回过期状态，无法恢复首次登录结果。

Harness 自有 WEB 扫码适配现在同时读取响应 Cookie 与旧式返回 URL 查询参数，保留两种返回方式。取得必要 Cookie 后才保存凭证并报告完成；缺少必要字段时提示重新扫码，不覆盖已有凭证。

## 缓存账单与活动上下文段

2026-10-05 吸收 `dsh-meow-memory` 与 `dsh-meow-cachebilling` 的可验证思路后，新增
