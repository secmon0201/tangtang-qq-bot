# 本地控制台

控制台读取 TangtangHarness 自己的 API 与事件记录。默认只监听本机，不接入旧机器人的管理网页，不读取或编辑旧配置。

语音消息统一显示为 `[语音]`。聊天历史、引用及后台整理只保留语音标记，不识别或转写音频，也不将文件地址、音频编码或合成语音的正文加入后续上下文；语音发送失败后实际送达的文字仍正常记录。

旧语音记录通过 `scripts/normalize_voice_history.py` 只读预览，停止 Harness 后加 `--apply` 修正；工具先在 ignored 的 `runtime/verification` 保存受影响字段的可恢复备份，再原子更新。历史实际模型请求档案保留原样。会话里的旧附件序列化记录按媒体标记展示，图片字节不会显示成长文段。

| 页面 | 可用操作 | 数据来源 |
| --- | --- | --- |

| 流量日志 | 数据库筛选与分页、排序、单次请求抽屉、触发消息、尝试链、送达、全量匿名导出 | `/api/analytics/requests`、`/api/requests/{id}`、`/api/analytics/export` |
| 缓存与费用 | 加权缓存 token 占比、请求命中比例、字段覆盖率、按币种费用趋势、输入与延迟散点 | `/api/analytics/overview` |
| 群与上下文 | 请求水位、预算、本地分层、压缩快照、摘要版本、归档来源及成员资料 | `/api/analytics/sessions`、`/api/analytics/sessions/{session_key}` |

| 实验 | 离线比较、显式真实模型实验、OneBot 消息回放 | `/api/experiments`、`/api/replay` |

SSE `/api/events/stream` 合并通知并刷新当前页面。刷新保留已有内容，在标题或操作栏显示转圈图标，不在正文插入加载行。主看板的“统计范围”默认折叠，展开后支持暂停实时刷新、手动刷新，以及今日、24 小时、7 日、30 日和自定义范围；切换看板保留筛选。图表支持悬停、缩放、数据表和匿名 CSV/JSON；流量列表只取摘要，完整模型 payload 和图片在详情按需读取。实验历史同样只读取摘要，点击“按需读取完整详情”后才通过 `/api/experiments/{id}` 获取原记录的脱敏副本，不重新运行实验。会话和请求没有记录时显示空态；服务断开时显示连接错误，不生成示例数据。

同一查询的读取进行中，新的实时通知只排入一次后续刷新，不取消正在读取的请求；切换查询或离开页面才取消旧请求。会话列表仍按最近活动排列，但默认选中的会话固定，不随其他群的新消息跳动。

后台使用完整群名和当前范围内保存的用户昵称，并标明“群”或“私聊”；群号、QQ 号作为辅助信息保留。群的缩写只用于发言排行榜，不替代控制台会话、查重或公告目标中的全名。后台任务类型、状态、工具名称及回执用途显示中文，原始键保留在展开的技术详情中。会话、请求和后台记录默认由新到旧显示。

工具卡显示新系统已保存的启用状态与额外群限制。启用或停用按钮只修改新系统配置，不执行业务工具、不触发 QQ 发送或模型请求；切换时保留已有群限制。工具启用不代表其外部依赖已经就绪。

“执行本地工具”提供中文参数控件，也可展开高级 JSON 补充其他参数。执行会话明确区分群和私聊，权限使用控制台操作者身份。默认只在控制台显示返回结果；勾选发送选项后才将返回结果投递到所选 QQ 会话。执行工具自身的配置修改或业务操作仍会生效，发送选项只控制返回结果的投递。

“发言排行”直接读取已采集的计数，不需要先到 QQ 群里发送指令。“群与集群”显示并编辑排行缩写、所属集群、群功能开关和群内过滤名单，支持创建集群。23:50 推送时，启用榜单推送的集群成员群收到同一份所属集群总榜；独立群收到本群榜。机器人离群后保留历史并归档，默认查重、自动任务、榜单及投递范围排除该群；勾选“显示已归档群”可查看历史身份，不会因此重新启用该群。

业务与运行看板的 B 站区域分别显示实际配置的订阅目标和已保存的游标目标。游标存在只说明曾经抓取过该目标，不代表当前仍在订阅；排查不推送时应先核对实际订阅数量、推送开关及群范围。登录状态区分有效、失效和未知，不把保存了凭证当作登录有效。`#bili_status` 会验证登录有效性，验证接口失败时保持未知。

“业务与运行 → 看门狗”记录 Harness、Core、SnowLuma 和语音的期望状态、检测状态及恢复事件。事件包括时间、触发来源、原因、结果和 PID，按新到旧显示最近 100 条，时间使用北京时间；正常的重复检查不每分钟追加一条正常事件。守护记录独立于聊天与模型筛选。外部计划任务在 Harness 停止期间写入的恢复记录，Harness 恢复后仍可查看。页面查询不会启动服务，操作入口和多重语音开关见[服务守护](服务守护.md)。

“进程存在”“服务就绪”和“连接成功”分别展示：Core/OneBot 断线不会触发自动杀进程重启，语音进程存在也不表示模型加载完成。守护成功只说明相应恢复动作及核验完成，实际聊天和 QQ 送达仍以请求记录及平台回执为准。

外部守护启用时统一承担语音拉起，内部语音任务只检查健康，因此这段期间的恢复尝试和结果可由守护时间线核对。守护停用期间沿用的原有语音后台恢复不补造为守护事件；历史事件也不代表当前连接成功。45 秒检查超时与失败会同时写入本机 `logs/watchdog-supervisor-check.log`。

2026-10-04 已修复 B 站配置迁移遗漏：旧实例未在 `.env` 明写的两项 UID 列表，现在由显式迁移读取旧 `bot/config.py` 的字符串默认值；只解析 AST，不导入或执行旧框架，`.env` 显式空列表仍保持为空。生产已补齐缺失的 8 个订阅目标和 5 个评论目标，后台取得 12 条真实 QQ 成功回执，涉及 4 个通知与 3 个群。

首次排查时公开抓取可取得 8 个目标的 49 条动态及 7 个直播间数据，但登录凭证无效，关注接口返回 `-101`。公开抓取成功不能代替登录验证。登录通过私聊 `#bili_login` 手工扫码，再用 `#bili_status` 检查；页面查看不执行登录或发送通知。

首次扫码后发现原登录库丢弃 WEB 轮询响应的 Cookie，造成确认后保存空凭证。Harness 已改为自有 WEB 扫码适配，同时读取响应 Cookie 与旧式返回 URL 的查询参数；缺少必要 Cookie 时不报告成功，也不覆盖已有凭证。操作者重新扫码后，真实凭证验证通过，关注、动态、视频与直播接口均成功，后台轮询正常，登录已恢复。

## 启动与构建

在 `TangtangHarness/frontend` 执行：

```powershell
npm.cmd install --cache .npm-cache
npm.cmd run dev
```

Vite 开发页面为 `http://127.0.0.1:5173`，`/api` 代理至 `http://127.0.0.1:8090`。后端必须另外启动。

```powershell
npm.cmd run build
```

新目录 `启动工具` 提供 `11-启动Harness.bat`、`12-停止Harness.bat`、`13-重启Harness.bat`、`41-检查全部状态.bat` 和 `51-打开Harness控制台.bat`。单独重启 Harness 不重启 SnowLuma 或 QQ；控制台地址默认为 `http://127.0.0.1:8090`。完整入口与独立启停行为见[运行入口](运行入口.md)。

产物为 `frontend/dist`，由 Harness 后端提供生产页面。`node_modules`、npm cache 和构建产物均不进入 Git。

## 指标口径

- 提供商真实 usage 决定实际 token 和缓存读取数；本地估算另作标注。
- 单次缓存 token 占比为缓存读 token 除以归一化输入 token；缺字段或供应商不报告时保持“未报告”。纯本地工具未调用模型，缓存指标不适用。
- 聚合命中率使用相同可报告样本的总缓存读取除以总输入，不把未知样本当零命中。
- 实际上下文和缓存页支持按模型档案、调用场景、提供商、账户标签和时间筛选。请求命中率与指标覆盖率分开显示。
- 成本按请求发送时冻结的 profile 单价估算，每百万 token；币种与价格版本一起保存。缺失单价时保持未知，历史未保存币种时单列“未知币种”，不同币种不相加，不代替提供商账单。
- 上下文分层占比是本地 token 估算，前缀 diff 是请求构建比较，两者都不证明实际缓存命中。
- 请求预览与消息回放不调用付费模型、不发送 QQ。实验默认离线，覆盖同会话追加、冷/热请求、模型切换、稳定前缀变化、工具事实隔离与压缩快照切换；模型切换需要至少两个档案。
- 在实验页主动勾选“真实模型调用（会计费）”并运行后，才执行两个实验模型请求。可单独记录为手动预热用途；不会自动周期预热，也不发送 QQ。离线实验结果不作为生产缓存收益。

密钥由新目录 `.env` 提供，浏览器模型表单只保存环境变量名称。完整请求记录可能包含私人会话内容，应保存在新目录 ignored data，使用本机界面查看。

统计时间边界统一为开始包含、结束不包含。用量汇总在全匹配范围计算，不受列表页数影响；触发用户是原消息作者，后台多来源资料的费用不能任意平分。个人资料、群配置和当前业务状态是存量，全历史版本与当前时间段的模型用量分别标明。私聊资料限制为该私聊本人，群资料遵循当前群范围；公共成长另标全局范围。

发言计数、保留正文和排行快照是不同来源，不能相加。六维雷达图表示既有文本规则命中条数，可能重叠，不代表人格分数。旧导入资料不等于当前有效资料，当前有效资料也不等于实际注入；本轮采用项可在请求 telemetry 的 sources.records 查看准确 ID/版本，排除原因另列。上下文曲线是每次请求采样，没有请求的时段不插值为实测。

新摘要保存发布版本及来源游标，旧记录只展示能由已完成任务还原的内容。后台开始结束、路由、上下文、媒体处理与发送耗时采用新记录的实测字段；缺少字段的历史保持未知。工具执行记录未覆盖全部前置拒绝路径，因此只称“已记录执行”，不伪称全部消息处理率。

缓存写入、首个内容块延迟、后端账号和图片实际 token 仅在供应商或适配器报告时展示。当前 CPU/内存、队列及容量没有持久历史，页面只显示当前采样，不生成过去曲线。读取看板、请求详情、资料和实验历史均不调用模型、不向 QQ 发送消息；真实实验必须在实验页显式运行。

模型页可以选择默认档案、故障切换档案、图片能力、超时、额外请求字段与 usage 计数语义。模型容量未知时保留空值，按供应商实际容量填写。默认使用自动计数；提供商输入字段是否包含缓存读取应以其真实响应合同为准。缓存统计同时显示可报告样本数与覆盖率。

模型容量填写后仍失败时，在流量日志打开请求详情查看错误：连接失败记录具体连接原因，HTTP 失败记录状态码及供应商简短错误消息，密钥和完整错误响应不会进入摘要。模型连接使用 Windows 证书信任库与原生证书链验证。接口证书过期需要供应商续证或在模型页更换有效 HTTPS 接口地址；调整上下文预算不会解决证书错误。未取得供应商 usage 的失败请求，token、缓存及成本保持未知；历史仅记录异常类型的请求不会补造具体原因。

使用操作者已配置的本地模型中转时，在模型档案填写其本机 API Base URL，保留原模型名称、API 格式、密钥来源及上下文参数。保存后立即用于后续请求。中转是独立运行服务，Harness 启停不操作它；中转连接故障也会记录到对应模型请求。

运行设置编辑器使用一套实际配置字段，移除重复派生视图和密钥状态。模型档案及默认模型在模型区域保存，避免运行设置草稿覆盖刚切换的模型。事件刷新保留尚未提交的编辑内容。

请求预览、回放、实验结果和请求记录按敏感字段生成脱敏副本；模型实际发送的请求体保持原值。模型额外请求字段中的敏感值显示为 `[redacted]`，原样保存会保留已有值；将字段设为空字符串或删除字段表示明确清除。前缀对比使用脱敏副本的本地序列化字节，不代表供应商缓存边界。

运行设置 `extra` 中的 Core 等敏感字段也显示为 `[redacted]`；原样保存保留已有值，明确设置为空字符串才清除该值。

旧功能台账由源码静态读取生成，不导入旧运行模块、不读取旧实例配置和数据库。在仓库根目录执行：

```powershell
.\TangtangHarness\.venv\Scripts\python.exe .\TangtangHarness\scripts\inventory_legacy.py
```

## 界面设计

控制台采用浅色数据界面、统一 SVG 图标、系统中文字体和可键盘操作的表单。主要视图可以直接看见数据来源和未知字段，完整 JSON 作为展开详情。屏幕缩窄时列表和内容上下排列，导航保持可辨认的图标与可访问名称。

未来可在独立域名部署前端与 `/api` 同源反向代理，例如 `https://harness.example.invalid`。这属于独立部署工作，当前不修改旧公共网关、隧道或域名配置，也不默认把会话界面公开。

## 本地验证范围

2026-10-05 的控制台改造增加了完整群/私聊身份、中文后台目录、默认会话入口、倒序记录、折叠统计范围、稳定刷新，以及独立的发言排行和群与集群管理。合成数据库测试区分完整群名与排行缩写，并验证昵称、后台范围和记录顺序；集群日榜及离群归档边界使用合成事件和模拟平台验证。这些检查不等同于真实 QQ 的 23:50 送达验收，本轮不为检查额外发送消息。

控制台已通过本机 Chromium 的七页桌面与手机视口检查、六项请求/指标筛选、SSE、零付费请求预览与消息回放、原样保存 observe 设置，以及六类离线实验。模型切换同时验证单档案提示和两个合成档案的切换；临时档案随后恢复，不生成供应商 usage。

最新构建另外在独立合成实例中验证模型额外请求字段的保存、排队后台工作的暂停与恢复。测试实例未连接 QQ，收费选项保持关闭。
