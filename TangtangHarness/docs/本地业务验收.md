# 本地业务迁移与验证

新运行时仅使用 `tangtang_harness`、新 SQLite 和 `TangtangHarness/resources`；不会导入旧 `bot` 或 NoneBot。业务算法和静态素材由项目已有源码迁移，QQ 边界由新的 OneBot 接口提供。旧目录、旧运行配置、旧数据库和旧进程不参与新工具执行。

## 来源核对

`scripts/inventory_legacy.py` 静态读取原注册表、插件源码、常量和能力清单，覆盖 29 个插件来源。按「插件 + 主命令或别名」去重后，共识别 108 个声明；当前路由能识别其中 103 个，其余 5 个均属于明确不迁移的官方 QQ 备用传输。识别路由只证明入口存在，不能代替参数、业务和实际发送验证。参数语法及完整旧入口见[迁移台账](旧功能迁移台账.md)。

## 验证边界

`test_router_business.py`、`test_tools_business.py` 和 `test_games_migrated.py` 使用临时新数据库、合成身份与 QQ stub。测试覆盖组合请求、不完整步骤、否定请求不执行、真实 @ 目标、玩法和榜单、缘分档案、知识审核、图库、统计与黑名单、查重、管理开关、实际网页和公告预览、队列重启、失败重试节奏及调度群范围。

离线验证不代表模型收费实验、B站扫码和网页公开部署已验收。本轮已在固定测试群完成本地工具与模型回复的限定范围实发，并完成 SnowLuma 双连接与送达回执核对；外部旧框架保留回切入口。B站扫码成功、过期或失败均生成发起者的私聊通知，沿用持久输出队列、隔离用户范围和发送回执；已验证通知跨重启保留、失败延迟重试和成功后不重复。扫码与验证码仍由用户手工完成。

混合工具与聊天请求使用 `ToolResult.data.facts`：排行保留总量和前五名，知识保留最多三段摘要，缘分只保留必要关系事实。完整图片、百行排行和发言原文保留在业务输出，不加入主模型稳定前缀。
