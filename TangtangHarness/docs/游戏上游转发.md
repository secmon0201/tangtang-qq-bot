# Harness 游戏上游转发

日常使用 `#nte帮助`、`#ww帮助`，也接受原有裸 `nte`、`ww` 前缀及大小写、空格和 `bot` 后缀。明确游戏命令整条交给 Core，不拆分参数，不调用聊天模型。并行测试仍可用 `#harness #nte帮助`、`#harness #ww帮助`。

群范围、机器人游戏总开关、群级 NTE/鸣潮开关和过滤名单保持有效。小游戏暂停或关闭不会同时关闭 NTE/鸣潮。游戏命令仍只从群聊进入；上游对已发起请求返回私聊结果时，可以沿原生 `target_send` 协议投递。

游戏接口、Core 或对应工具关闭，或游戏命令不满足调用范围时，静默阻断，不向 QQ 发送未开启提示，也不转发 Core 或调用聊天模型；已接单的阻断结果仍保存在本地工具记录中。

主连接使用 `extra.core.identity`，默认 `TangtangHarness`；QQ 平台字段保持 `onebot`，账号字段使用当前 OneBot 实际身份。只有主连接发送游戏命令，`extra.core.receive_identities` 中的连接只接收旧订阅及上游后台通知，回执返回原接收连接。

旧 Core 订阅的连接标识和消息来源可通过 `scripts/import_core_routes.py` 从上游 SQLite 只读导入。直接运行显示导入数量，加 `--apply` 写入 Harness 自己的配置和数据库。该操作不修改上游数据库、源码、配置或旧 NoneBot。重复导入会替换这份来源快照，不会创建或执行上游订阅任务。

Core 回程支持文字、图片、语音、视频、文件、合并转发、禁言、撤回和消息回执。前置 `@`、引用正文、引用图片和原引用 ID 按 Core 原生字段传递。重启后可以从 Harness 已存事件和导入来源恢复订阅关联；没有原消息 ID 的后台通知按当前接管范围投递。两个连接收到相同广播时，只发送一份结果，并分别返回同一平台回执。

observe/replay 不发游戏请求或 QQ 消息。Core 连接、重连和回程执行错误写入本机日志及控制台；文件或发送失败不会断开整条 Core 连接，也不影响聊天和其他本地工具。

2026-10-05 已使用临时独立连接调用真实上游 `#nte帮助`、`#ww帮助`，在本地截获并解码实际 JPEG 帮助图。探测没有执行 OneBot RPC、向 QQ 发送、调用聊天模型、登录、绑定或签到。主连接与旧订阅兼容连接的唯一发送者、广播去重、重启恢复、权限和 observe 行为由协议行为测试覆盖。

游戏解析、资源、登录、查询、面板、排行、帮助和定时任务由原上游实现拥有。Harness 不写 `GsUID.Core`、NTEUID 或 XutheringWavesUID 源码，也不通过改动上游配置或数据库实现兼容；正常游戏业务的运行数据仍由上游自身维护。
