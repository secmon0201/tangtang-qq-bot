# 独立语音运行时

语音默认关闭。新 `SpeechRuntimeManager` 只管理 TangtangHarness 自己启动的 GPT-SoVITS 实例，固定监听 `127.0.0.1:9890`。旧 `9880` 实例、旧监督器和旧声线配置不受新启停工具管理。

## 配置与启动

把 [speech.example.json](../config/speech.example.json) 作为新配置模板，另存为 `config/speech.json`；该文件已忽略，不应提交实例路径。填写以下项目：

| 项目 | 含义 |
| --- | --- |
| `enabled` | 默认 `false`；准备好独立运行环境后才设为 `true` |
| `python` | 已安装 GPT-SoVITS 依赖的 Python 解释器绝对文件路径；不是 Harness 的 Python 3.13 环境 |
| `api_script` | 可读的 GPT-SoVITS `api_v2.py` 绝对文件路径 |
| `tts_config` | 位于 TangtangHarness 内的独立 YAML 绝对文件路径，建议放在 ignored 的 `runtime/speech-config/tts_infer.yaml` |
| `bert_path` | GPT-SoVITS 文本多音字模型使用的 BERT 目录；填写只读外部模型目录，避免按相对路径访问 Hugging Face |
| `host`、`port` | 固定为 `127.0.0.1`、`9890` |
| `retry_seconds` | 后台重试间隔，默认 15 秒 |

YAML 中的 `custom.t2s_weights_path`、`custom.vits_weights_path`、`custom.bert_base_path`、`custom.cnhuhbert_base_path` 应填写已存在模型文件或目录的绝对路径。外部权重作为只读输入复用；不要把旧运行服务正在使用的 YAML 交给新实例，因为 GPT-SoVITS 会写回它。

运行 `scripts/start_speech.ps1` 启动独立实例，`scripts/start_speech.ps1 -Status` 只查进程状态，`scripts/stop_speech.ps1` 停止它。缺少配置或 `enabled=false` 时，启动命令只返回 disabled，不启动子进程。显式停止会保存新运行时自己的 `stopped.flag`，后台健康任务不会撤销此选择；准备好后再次显式启动会清除该标记。

这些显式启停同时通过 Harness 的公共生命周期控制器保存语音期望状态。外部[服务守护](服务守护.md)恢复语音还要求 Harness 期望开启且实际运行、模式为 `live`、Harness 自身 `speech_enabled` 开启、独立配置 `enabled` 开启，以及没有 `stopped.flag`。启动或重启 Harness 不会清除显式语音停止标记；关闭全部会关闭恢复意图，保留既有语音开关。语音恢复尝试、失败退避和结果保存在独立 `data/supervisor.db`，控制台可查看。

`running` 仅表示自有进程存在，不表示模型已经加载或合成 API 已就绪。Harness 的 `SpeechClient` 另查 `/docs` 就绪状态；聊天发语音还需要 Harness 自身的语音开关。语音不可用时继续使用文字。

聊天回复支持 `auto`、`accept`、`decline`、`text`，兼容既有 `voice` 值。明确要求语音且人格同意时直接合成；普通短对白默认 10% 概率尝试，同一会话成功发送随机语音后冷却 600 秒。用户要求文字或人格拒绝时保持文字，代码、链接和超过 200 字的说明也保持文字。多气泡只合成一次，使用完整 `speech_text` 或依次合并全部对白；语音成功不再附表情。合成或平台发送失败时静默回退原文字，故障记入后台。

表情候选由本地素材目录按本轮输入选取，放入动态上下文，素材变化不改变固定人格前缀。模型提供首选与替代 ID 后，程序按 60% 概率从认可候选中选择一个，排除最近两个已送达素材并降低 24 小时内重复项的权重。明确请求表情直接发送本地原始素材，不新增模型调用；动画素材按原文件发送。

## 文件与进程所有权

启动时，新运行器把 API 脚本以及旁边 `GPT_SoVITS`、`tools` 的源码和小型资源复制到新 `runtime/speech-runtime/source`，运行新副本。GPT-SoVITS 除了写 YAML，还可能在 `english.py` 旁生成词典缓存；源码副本使这些写入留在新目录。外部原源码不写入，也不安装或修改外部 Python 环境。

复制不包括模型权重、`pretrained_models`、G2PW 模型目录和旧缓存。某些 GPT-SoVITS 版本的附加模型采用固定相对位置：例如 v2Pro 的 SV、v3/v4 的 vocoder，以及文本预处理附加模型。实际启用这些版本前，需要在新副本对应位置准备它们的独立资源，或按该版本可用配置指向绝对资源；这里不假定只填写四个基础权重就能启动所有版本。不要将新副本的可写目录链接回旧源码或缓存。缺失资源会反映在新 `server.log`，真实声线和首条合成需要单独验证。

子进程工作目录、词典缓存、临时文件、Hugging Face/Torch/NLTK/Numba 缓存、输出和日志全部位于新 `runtime/speech-runtime`；合成 WAV 缓存由现有 `SpeechClient` 写入新 `runtime/speech`。旧声线权重切换接口不调用。

音频缓存包含参考音频内容、独立 YAML、合成参数与文本的哈希。参考音频或声线配置变化会重新合成；损坏的自产音频缓存会重新生成。合成占用期间不并行探测 `/docs`，避免 CPU 实例正在忙时误判失效。

进程记录包含 PID、创建时间、实际命令和新源码副本位置。停止前核对记录，停止自有进程及其子进程；记录与当前 PID 不匹配时明确报错。端口被其他进程占用时明确报错，不停止占用者。启动/停止共用新目录内的短操作锁，后台健康工作只做单次启动尝试并按间隔重试。

## 应用接口与验证范围

应用创建 `SpeechRuntimeManager(root)`，通过 `status()` 读取状态，`start()` 显式启动，后台使用 `await ensure_running()`。后台接口尊重保存的停止选择，不应在 QQ 消息路径等待启动。应用退出使用 `stop(disable=False)`，保留原来的启用选择；操作者显式停止使用默认 `stop()`。

语音健康检查使用独立的 `harness-speech` 后台任务，每 15 秒检查一次，不等待 B站、日程抓取或其他外部服务完成。外部守护启用时，由它统一负责拉起语音并保存恢复事件，内部任务只检查 API 健康；外部守护停用时，内部恢复仍尊重已保存的语音关闭意图与 `stopped.flag`，未关闭的语音意图可沿用原来的后台恢复。聊天事件只读取已有就绪状态；语音未就绪时继续文字回复。

[test_speech_runtime.py](../tests/test_speech_runtime.py) 启动独立的合成测试 Python 脚本，验证参数与端口、源码侧缓存和 YAML 写入位置、外部输入哈希不变、重复启动、进程树停止、记录不匹配、停止选择和有间隔的恢复。测试不启动 GPT-SoVITS，不调用 QQ 或模型，不验证真实语音加载和音色效果。

[test_reply_media_runtime.py](../tests/test_reply_media_runtime.py) 验证聊天到语音、失败文字回退、随机冷却、表情附带与单次模型调用；[test_speech_client.py](../tests/test_speech_client.py) 验证缓存失效、损坏重建、超时与合成期间的健康状态。实际 CPU 合成可运行 `scripts/probe_speech.py`，只生成新目录内的测试音频，不向 QQ 投递。
