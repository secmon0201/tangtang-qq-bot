# TangtangHarness 缓存优化与上下文窗口实施计划

本文保留原实施基线。当前默认聊天主路径已改为[上下文缓存主干](上下文缓存主干.md)：原样追加日志、容量重建和独立送达事实；下述自动学习、摘要与 AI 压缩仅适用于显式 legacy 布局。

本文件是 TangtangHarness 的缓存、记忆和上下文窗口实施基线。它把
[dsh-meow-memory](https://github.com/Phant0Meow/dsh-meow-memory/tree/f5987045812bbd928f7d2dd7a0ed064c3040d44f)
与
[dsh-meow-cachebilling](https://github.com/Phant0Meow/dsh-meow-cachebilling/tree/c0ba9d481da652bfe47ef399e0e340bb963a382d)
中可验证的做法转换成 Harness 的数据结构和操作规则。新代码、数据、接口和页面只放在
`TangtangHarness`；NoneBot、旧配置、旧数据库和上游 Core 不在本计划的修改范围内。

## 1. 目标和边界

目标是让每一次模型请求都能回答四个问题：实际发了什么上下文、缓存读写了多少、这一请求和这一窗口花了多少钱、继续使用旧窗口是否仍然划算。优化目标是降低同等有效对话质量下的总费用，同时保留群聊和私聊的历史可追溯性。

窗口是上下文和费用管理单位，不是 QQ 回复权限。群内普通聊天仍须呼叫娅娅或真实 `@`；主动聊天、免呼叫续聊、工具权限和群开关由各自配置决定。窗口关闭、释放或切换不自动改变这些触发规则。

本计划不把“高命中率”当成单一成功指标。缓存读取本身可能收费，命中率升高而缓存输入变长时总费用仍可能上升。因此每次决策同时看缓存 token、缓存读取金额、未命中输入、输出、总金额、上下文容量和有效对话质量。

## 2. 从两个插件吸收的确定性做法

### 2.1 dsh-meow-memory 的可迁移部分

1. **固定说明和可变记忆分离。** 人格、输出协议和稳定规则留在版本化固定前缀；画像、群状态、近期事实和工具结果作为独立动态层。修改动态记忆不应无意改写整段固定前缀。
2. **窗口建立时冻结记忆基座。** 新窗口只选取当前有效的 soul、用户资料、项目或群规则和高价值长期事实，保存 `memory_snapshot_revision`。后续请求重放同一快照，不每轮把整库重新注入。
3. **增量、少量、可解释的本地检索。** 新问题只检索相关的 active 记忆，默认取少量结果；结果带 `(memory_id, version)`、来源和分数。没有相关内容时保持空，不为了填满数量注入无关资料。
4. **按实际版本去重。** 去重键是 `(memory_id, version)`，不能只按曾经出现过的 ID；更正、遗忘和恢复必须能使新版本重新进入上下文。
5. **压缩后重建。** 压缩成功后结束旧上下文段，在下一条真实用户消息建立新的记忆基座，补回本窗口确实使用、创建或更新且仍有效的条目。压缩失败不能清除旧段状态。
6. **后台整理按窗口空闲和范围运行。** 整理使用窗口截止时间冻结的资料，结果进入后台记录和下一窗口的快照；不能把后台三轮整理结果直接追加到前台历史，不能用后台自激改变活动窗口。

BM25、中文二元词、时间衰减和重要性权重可作为本地检索的实现参考，但它们是启发式，不应在页面上宣称为科学记忆模型。七层记忆可以映射到现有的事实、认知、成长、话题和摘要记录，不必为了复刻插件新建七套表。

### 2.2 dsh-meow-cachebilling 的可迁移部分

1. **四类 usage 分开记账。** 对每一次模型尝试保存未命中输入 `input_tokens`、缓存读取 `cache_read_tokens`、缓存写入 `cache_write_tokens` 和输出 `output_tokens`。供应商没有报告的字段保持 `unknown`，不得填零。
2. **三级账目。** 同时保存当前 API step、用户消息 turn（同一条消息可能多次请求）和窗口累计；跨窗口另存会话或群/用户累计。流式 chunk 的重复 usage 用最终样本替换，不能重复计费。
3. **按事件时间取价。** 单价按供应商、模型、渠道、币种、价格版本和请求时刻计算；支持峰谷或固定价格，但页面必须标注“配置估算”，实际扣费以供应商账单为准。
4. **缓存失效可观测。** `cache_write_tokens > 0` 标记前缀写入或失效线索；有输入而 `cache_read_tokens = 0` 标记完全未命中。两者是观测指标，不等同于供应商确认的缓存过期原因。
5. **用曲线指导换窗。** 显示本窗口每步真实费用、累计费用、缓存读取费用、若全部按未命中计的费用，以及新窗口首轮重建成本。只有比较继续旧窗口和新窗口的回本轮数后才切换；插件本身没有可靠的过期预测，Harness 也不伪造预测。

## 3. 会话、窗口和上下文模型

### 3.1 永久会话与活动上下文段

每个群和私聊均有永久业务会话，保存原始消息、完成轮次、工具结果、记忆版本和实际请求。永久会话下分多个上下文段（`window_epoch`）：

| 范围 | 会话键 | 活动窗口 | 关闭/切换规则 |
| --- | --- | --- | --- |
| 群聊 | `group:<group_id>` | 同一群独立维护；默认持续到预算或成本策略触发切段 | 当前轮完成后换段，旧段只读保留 |
| 私聊 | `private:<user_id>` | 用户活跃时保留；默认闲置 60 分钟释放内存（可配置） | 释放只清运行态；再次发言按历史、预算和成本决定续用或新段 |

活动窗口释放不删除历史，也不声称关闭供应商远程 KV。供应商是否保留缓存只能由实际 usage 验证。窗口 ID 本身不会产生缓存；只有相邻请求的真实 token 前缀一致，才可能复用供应商缓存。

每个窗口保存：`window_id`、`scope_key`、`opened_at`、`last_activity_at`、`closed_at`、`close_reason`、`fixed_prefix_hash`、`memory_snapshot_revision`、`context_revision`、`model_profile_id`、`provider`、`api_format`、`price_version`。模型切换不删除永久历史，但新模型从自己的固定前缀和容量预算重新构建。

### 3.2 请求排列

在同一窗口内，输入顺序固定为：

1. 固定人格、输出协议和稳定规则；
2. 窗口记忆基座快照；
3. 已完成轮次，保留真实说话者、引用关系和必要媒体引用；
4. 本轮少量增量记忆、必要工具事实、群/用户状态；
5. 当前用户消息和当前轮临时数据。

动态尾部只在确有变化时加入。整库工具目录、全部画像、完整图卡和大型 JSON 不进入固定前缀；工具结果只有在用户明确要求分析或后续追问时才选择性注入。每次实际发送前冻结构建结果并保存来源、采用项、排除项、估算 token 和最终供应商 usage。

### 3.3 预算和切段信号

模型档案必须填供应商确认的 `context_limit`；为空时不能按名称猜测。默认输入预算为：

```text
min(32768, context_limit - output_reserve - 1024)
```

达到预算 75% 时安排后台压缩评估，达到 90% 时当前轮完成后优先评估切段；当前输入和固定内容本身超预算时明确记录失败原因，不静默裁剪用户请求。

成本切段采用可解释的回本模型。对继续旧窗口的未来 `N` 轮和新窗口的首轮重建及未来 `N` 轮分别估算：

```text
step_cost = cache_read * read_rate
          + input_miss * miss_rate
          + cache_write * write_rate
          + output * output_rate

break_even_rounds = new_window_setup_cost
                  / (old_window_expected_cost - new_window_expected_cost)
```

当分母大于零且预计继续轮数达到回本轮数，或容量达到 90% 的切段信号成立时，标记 `switch_recommended`。价格或 usage 缺失时不做金额自动切段，只保留容量、前缀变化和 token 量的切段依据；页面显示“未知”，不补零。实际执行需等当前请求、送达和必要后台写入结束，避免切断进行中的请求。

## 4. 数据口径和存储要求

所有记录写入 TangtangHarness 自有 SQLite。推荐的逻辑对象如下，表名可按现有 store 命名调整，但字段语义必须保持一致：

| 对象 | 最小字段 | 作用 |
| --- | --- | --- |
| `conversation_windows` | window、scope、epoch、开闭时间、关闭原因、前缀和快照 revision | 记录活动段边界 |
| `context_builds` | request_id、各层内容/hash、来源、采用/排除、估算 token、预算 | 解释实际构建 |
| `model_attempts` | request、window、turn、provider、model、用途、状态、耗时、usage 原样和归一化值 | 每次真实请求和失败尝试 |
| `billing_samples` | input/cache-read/cache-write/output、费率版本、币种、估算金额、覆盖状态 | 可重算账单，未知不归零 |
| `memory_snapshots` | scope、window、revision、memory id/version、来源和发布时间 | 冻结窗口记忆基座 |
| `window_decisions` | 当前指标、预测范围、阈值、建议、实际结果、人工/自动原因 | 解释为什么换段 |
| `background_jobs` | 类型、窗口截止游标、预算、排队和结果 | 区分后台费用与前台费用 |

口径定义：

- **缓存 token 占比** = `cache_read_tokens / (cache_read + input_miss + cache_write)`，仅在分母和字段覆盖完整时计算。
- **请求命中比例** = `cache_read_tokens > 0` 的可判断请求数 / 可判断请求数。
- **缓存读取金额**、**未命中金额**、**输出金额**分别计算；不能用总费用减法猜测缺失项。
- **窗口费用**是该 `window_id` 真实模型尝试的合计，失败且无 usage 的费用为未知；后台摘要、画像、预热和实验按 `purpose` 单列。
- **有效对话轮**以平台确认送达的业务回复为准；生成文本或失败尝试不能伪装成已完成轮次。
- 估算 token、供应商 usage、配置价格和实际账单不混在一个字段中，导出时保留来源和覆盖率。

## 5. 实施阶段和交付物

| 阶段 | 工作内容 | 交付物 | 进入下一阶段的证据 |
| --- | --- | --- | --- |
| P0 基线 | 核对现有 context、store、models、后台队列和控制台字段；建立 usage 与价格字段映射 | 字段映射、当前前缀样本、缺失字段清单 | 每种 API 格式至少有一份真实请求边界样本 |
| P1 窗口存储 | 增加群/私聊永久会话与活动窗口 epoch；实现私聊闲置释放、群切段状态和历史只读重放 | `conversation_windows`、窗口 service、迁移测试 | 并行群/私聊隔离，释放不删历史，旧框架未改 |
| P2 记忆基座 | 首轮冻结快照、增量本地检索、`(id,version)` 去重、压缩成功后重建 | `memory_snapshots`、检索和压缩接线、版本测试 | 同窗口相邻请求的固定层和基座稳定，更新/遗忘可重新出现 |
| P3 费用归一 | 接入 Responses/Chat Completions/中转 usage；保存四类 token、价格版本、三级账目和失败未知 | billing adapter、重算命令、供应商字段测试 | 合成 usage 能重算；缺字段不变零；流式 chunk 不重复 |
| P4 换段决策 | 实现预算信号、费用曲线、回本轮数和 `switch_recommended`；当前轮完成后执行新段 | decision service、窗口事件和手动覆盖 | 固定实验能解释“继续/切段”；无价格时仍能按容量工作 |
| P5 可视化 | 总览、流量日志、上下文层、缓存费用、窗口时间线、模型和群/私聊钻取 | 本机控制台页面与 REST/SSE 数据 | 页面正文与实际请求记录一致；预览和查询零模型调用 |
| P6 业务并行 | 先在离线、observe、专用 `#harness` 范围验证，确认工具零模型、聊天按呼叫规则 | 回放、工具与聊天行为报告 | 旧 NoneBot 仍可独立启动；未发生双发送 |
| P7 真实限定联调 | 对固定测试群和一名私聊用户做小样本请求、缓存连续请求、换段和回切 | usage、回执、窗口决策和费用报告 | SnowLuma 回执成功、费用可解释、失败静默记录 |
| P8 日常切换 | 旧接单者停止、最终快照、启用 Harness 唯一接单；保留旧回切入口 | 切换清单、运行说明、回切验证 | 旧源码/库未改，Harness live、连接和看板正常 |

实施过程中不训练小模型、不引入通用插件平台、不把远程 provider conversation id 当作缓存前提。只有规则识别的实际缺口达到可量化阈值，才另立小模型评估任务。

## 6. 验收矩阵

| 验收项 | 测试方法 | 必须看到的证据 | 不通过时处理 |
| --- | --- | --- | --- |
| 群隔离 | 两个合成群交替对话 | 各自 `scope_key`、历史和窗口不串，前缀 hash 可分别追溯 | 修复路由和查询，不扩大共享上下文 |
| 私聊临时窗口 | 同一用户活跃、闲置、再次发言 | 运行态释放；永久历史不丢；再次发言可续段或新段且有原因 | 修复 idle worker 和重放边界 |
| 触发规则 | 群消息无呼叫、呼叫、真实 @、私聊 | 无呼叫不产生聊天请求；明确命令仍可执行 | 修复 router，不通过窗口逻辑放宽权限 |
| 固定前缀稳定 | 同模型同参数连续三轮 | fixed hash 和基座 revision 不变；动态变化有来源 | 找出注入顺序变化，禁止隐式时间/随机值进入固定层 |
| 记忆去重 | 重复问题、记忆更新和遗忘恢复 | 同版本只注入一次；新版本可进入；已遗忘内容不再进入 | 检查 `(id,version)` 和 snapshot 发布 |
| 压缩切段 | 达到 75%/90% 模拟压缩 | 压缩成功后下一轮新 epoch；失败保留旧段；最近轮次和未决事项可用 | 修复压缩事务，不删除原始历史 |
| usage 归一 | Responses、Chat Completions、中转和缺字段样本 | 四类 token、供应商原字段、覆盖率和未知状态正确 | 修复 adapter，不补零或猜字段 |
| 费用准确 | 固定价目表合成样本 | step/turn/window 金额可手工复算；币种和价格版本保留 | 修复计费公式或价格版本，不修改历史样本 |
| 缓存失效标记 | cache write>0、read=0 和正常命中样本 | 失效线索、完全未命中和供应商确认分开 | 只改显示语义，不声称知道过期原因 |
| 换段回本 | 构造继续旧段更贵、新段首轮更贵两种样本 | decision 记录输入、阈值、预测轮数和实际结果 | 调整阈值配置；价格未知时只走容量策略 |
| 后台成本隔离 | 摘要、画像和预热任务 | `purpose=background`，费用不混入前台；预算耗尽留 queued | 修复队列账本，不伪装成功 |
| 实际请求可见 | 请求详情与导出 | 页面显示实际 payload 来源和 usage；密钥不出现 | 修复保存边界和脱敏 |
| 零 token 工具 | 帮助、排行、状态、组合本地工具 | 模型尝试数为 0，QQ 回执成功 | 修复路由，避免工具目录注入聊天 |
| 模型切换 | 同一业务历史切换两个模型 | 历史共享但 prefix/model/provider 统计分开；容量为空不发送 | 修复 profile 和 key，不按模型名称猜容量 |
| 旧系统独立 | 分别启动/停止旧 NoneBot 和 Harness | 一方启停不改另一方源码、库、端口和连接 | 停止发布，先修边界 |
| 回切 | 运行旧回切入口后发合成检查 | Harness 观察/停止，旧入口可启动；无重复发送 | 修复运维脚本，不重启 QQ/SnowLuma |

完成标准是矩阵每行都有运行证据、请求或数据库记录和对应报告；单元测试通过但没有实际请求边界证据时，只算部分通过。

## 7. 风险和处置

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| 供应商不报告 cache 字段 | 无法可靠计算金额和命中 | 显示未知，保留原始 usage；只用容量策略切段 |
| 只换 window id，实际仍发送同样长历史 | 费用不降且误以为优化成功 | 切段必须改变实际上下文构建；用 prefix hash 和 payload diff 验证 |
| 动态时间/随机内容进入固定层 | 每轮缓存前缀分叉 | 将动态状态放尾部，固定层仅版本化稳定文本 |
| 过早换段 | 新窗口重读成本高，质量下降 | 使用回本轮数并要求当前轮完成；保留人工关闭自动切段开关 |
| 过晚换段 | 长缓存读取费用持续上升或容量超限 | 75%/90% 水位、窗口费用曲线和下一轮预测提前提示 |
| 后台整理自激 | 增加模型费用并扰动前台前缀 | 后台使用截止游标、独立预算和 `purpose`，结果下一窗口才使用 |
| 私聊 idle 误删上下文 | 对话质量下降 | idle 只释放内存，历史和快照永久保存；再次发言可重建 |
| 双系统重复发送 | 用户收到两份回复 | observe/专用范围先验证，切换前确认旧接单停止并保留回切入口 |

## 8. 运维和可视化最低要求

控制台至少提供窗口时间线、实际请求详情、四类 token、缓存读取金额、未命中/写入金额、输出金额、覆盖率、未知字段、当前预算水位、压缩/切段原因、预计回本轮数以及按群、私聊、模型、用途的筛选。图表可以使用曲线、堆叠面积、分布柱、散点、时间线和明细表，但每个金额必须能跳转到原始请求。

收费实验、预热和手动换段必须显式触发；查询、回放和预览不得调用远端模型或发送 QQ。错误写请求、工具和后台日志，QQ 只收到正常业务结果、参数澄清或必要的用户操作提示。

本文件完成后，实施应按 P0→P8 顺序推进；每阶段更新交付物和验收证据，不能以“窗口 ID 增加”或“本地估算命中率上升”代替供应商实际 usage 和费用验证。
