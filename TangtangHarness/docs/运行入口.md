# 启动工具与运行入口

日常运行使用 `TangtangHarness/启动工具`。本目录已统一为下面这套入口，旧 Harness 快捷方式已替换；仓库根目录的旧 NoneBot 启动工具继续独立保留。

## 快捷方式

| 文件 | 用途 |
| --- | --- |
| `01-启动全部.bat` | 按 Core → Harness → SnowLuma 启动完整 Harness 运行链路。 |
| `02-关闭全部.bat` | 按 Harness → Core → SnowLuma 关闭，QQ 保持运行。 |
| `41-检查全部状态.bat` | 检查 Harness、Core、SnowLuma 及相关连接和语音状态。 |
| `11-启动Harness.bat` | 启动 Harness；语音按已保存的开关运行。 |
| `12-停止Harness.bat` | 停止 Harness 及其拥有的语音运行进程，保留语音开关。 |
| `13-重启Harness.bat` | 先停止再启动 Harness，不重启 Core、SnowLuma 或 QQ。 |
| `21-启动Core.bat` | 启动 GsUID Core，供 `#nte`、`#ww` 上游转发使用。 |
| `22-停止Core.bat` | 停止 Core；Harness 的聊天与本地功能继续运行。 |
| `31-启动SnowLuma.bat` | 启动 SnowLuma，使用已有安装、配置和 QQ 登录态。 |
| `32-停止SnowLuma.bat` | 停止 SnowLuma，QQ 保持运行；Harness 控制台仍可访问。 |
| `51-打开Harness控制台.bat` | 打开本机 Harness 控制台，默认 `http://127.0.0.1:8090/`。 |
| `52-打开SnowLuma管理页.bat` | 打开本机 SnowLuma 管理页，默认 `http://127.0.0.1:5099/`。 |

网页入口读取本机配置后打开浏览器；服务启动后页面才可访问。实际地址以状态输出为准。

## 日常使用

双击 `01-启动全部.bat`，完成后运行 `41-检查全部状态.bat`。Harness 服务运行与 QQ 连接成功是两项不同的状态：控制台能打开，但 OneBot 未连接时，机器人仍不能接收和回复 QQ 消息。游戏还需要 Core 运行并建立 Harness 的 Core 连接；语音按已保存的开关及独立运行配置显示状态。

修改 Harness 的 Python 代码后使用 `13-重启Harness.bat`。只需启动某项服务时使用对应的独立入口。结束使用执行 `02-关闭全部.bat`；运行开关及数据库保留，下次启动沿用原设置。

启停入口同时登记服务的期望状态。启动失败会保留“期望开启”供看门狗按退避恢复；显式停止先登记“期望关闭”，不会被下次定时检查重新拉起。关闭全部先关闭全部服务的恢复意图，保留语音保存开关；重新启动 Harness 时仍尊重独立语音的停止标记。直接在任务管理器里结束进程按意外退出处理。看门狗总开关、计划任务及恢复历史见[服务守护与恢复记录](服务守护.md)。

SnowLuma 启动使用已有配置，不新增或覆盖 OneBot 连接。QQ 登录、二维码、验证码、设备验证及 SnowLuma 管理页登录仍由操作者完成。启停脚本不会自动登录或切换账号。

## 业务网页的公网地址

排行、帮助、日程及业务管理页使用 Harness 自有 SQLite `data/harness.db` 的 `web_base_url` 拼接在线链接。公网实例填写已由 Cloudflare 接管的 HTTPS origin，例如 `https://example.invalid`，不带 `/business` 或尾部斜线；真实域名只存入本机运行配置。未配置时保留本机 `http://127.0.0.1:8090` 地址。

首次配置导入会读取旧 `.env` 的非空 `PUBLIC_SITE_BASE_URL`，保存为 `web_base_url` 并启用 `public_gateway_enabled`；非空 `PUBLIC_SHORT_HOST` 保存为 `public_short_host`。空字段不会生成公网地址。已有实例需要单独修改这几项时，使用本机控制台“工具”页选择“系统设置”、选择已配置超级管理员的私聊，在“高级参数 JSON”中执行下面的对象；按表逐项替换 `key` 和 `value`，并保持发送结果开关关闭：

```json
{"key":"web_base_url","action":"set","value":"https://example.invalid"}
```

| `key` | `value` |
| --- | --- |
| `web_base_url` | 实际 HTTPS origin 字符串。 |
| `public_gateway_enabled` | JSON 布尔值 `true`。 |
| `public_short_host` | 旧实例的短域名字符串；没有则省略。 |

该操作使用已有的本机 `POST /api/tools/run`，业务设置写入 Harness SQLite；“模型与设置”的运行配置 JSON 保存的是另一类配置，不能代替这些业务设置。已有实例不必重新执行完整配置导入，以免重新覆盖模型与运行选项。

保存后使用 `13-重启Harness.bat`。公网业务网关默认监听 `127.0.0.1:18769`，复用已有 Cloudflare Named Tunnel，将业务域名 origin 指向此端口。网关提供业务页面、业务资源及业务 API，并保留 NTE、完美登录及鸣潮的受限登录路径到本机 Core；完整 Harness 控制台继续在 `http://127.0.0.1:8090/` 本机使用。查重、白名单和公告管理页由 QQ 私聊工具为有权限的操作者签发 15 分钟链接；群内请求提示私聊获取，过期后重新索取。

这项调整只需单独重启 Harness，Core、SnowLuma 和 QQ 沿用当前进程和登录态。域名配置与 Tunnel 凭据属于本机运行数据，不写入公开模板或源码。

## 命令行入口

在 `TangtangHarness` 目录中执行：

```powershell
.\scripts\stack.ps1 -Action start-all
.\scripts\stack.ps1 -Action stop-all
.\scripts\stack.ps1 -Action status
```

其他动作与快捷方式对应：

| `-Action` | 动作 |
| --- | --- |
| `start-harness` | 启动 Harness。 |
| `stop-harness` | 停止 Harness。 |
| `restart-harness` | 重启 Harness。 |
| `start-core` | 启动 Core。 |
| `stop-core` | 停止 Core。 |
| `start-snowluma` | 启动 SnowLuma。 |
| `stop-snowluma` | 停止 SnowLuma。 |
| `open-console` | 打开 Harness 控制台。 |
| `open-snowluma` | 打开 SnowLuma 管理页。 |

快捷方式仅负责调用 `scripts/stack.ps1`；服务实现和状态查询留在 `scripts` 与 Harness 自有运行模块中。原有 `scripts/start.ps1`、`stop.ps1` 等底层入口继续供脚本调用。

服务守护通过独立命令行入口管理，首次部署执行 `install` 注册当前用户计划任务，再执行 `enable` 纳入当前运行服务；已经保存的关闭意图不会被覆盖：

```powershell
.\scripts\watchdog.ps1 -Action install
.\scripts\watchdog.ps1 -Action enable
.\scripts\watchdog.ps1 -Action status
```

`disable` 停用外部恢复而不停止当前服务，`uninstall` 先停用再移除本 Harness 任务。`status` 查询服务意图、事件和计划任务状态，`check` 可能实际启动缺失服务。计划任务使用自有 `pythonw.exe`，每分钟和用户登录时无窗口检查；子检查限时 45 秒，任务限时 50 秒供失败记录落库。语音原有后台恢复继续尊重已保存的关闭意图，具体交接规则见[服务守护](服务守护.md)；本入口不依赖旧 QQBot 看门狗。

## 旧系统回切

这套启动工具不启动旧 NoneBot。需要回切时先在 `TangtangHarness` 目录运行：

```powershell
.\scripts\switch_to_legacy.ps1
```

该脚本把 Harness 改为观察模式并停止它，然后由操作者使用仓库根目录的旧 NoneBot 专用启动入口恢复旧接单。脚本本身不启动旧 NoneBot，不重启 SnowLuma、QQ 或 Core。恢复 Harness 接管前先停止旧 NoneBot，确认旧 8080 已停止接单，再将 Harness 配置恢复为 `live` 并运行 `11-启动Harness.bat`。

以前的 `41-启动Harness.bat`、`42-停止Harness.bat`、`43-重启Harness.bat`、`44-查看Harness状态.bat`、`45-打开Harness控制台.url` 和 `46-回切旧NoneBot.bat` 是历史入口。当前操作以本页的新文件名为准，历史验收记录中的旧名称只表示当时的入口。
