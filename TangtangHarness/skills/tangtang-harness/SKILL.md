# Harness 制作、修复与维护

将当前工程的制作、故障修复和日常维护方式复用于后续任务。技能权威源位于 `TangtangHarness/skills/tangtang-harness`；本地 Codex 使用目录联接，后续修改始终写回权威源。

## 定位工程与选择流程

1. 先用 `Path.resolve()` 或 PowerShell 联接 Target 将技能目录解析到权威源，所有相对引用也以权威源为基准；从该目录向上定位同时包含 `tangtang_harness`、`pyproject.toml`、`scripts` 的 Harness 根目录，记为 H。当前工作区若是外层仓库，也检查其 `TangtangHarness` 子目录。外层 Git 仓库记为 R；命令必须在正确根目录执行，不嵌入本机绝对路径。
2. 读取 H 的 [AGENTS.md](../../AGENTS.md) 和 [README.md](../../README.md)，检查 R 的 `git status --short`。保留其他任务的未提交改动。涉及外层仓库提交或旧系统操作时，再读 R 的 `AGENTS.md` 和仓库维护约定。
3. 按任务只读取相关流程；第一次接手或不清楚所有者时先读 [工程定位](references/project-map.md)。

| 用户意图 | 加载的流程 | 应交付的结果 |
| --- | --- | --- |
| 新建 Harness、迁移功能、扩展能力、制作控制台或优化上下文 | [制作流程](references/build.md) | 可执行的实现、实际入口接线、行为证据和当前文档 |
| 不能回复、功能遗漏、协议错误、超时、缓存或页面异常 | [修复流程](references/repair.md) | 可关联的根因、范围内修复、回归结果；需要部署时补运行核验 |
| 启停、状态检查、配置维护、迁移补缺、依赖更新、清理或回切 | [维护流程](references/maintenance.md) | 操作后的实际状态、数据保留结果和仍需人工处理的事项 |

组合任务按实际需要接续流程。小修复不重跑首次迁移；安装、离线检查和技能编辑不自动变成生产切换。

## 持续保留的工程边界

- 当前聊天默认 `cache_first`：原样模型日志与 QQ 已送达历史分开，输入发送边界提交、原样输出与送达事实尾追加。思考等级是请求参数，不改变同一模型档案的会话身份；旧版本因思考等级分开的缓存首次读取时迁移合并。输入预算默认按模型档案容量扣除输出与安全预留自动计算；默认 90% 一次换段、按 50% 总输入预算保留完整近期事件组，不受 `recent_rounds` 上限约束。真实输入 usage 校准容量估计，不能改写旧 payload 或冒充缓存命中。自动记忆/认知/成长/画像/摘要/模型压缩退出该路径；显式记忆工具及独立业务保留。以实际 usage 验证上游命中，详细约定见 H 的 `docs/上下文缓存主干.md`。

- Responses 成功输出被动归档原生 `output` 与完整性，不向 QQ 发送推理状态。仅档案显式 include `reasoning.encrypted_content` 且推理非 `none` 时将新生成的完整 encrypted reasoning + assistant message 批次加入统一日志；已保存的原生批次在后续切换思考档位或移除 include 时仍原样回传，不重写冻结历史。未知或原生工具输出仅归档，不拆链或执行。当前 `none` 纯正文日志仍走正文输入，不自动改配置或调用模型探测能力。原生批次随事件整组裁剪，遗忘和过滤整窗撤销；代码支持不等于中转已支持，不把密文估算写入实际 usage。真实缓存对照由操作者正常使用完成。

- 使用 Windows 本地 Python 3.13、asyncio、FastAPI、SQLite、OneBot v11 与 React/TypeScript/Vite。新代码、配置、资源、依赖、脚本、测试和运行文件均在 H。运行时禁止 `import bot.*`、NoneBot 或 DSH；成熟算法和素材在 H 移植并替换框架绑定。
- 旧 NoneBot、旧数据库、旧配置及上游 Core/NTEUID/鸣潮保持独立。旧实现作为行为来源只读核对，不为 Harness 迁移修补旧框架；不要套用旧 `bot/plugins` 注册规则到新 Harness。
- 纯工具直接执行业务并交付，不调用聊天模型或间接 AI 整理；工具目录不整体加入人格前缀。用户明确要求分析结果时才走相应聊天路径。
- 群内普通自然语言聊天和工具请求需要呼叫“娅娅”或真实 @ 机器人，明确业务命令直接可用。主动聊天、免呼叫续聊、画像、成长、语音及后台整理各自保留保存开关，不能因修复或迁移顺便开启。
- 默认新安装为 `observe`。离线回放、预览和普通离线实验不调用远端模型、不发 QQ；不重放导入的旧 pending、发送、语音、续聊或主动任务。既有 live 实例保持其当前配置，实际模式现场读取。
- 模型、Core、语音与工具技术错误保存在后台日志、请求/工具记录和本机控制台；QQ 可返回参数澄清、正常业务状态及必要人工操作提示。语音失败回退业务文字；工具技术失败不能转成一次额外分析请求。
- 游戏命令保持上游原生行为与完整原文；主 Core 连接是唯一命令发送者，兼容连接仅收旧订阅。更换 route identity 要验证协议与订阅，不能修改上游源码、配置或数据库来补兼容。
- 实际模型请求在发送边界保存；每次尝试、失败、用途和送达分别记录。只有平台确认回执才算已送达。usage 缺项、未知容量与缺失价格保持未知；本地 token/金额估算与供应商观测分开。
- 网络连接、健康与重连放在有间隔、有界、独立的后台任务，不阻塞无关业务。关闭某类工作不能阻塞队列中其他任务。
- 服务启停经 Harness 公共生命周期控制器和文件锁，先保存独立 `data/supervisor.db` 中的期望状态。守护只恢复归属确认、期望开启且相关开关允许的缺失进程；显式停止保持关闭，活进程断线或不就绪只记录。Core 尊重 `extra.core.enabled`，语音同时尊重 Harness 状态、live 模式、`speech_enabled`、独立配置与 `stopped.flag`。运行开关由 `config/settings.json` 和 `config/speech.json` 保存，不能与业务 SQLite 群开关混用。守护启用时统一负责语音拉起与恢复记录，内部语音任务只查健康；`disable` 暂停外部恢复，内部语音仅在意图未关闭且保存开关允许时沿用原恢复行为。当前用户 Windows 计划任务使用自有 `pythonw.exe` 无窗口入口，每分钟/登录时检查；子检查限时 45 秒、任务限时 50 秒，最多尝试恢复一项，失败写守护事件与 `logs/watchdog-supervisor-check.log`。不直接调度 PowerShell，也不接管旧 NoneBot 看门狗。详见 H 的 `docs/服务守护.md`。
- 迁移用旧 SQLite 只读在线 backup，保留 WAL 中已提交的数据；新库独立写入。重复累计与新设置保留必须实际验证；现有全量导入会更新部分设置，既有实例或限定范围迁移先读维护流程中的导入边界。清理只覆盖自有生成缓存，历史、媒体、快照和备份不自动删除。
- 账号扫码、验证码、设备验证由用户操作。沿用会话已有授权推进任务；QQ 实发、付费实验、共享连接更改和生产接管须在本次授权范围内。缺少授权时先完成可审阅的本地实现与验证，再询问具体剩余操作。

## 完成与持续维护

代码改动按 H 的维护约定运行行为测试及前端构建；提交前在 R 运行仓库要求的全部校验。技能或文档修改核对 frontmatter、相对链接、安装联接和脚本行为；不以这些检查代替代码或实机验收。详细命令见 [维护流程](references/maintenance.md)。

交付说明包含：实现或修复了什么、验证到哪条边界、是否已部署、仍未验证的实际行为。将敏感运行证据留在 H 的 ignored `runtime/verification`；公共文档使用合成身份与 `example.invalid`。测试总数、模型选择、在线连接和开关属于现场状态，不写成技能常量。

工作中发现真实流程变化时，在同一任务内更新受影响的引用和本技能；核心入口/API、配置优先级、生命周期或错误交付变化同时更新 H 的对应文档。保留“已实现”“本次已验证”“计划”之间的区别，避免依据历史验收记录自动恢复早期配置。
