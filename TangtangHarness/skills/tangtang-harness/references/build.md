# 制作与扩展流程

在已有 Harness 上做增量实现。只有首次建设或用户要求重新迁移时，才展开基础运行时与数据迁移步骤。

## 先确定可执行的功能合同

对每项需求明确：触发入口、群/私聊范围、角色、保存开关、业务数据来源、是否允许模型调用、结果交付、后台所有者和本次验收边界。按[工程定位](project-map.md)找到现有实现；迁移旧功能时以旧有效源码和迁移台账对照参数、默认值、媒体及失败行为。

不要将退役活动、问卷、官方 QQ OpenAPI 或本地 NTE/鸣潮接管重新列为待迁移能力。游戏采用 Core 原生透传，成熟本地业务采用迁入 H 的实现。

## 首次建设或迁移的推进顺序

1. 建立 H 自有环境、配置、SQLite、OneBot 接收/RPC、事件去重及平台回执，默认 observe。先用合成事件与临时数据库验证断连、重复事件与发送失败。
2. 移植业务算法和素材，替换旧配置单例、数据库、事件类型与发送入口。补上路由、目标解析、权限、保存开关、后台生命周期及图文/网页交付，再验证完整行为；仅复制文件或登记目录不算完成。
3. 实现聊天所需的实际请求保存、Responses/Chat Completions、媒体、分层上下文和已送达历史；再接后台记忆、成长、摘要、压缩及可选画像。任务预算与前台费用区分，保存开关不因实现完成而启用。
4. 在独立 adapter 中接 Core、TTS、B站及日程；连接/重试与启动健康任务独立且有界。模拟协议通过后，再按授权做限定真实联调。
5. 控制台读取相同业务来源，展示实际请求、用量来源、覆盖率、未知值和错误；本机控制台与受限公网业务网关分别使用已有入口。
6. 数据导入先预览，再按本次授权写新目录；验证重复导入、可变版本、图片引用、关闭项及旧队列不重放。生产切换使用[维护流程](maintenance.md)，并行测试不代替唯一接单验收。

## 单功能如何完成接线

沿着 `InboundEvent → Runtime/Router → ToolExecutor 或 ChatService → 业务实现 → 媒体/OneBot → 回执和 Store` 检查需要修改的环节。后台功能额外核对 `Runtime.start/close`、调度时刻、预算、群同步及重连后的恢复。

纯本地工具以真实业务结果为事实来源，不把大图卡或完整 JSON 回灌模型。组合解析不能拆断游戏原文或用户参数；用户要求分析时仅采用必要结果。权限和业务写入由本地执行路径确认。

迁移配置区分“缺失”“显式空值”“显式 false/0”。首次导入允许按来源规则迁移；既有实例补缺只添加不存在的 key 或字典字段，保留用户已经保存的新选择。旧源码默认值需要时通过 AST 读取字面量，不 import 或执行旧模块。

## 上下文、缓存与费用的制作要点

- 优先维护当前 `cache_first` 单一路径：原样模型输入/输出日志、独立 QQ 回执、只追加新事实、容量一次重建。不要为提高缓存恢复自动资料整库注入或后台模型整理。旧构造器隔离在 `legacy_context.py`，只能显式选择 legacy；两个布局不混用。

- 永久会话与活动 `context_epoch` 分离；闲置释放运行态保留历史。群/私聊按当前实现隔离，关闭成长或遗忘内容不能继续进入请求。
- 人格、输出协议和稳定规则保留版本化固定层；可变资料、当前状态和本轮工具事实进入相应动态层。核对实际 payload 排列和 hash，不用相同窗口 ID 证明缓存命中。
- 容量填供应商确认值，不根据模型名猜测；现场已有档案配置不能自动声称已验证上游支持。cache_first 的 `cache_input_budget_tokens=null` 自动使用档案容量扣除输出与 1024 安全预留，人工正整数只作更低上限；默认 90% 一次切段，以 50% 总输入为目标选择连续完整近期事件组。真实总输入 usage 只校准容量判断，不改旧日志，不补造供应商缺失字段。预算不足不静默删掉用户请求。legacy 的压缩成功发布后才按当前实现切段，失败保留原历史与有效快照。
- 保存供应商原 usage 与归一结果，检查不同渠道的输入/缓存语义、流式最终样本、失败未知、价格版本与币种。缺价格/usage 时不猜金额，也不启动额外预热补数据。
- 优化结论同时看费用、上下文容量和有效对话；本地公共前缀长度或路由耗时只证明对应本地指标。

## 验证与交付

选择能证明需求的行为验证：触发/不触发、开关与权限、真实本地数据、模型调用次数、失败降级、回执、重启与数据保留。涉及外部服务用模拟 QQ/Core/TTS/模型，临时新库与合成身份；UI 修改另验证桌面/手机、范围切换和慢响应。

执行现有 Harness 行为测试与前端构建，更新对应功能文档、迁移来源和本技能的受影响指引。声明清楚“本地通过”“实机协议通过”“实际 QQ 回执成功”“已部署”分别验证到了哪里。文档/技能编辑不为证明可用而发 QQ、调用收费模型或切生产开关。
