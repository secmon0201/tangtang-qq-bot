# 修复流程

## 建立当前故障证据

从用户给出的功能、时间、入口或请求关联定位现有记录。先读运行中的 `/api/status`、相关请求/工具/队列和日志的最小片段；保留其他会话改动，识别磁盘代码是否已被当前进程加载。日志与供应商错误摘要可以含私有正文、身份或凭据，分享结论前脱敏。

把当前症状串成：事件收到 → 范围和触发允许 → 路由正确 → 参数/开关/数据有效 → 本地业务或模型执行 → 媒体与平台发送 → 回执落库。只修复证据指出的断点。后台另外区分开关关闭、预算等待、外部失败、中断 running 和成功完成，不能靠“worker 存活”判定业务正常。

## 常见断点及最小修复

| 症状 | 先核对 | 当前流程要求 |
| --- | --- | --- |
| 控制台能开但 QQ 不回复 | OneBot connected、群列表同步、mode、群/私聊范围、真实 @、呼叫与独立开关 | 无呼叫群消息不强行开放；已离群目标不重新启用；同步失败留在后台，不阻塞私聊 |
| 服务意外退出未恢复，或停止后重新启动 | 守护总开关、`data/supervisor.db` 期望状态、计划任务触发、归属/开关/退避与事件 | 显式停止先保存关闭意图；直接结束进程按意外退出处理；断线不自动杀活进程，不据历史记录开启功能 |
| 业务已迁入却无作用 | native key 与业务表、实际入口及调度、旧默认值映射 | 表数量不能证明接线；生产仅补缺失字段，保留显式空/false/0 与新设置 |
| 本地工具触发模型或分析 | Runtime 路由、组合请求和 ChatService 调用 | 纯工具模型尝试为零；工具技术失败保留后台证据，不转成额外分析请求 |
| 游戏没回复或重复回复 | 主连接、route identity、receive-only 连接、完整原文、消息去重和媒体 | 主连接唯一发送；兼容连接只收订阅；不修改上游、不重复执行生产命令试错 |
| 模型超时或 SSE 错误 | 实际 URL/API 格式、TLS、连接/读取超时、流完整性、容量、错误与 usage | 查看请求 `telemetry.model_diagnostics` 的返回标识与结构化错误；缺失 usage 保持未知。根据具体原因修复本目录；保留 Windows 证书验证，不盲目切模型/放大窗口或自动重试收费请求 |
| usage、缓存或费用失真 | 供应商原字段、渠道语义、最终 SSE 样本、价格版本与币种 | 缺项未知；不填零、不重复累计，不将单次命中说成总体优化 |
| QQ 正文后泄露协议 JSON | 原始生成内容、parse_reply、reply_metadata 与最终发送记录 | 仅正文与末尾完整协议的 messages 一致时恢复同一协议对象；不在 OneBot/通用文本层删花括号，不扫描 messages 内用户代码，不重写原始模型日志 |
| 图片未进入模型输入 | 原始 image 段、vision、媒体 failures、actual payload 的 input_image 与 assets | 检查下载前 DNS 校验，精确 QQ 图片 HTTPS 域名可兼容代理 Fake-IP；其他非公网来源继续拒绝。GIF 首帧转换仅在新图片入库时进行；失败记录脱敏具体原因，未发送图片不能视为模型不支持视觉 |
| 群聊内容搜索没有执行 | route 的 group_chat_search、当前群 speech_archive 开关、存档范围和工具记录 | #群聊搜索 关键词 [页码] 或呼叫后说“找一下群里的关键词”；只读当前群已存档文本、排除查询消息和过滤名单，不猜群成员身份、不调用模型。无匹配与技术失败分别记录 |
| 语音或表情未交付 | 本群开关、候选素材、独立服务 readiness、音频格式、媒体发送 | 进程存活、API 就绪、有效合成和 QQ 回执分别确认；语音失败继续文字 |
| B站登录“成功”但无认证 | 本适配 Cookie/返回 URL、必要字段、凭证有效性 | 缺字段不覆盖旧凭据、不报告成功；扫码由用户执行，公开抓取可用不代表认证有效 |
| 推送轮询更新但没有消息 | 实际订阅、可接收群、角色、群同步、事件游标及持久队列回执 | 无接收群不能吞掉待投递内容；失败不占已送达历史，不重放迁入旧队列 |
| 后台积压或关闭项仍影响聊天 | 队列状态、预算、独立开关、执行后再核对与发布时间 | 保留预算与失败证据；关闭项不发布、不删除历史，也不堵住其他类型任务 |
| 控制台慢刷新或跳群 | SSE 刷新合并、同查询在途请求、会话选择、分页与完整详情加载 | 慢响应仍能显示；换群不混旧数据；列表按需读取大 payload，不伪造历史图表 |
| 在线链接仍指向 localhost | SQLite `web_base_url`、受限网关与现有 Tunnel origin | 只改 Harness 的实际业务配置；完整控制台继续本机使用，不全量重新导入模型配置 |

## 中转错误、路由与原生推理状态

`telemetry.model_diagnostics` 的响应头和响应 ID 均来自当前 HTTP 对端。经中转时，`x-request-id` 和 `resp_...` 的形式不能证明它们是原始供应商 ID；后端/渠道字段未返回时保持未知。本地代理透传请求、响应和 usage 只说明本地没有重算，不能证明中转内部未换账号或缓存节点。

路由问题先用已有自然请求的时间和 `x-request-id` 关联中转记录，再核对真实上游请求 ID、脱敏的稳定账号/渠道/节点标识及重试切换记录。错误概要保持短；诊断中的脱敏 `error.message` 最多保存 4096 字符，超出 16 KiB 的 HTTP 错误正文记录省略状态。没有原始错误时，不用延长本地超时或自动收费重试替代定位。

新生成批次只有在 Responses、非 `none` 推理档位以及档案 `extra_body.include` 明确包含 `reasoning.encrypted_content` 时进入原生输入日志。成功输出先本地归档；只有完整的加密 reasoning 与 assistant message 批次才原样回放。已保存的原生批次在后续思考档位/include 改变时保持原样，不重写冻结历史。未知工具输出、缺少密文或未确认完整的输出保持正文路径；不把人工思考文字当原生状态。具体保存、容量和撤销边界见[上下文缓存主干](../../../docs/上下文缓存主干.md)。本地协议通路可用与中转支持、真实缓存收益分别确认；用户正在观察的配置保持其既有选择。

## 实施与验证

用临时数据库和模拟协议还原用户可观察的失败与修复结果。优先扩展相关现有行为用例，不靠断言某行源代码文本代替功能。验证同入口正常行为、必要的相邻失败路径和“没有额外模型调用/重复投递”等实际约束。

技术失败只写后台记录与控制台；参数澄清、正常业务状态及必要人工操作提示仍可发。不要为了让 QQ “有回复”把内部异常公开或伪造已完成结果。

运行 H 的行为测试与前端构建。若外层旧测试或校验失败，记录具体失败和当前差异，不称全部通过，不改旧框架来掩盖 Harness 任务外的既存问题。提交须满足外层必需校验。

需要加载代码且已有部署授权时按[维护流程](maintenance.md)仅重启 Harness，随后核对新 PID、端口、连接、队列和相应只读接口。不要用一次重启代替定位根因。没有生产操作授权时先交付可审阅补丁和本地结果。

保留原失败历史、usage 与请求记录，修复不改写为成功。现场证据写入 ignored 的 `runtime/verification`；文档解释修复后行为与实机限制，不把当次模型、开关或失败测试名称写成永久规则。
