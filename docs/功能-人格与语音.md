# 人格与语音

同一 QQ 账号按群选择糖糖或达妮娅，默认糖糖。人格、聊天模型和声线分别配置，沿用现有呼叫、主动接话、费用总控和群开关。

聊天调度每群最多一条运行任务，明确呼叫最多再等待两条，按接收顺序处理；主动接话不排队，群内已有任务或等待呼叫时跳过。不同群可独立处理，全局最多 32 个活跃群。队列满、重复消息、停机和上下文失效都有原因日志；排队请求开始前复核冻结的人格与配置，切换后旧请求不执行。排队不绕过原有去重、呼叫忽略或费用开关。

## 受限续聊与短句合并

成功送达聊天回复后，本群会为刚才交谈的用户打开续聊窗口；他可不再重复呼叫词或 @。窗口只属于同一群、同一人格、同一用户，不接管全群消息。默认最后一次成功回复后空闲 120 秒结束，总长最多 600 秒，最多自动尝试 4 次，连续两次模型沉默也结束。自动回复仅刷新空闲时间，不重置总时长或次数；再次明确呼叫可开启新的窗口。

自动续聊每天最多每群 20 次、全局 80 次，两个人格共用且重启不清零；每次实际进入模型前记一次尝试，失败和沉默也计入。自动续聊同时遵守呼叫聊天、主动聊天的全局总控和本群开关，也遵守暂停、黑名单、去重、人格冻结及共用调度。关闭主动聊天仍可明确呼叫，但不再免 @ 自动续聊。

同一个用户连续补充的短消息等待 1.5 秒合并，最长从首条起等待 3 秒，每批最多 8 条、8,000 字符；不会等待其他用户的消息。初始明确呼叫的补充也能合并，不增加模型机会。所有合并消息 ID 原子去重，来源记录保留全部 ID。缓冲在后台完成，不阻塞排行、游戏等其他命令。自动续聊不接命令、向其他人的 @ 或引用、陈旧消息和其他用户的插话；这些消息仍按原有功能处理。

已处理或正在处理的重复消息在合并前排除，避免重放旧消息时连带吞掉新补充。续聊中的确定性本地功能请求仍走原功能入口，不消耗续聊模型次数；普通续聊只在共用额度准入后调用聊天模型。

续聊窗口、合并缓冲或已接纳请求存在时协调暂停该群的主动插话尝试，避免同时开口；现有热度、日帽、随机时钟和低流量群参数不变。人格切换、相关开关关闭、断连或停机使旧请求失效，迟到语音也不发送。窗口本身不跨群、不跨重启保存。

每轮同时冻结全局和本群聊天开关版本；关闭再开启不会恢复关闭前的旧请求，其他群的开关变化不影响本群。版本持久化在主数据库，初始化保留原有群设置。

本地超管通过 `scripts/persona_settings.py --set <键> <值>` 调整：`continuation_enabled`（0/1）、`continuation_idle_seconds`、`continuation_hard_seconds`、`continuation_max_attempts`、`continuation_silence_limit`、`continuation_group_daily_limit`、`continuation_global_daily_limit`、`continuation_debounce_seconds` 和 `continuation_max_debounce_seconds`。初始值不覆盖已经保存的设置。

每个排队请求独立保存 NoneBot 事件、机器人及发送节奏上下文；执行时恢复该请求自己的上下文，避免沿用首条消息造成回复对象或过期判定错误。队列容量是明确的接纳上限：同群同时超过三条时，超出部分会被拒绝并记入日志，不承诺所有突发呼叫都获得回复。

`logs/bot.out.log` 的 `Chat trace` 记录接收、入队、开始、结束或丢弃。`data/tangtang/usage` 的模型结果及发送记录携带相同 `request_id`（群号:原消息 ID）和 `message_id`；额外诊断事件不重复累计 token。失败记录异常类型，发送成功记录平台消息 ID。

糖糖响应“糖糖”或真实 @；达妮娅响应“娅娅”或真实 @。“达妮娅”不是呼叫词，适配器的 `to_me` 标记本身也不算 @。叫错名字按普通群聊处理，仍可能符合主动接话条件。切换时公告，日常不加角色前缀。

首版不提供临时点名切换、个人专属人格或私聊陪聊。达妮娅按初识开始，不继承糖糖关系。可完整讨论剧情，日常不反复解释虚质设定。

普通文字回复的表情候选以 60% 概率进入本地抽选，并非每条回复都有 60% 概率带表情。明确呼叫“娅娅，发个表情包”跳过呼叫忽略和 60% 门槛，在友善微笑中选择；“发个开心表情”按类别选择，“发个手动微笑表情”或“发个expr_026表情”按名称或 ID 点播。点播仍受群开关、资源和消息去重限制。明确要求不要表情时不发送；语音与沉默不附图。确定附图后，一律与第一条文字合成同一条 QQ 消息，不单独补发图片；合并消息失败或送达不明时不补图。语音与沉默仍不附图。

角色图支持 GIF、WebP、PNG、JPG 和 JPEG；优先读取目录登记的文件，未登记文件名的兼容资源按上述扩展名顺序查找。文件放在 `bot/resources/personas/denia/expressions/`，发送原文件，不截图、不取首帧、不转为 JPG；动画最终显示效果由 QQ 客户端及 OneBot 实现决定。更新资源或语义目录后重启 NoneBot，以重新冻结资源版本；保留来源、版本和授权说明。仅放入陌生文件名不会自动登记。

正式目录只保留登记使用的 51 个图片文件；旧中文文件名的重复副本已清理。中文名称与别名由语义目录映射到正式文件，点播不依赖同名中文图片副本。

`expression_catalog.json` 保存 51 张图的逐图视觉观察、中文名称及别名、画面文字、情绪解释、主观强度、适用/避用场景、语义组、文件哈希和 GIF 已查看帧号。标注由维护助手直接查看图像及关键帧后完成，不按文件名生成，不增加人工审批阶段；情绪解释允许后续修订，没有伪造数值置信度。目录版本随人格资源哈希冻结；完整元数据启动时同步 SQLite 的 `expression_metadata`，基本中文名称兼容保存在 `expression_catalog`。聊天只传文字目录，不读取图片上传给聊天模型。带“杂鱼”文字的图只允许明确点播，不能作为普通微笑替代项。

新增表情可参与普通语义候选，也可按下表中的名称、别名或 ID 明确点播，例如“娅娅，发个脸红嘟嘴表情”。语义组是聊天模型选择时的参考，不是固定关键词触发器；下表别名是这张图的准确点播名称。

| ID / 文件 | 匹配类型 / 主观强度 | 点播别名 | 适用与避免 |
| --- | --- | --- | --- |
| `expr_050` / `脸红嘟嘴.gif` | `pout`：羞恼、轻微不满、闹别扭；0.55 | 脸红嘟嘴、羞恼嘟嘴、羞恼、小脾气 | 被轻松打趣后嘟嘴或有点不服气；不用在真实争执、严肃投诉和悲伤求助，不自动解释为恋爱示好。 |
| `expr_051` / `歪头疑惑.jpg` | `skeptical`：疑惑、不解、轻度质疑；0.35 | 歪头疑惑、歪头问号、疑惑、问号、不解 | 没听懂、温和追问或对奇怪说法表示疑问；不嘲弄理解能力、不质疑真实痛苦，问号不能代替事实解释。 |

模型输出 `expression` 首选 ID 和 `expression_candidates` 最多三个替代 ID；语义组仅供参考，替代项允许跨组轻松联想、接梗或呼应气氛，不要求与正文逐字对应，但仍须遵守避用场景，不用嘲讽图回应真实痛苦或严肃求助。目录每轮随机排列，消除固定位置优先。程序验证允许 ID、资源与明确点播限制，只在模型给定的合适候选中抽选，不为了凑数自动扩展到整个情绪类别。普通抽选和类别点播排除本群、本人格近 24 小时最后两次成功发送的图片，余下候选的权重为 `1 / (1 + 近24小时成功次数 / 3)`；全部被排除时不附图。准确点播某个唯一 ID 或名称可重复发送。各群、各人格的计数隔离，成功回执才增加计数，重启不丢失。

`expression_events` 按请求记录候选、最终 ID、概率值、排除原因、权重、目录版本和平台消息 ID。状态区分 `skipped`、`selected`、`sending`、`delivered`、`failed`、`uncertain`、`cancelled`；无回执或网络异常不计成功、不自动重发。中断后遗留的 `sending` 也是未确认状态。人格切换、功能关闭和请求失效后不继续发送。离线只读查看当天排名：`.\.venv\Scripts\python.exe -X utf8 scripts/report_expressions.py`，可加 `--day YYYY-MM-DD`、`--group 群号`。导入的旧平台回执只有成功次数，没有当时的候选决策，不可据此推测未选原因。

## 记忆与成长

达妮娅 v2 使用同一人格库保存跨群连续的个人认识与自身经历，通过本地迁移脚本启用。糖糖沿用原流程。v2 的事实、开放印象、双方关系、可学习观点和待办均按人格＋QQ 用户延续；只有原始对话上下文限当前群。群号是来源，不是个人档案分区。

消息在 NoneBot 预处理阶段与持久入口一起入库，冻结接收时的人格和资源版本，不在事件入口调用模型。直接交流与本人日常群发言都可整理，旁观推断权重较低；同一消息从旁观升级为直接交流不重复计证据。聊天回复之前提交有证据的记忆，因此沉默、发送失败和停机不会抹去已采用的信息。命令、机器人自身消息、过期消息和现有观察范围以外的群不采集到 v2。

主要印象是可修订的自然语言，带适用条件、支持/反对证据和版本。事实保存一人称原话并标为自述，不宣称核实。短期状态绑定具体用户和原因、限制强度并随时间衰减；不会将对某个人的不满传播给其他人。核心身份及剧情资源不进入学习写入。人格自述和用户摘要均不充当独立证据。

跨群意图由人格库预留；同一事项不能在两群同时追问。“先不聊”变为暂缓，保留原记录。发送成功后只进入等待结果，时间过去不等于完成。发送按段保存实际回执；无回执、超时或发送中崩溃记为不确定，不自动重发。只有确认送达的部分形成实际行动经历和曝光记录，曝光不表示用户已阅读。明确引用已发送消息的反馈有独立关联记录。

个人整理 worker 与话题刷新、旧公共成长分开运行，每两秒检查一次；同用户最多一批，按轮次和等待年龄轮转，合批最多 12 条、约 12,000 字符。前台正在整理的来源先预留，失败后交还后台。此 worker 不使用旧公共成长的每日额度。模型端点默认最多四个并发请求，其中后台最多一个，前台优先；后台调用有 40 秒超时和持久故障退避。容量不足表现为可检查的积压，不承诺任意流量下固定延迟。关闭后台总开关保留队列。

技术落点为 `persona_inbox.py`、`persona_cognition.py`、`persona_actions.py`、`persona_turn.py` 和独立 worker。认识条目复用 `person_semantic_memory` 与版本表；新增来源、支持/反证、状态因素、经历、意图及动作表。后台先提交目标库处理回执再确认来源，租约代次防止旧 worker 覆盖新处理。发送前只检查实际依赖条目版本及现有人格/功能开关，无关用户更新不会取消当前回复。中文精确片段和主题检索覆盖该用户的全部有效条目，另保留近期认识基线，不依赖外部 embedding 服务。

```powershell
.\.venv\Scripts\python.exe scripts/migrate_persona_v2.py --report reports/persona-v2-preview.json
# 暂停 watchdog 并停止 NoneBot 后，选一个尚不存在的备份目录：
.\.venv\Scripts\python.exe scripts/migrate_persona_v2.py --apply --backup-dir data/backups/persona-v2-pre-migration
.\.venv\Scripts\python.exe scripts/report_persona_memory.py
.\.venv\Scripts\python.exe scripts/evaluate_persona_memory.py --env .env
```

默认迁移仅在临时副本演练；正式迁移先备份三个相关 SQLite 文件、验证完整性与恢复副本，再接纳旧资料、已有印象和有证据的公共观点，最后写入启用标记。旧表、旧版本及停用/删除状态保留，重复迁移不重复累加。v2 启用后旧达妮娅公共成长写入停止；旧成长列表仅为历史资料，不再是 v2 当前观点的权威来源。现有旧成长停用/回退命令不修改 v2 私人认识。

快速停止 v2 可执行 `scripts/persona_settings.py --set denia_v2_enabled 0`，保留新增证据；恢复启用仍走迁移检查。完整回退须先暂停写入，另外保存迁移后的库，然后从此次备份恢复三个文件并切回相应源码版本；切勿在运行中覆盖 SQLite 或丢弃迁移后的新资料。旧版数据迁移工具不用于回滚 v2。诊断脚本只读汇总队列、延迟 P50/P95、拒绝项、模型用量、意图与动作状态，不输出私聊档案。

离线评测使用合成人物和群，覆盖旁观、跨群延续、否定纠正、第三人转述、暂停话题、真实结果和身份诱导；模型输出与最终采用结果保存在忽略的报告目录。格式通过不能代替对归属、自然度和事实含义的检查。

`scripts/replay_persona_runtime.py --env .env` 使用实际聊天服务、模型、后台和本地模拟回执跑完整时间线，所有人物及数据均为合成样例，不连接 QQ 发送接口。格式或证据失败只修复一次回复，拒绝的学习项继续由后台整理；后台部分成功也不将失败项伪记为完成。修复故障后可先运行 `scripts/replay_persona_observations.py --limit 100` 查看隔离任务数量，再加 `--apply` 重新排队；证据不删除、不重复累计。

以下为未启用 v2 时的兼容行为及旧迁移工具说明；其中成功送达后提取、固定印象维度和公共成长门槛不用于 v2：

糖糖原历史库继续使用，达妮娅历史位于本地 `data/personas/denia-history.db`；选择、公共成长、预算和送达记录位于 `data/personas/state.db`。同一人格按 QQ 账号跨群认识用户，共享稳定个人资料、熟悉程度和对该用户的短时情绪；不同人格仍独立。群内正在讨论的话题和当前氛围保留本群范围，达妮娅个人称呼与约定不按群分档。公共成长列表不显示私人记忆。

达妮娅个人记忆以人格＋QQ 用户为唯一主体：资料、称呼、职业、偏好、经历、约定、交流印象均跨群共享。来源群只保留取证用途；只有聊天上下文、当前话题和未完成问题按群隔离。旧的按群保存的有效个人资料直接按全局范围召回，不搬迁、合并或删除原记录。普通相关历史检索仍仅返回本群至多两条互动片段；跨群认人只提取本人自述，不能把原聊天话题带入当前群，也不把自述当成核实事实。糖糖保留原有的本群限定个人资料规则。

达妮娅不接受聊天中的遗忘、删除、清空、限制本群召回或恢复资料请求；这些请求走本地说明，不调用模型、不修改记录，也不允许模型通过结构化结果执行删除。用户可说“娅娅，查看我的印象”或使用上述指令查看本人印象，也可明确纠正个人自述。历史版本和已有的停用、删除状态保留，不自动复活旧记录。糖糖继续使用原有遗忘/恢复规则。

稳定观点及通用表达允许跨群成长，专有表达留在本群。`#人格 成长 列表` 标记跨群/本群条目；群管理员停用跨群条目仅屏蔽本群。超级管理员可用 `#人格 成长 全局 列表`、`#人格 成长 全局 停用 <编号>`、`#人格 成长 全局 回退 <编号> <版本>` 管理共享条目。管理员不能用这些公共成长命令修改私人资料。

迁移先执行 `python scripts/migrate_persona_memory.py` 只读预览，停止 NoneBot 后以 `--mode apply` 备份并增量迁移。旧表保留，重复执行不重复累加；初始熟悉度取同用户各群最大值，初始态度取最近记录，个人临时情绪从中性开始。`--mode rollback` 退回群内资料读取，`--mode enable` 恢复共享读取；两者保留新增资料和遗忘限制。旧群成长不批量升为全局。运行时数据及备份不提交。

只有成功送达的互动提供成长证据，旁观群聊只作临时上下文。达妮娅每轮聊天可同时提出一条公共表达成长，引用本条原文即可立即校验、保存，无跨日门槛，也不占额外后台模型调用；新条目全局共享。糖糖后台仍要求两个自然日、三次不同互动的证据。稳定身份、剧情事实和核心性格不自动修改，私人资料和个人印象不能写入公共成长；旧历史不批量重解释。停用项不会被自动启用，回退产生新版本。

情绪变化有界，偏离平静的程度每六小时衰减一半。关系保持群友式熟悉，不自动形成恋爱或排他关系。成长通过表达自然体现，不播报等级变化。

## 语音行为

TTS 只转换确定的文字并发送。达妮娅绑定 `villia/dania` v2ProPlus 声线；糖糖暂不绑定。以后指定糖糖自己的模型、参考音频和台词即可使用同一接口，不覆盖管理员已关闭的开关。

优先级：沉默 → 能力与开关检查 → 用户明确要求文字 → 用户主动要语音时由人格决定 → 普通回复随机尝试。拒绝语音后禁止随机覆盖。语音回复只有一条录音，不附同文文字或角色表情；代码、链接、表格及过长内容使用文字。

默认随机概率 10%，同群随机间隔至少 10 分钟；主动点播不受这两项限制，但仍可被人格拒绝。本地 TTS 不设每群或全局每日次数额度，旧语音额度设置和计数不再限制合成。随机概率与间隔通过本地管理工具调整。

明确请求语音（例如“娅娅用语音跟我说句话”）跳过呼叫的随机忽略，由人格决定是否答应；仍遵守沉默、去重、聊天模型费用总控，以及合成队列和超时限制，不保证每次都发语音。用量日志中的 `voice_decision` 记录可用状态及发送形式，`voice_result` 记录合成发送结果；普通呼叫的随机忽略标注 `call_ignore_probability`。

例如：`.\.venv\Scripts\python.exe scripts/persona_settings.py --set speech_probability 0.1`。不带参数查看可调项与当前值。声线文件更新由后台重新校验加载，任何已关闭的群开关保持不变。

排队和合成统一最多 30 秒，单并发、最多两项等待；后台负责启动和健康检查，聊天不等待冷启动。随机语音失败回退文字，接受点播后失败会简短说明。QQ 送达不明时记录为不确定，不重试或补发。成功送达的转写才进入历史；人格切换后的迟到语音不发送。

接口可访问后还需后台实际试合成并校验音频，完成前保持“准备中”。预热使用同一个合成工作槽，不发送消息、不记录互动。预热失败后至少等待 60 秒再重试；超时后仍在执行的任务继续占用槽位，迟到结果不能把状态改为可用。服务失联、关闭语音或更换声线会使相应就绪状态失效。

## Windows 本地运维

机器人保持 Python 3.13，TTS 使用独立 Python 3.10 CPU 环境。上游、声线和前置模型校验值见 [语音锁文件](../config/speech-upstream-lock.json)，直接依赖见 [语音依赖](../config/speech-requirements.txt)，完整版本锁见 [CPU 环境锁](../config/speech-requirements.lock.txt)。

默认目录：`downloads/GPT-SoVITS-cpu` 为原始上游源，`data/tts` 为运行时、模型、配置和日志，`data/personas/voices.json` 为本地声线档案。所有这些本机数据均不进入公开源码。准备声线权重、参考音频与台词，以及上游要求的 BERT、HuBERT、G2PW、语言识别和说话人编码器。

声线条目可保存合成参数：`language`（待念文本语言）、`prompt_language`（参考台词语言）、`speed`、`top_k`、`top_p`、`temperature`、`text_split_method`、`fragment_interval`、`seed`、`repetition_penalty` 和 `batch_size`。机器人逐项传给本机接口；全部参数计入音频缓存版本，修改后重启 NoneBot 即可生效，不会命中旧参数的缓存。重新运行声线绑定脚本保留同一声线已保存的调参值。未配置的新字段沿用原接口默认值。

纯中文慢速试听起点为 `language=all_zh`、`prompt_language=zh`、`speed=0.85`、`top_k=15`、`top_p=0.8`、`temperature=0.7`、`text_split_method=cut0`、`fragment_interval=0.45`、`seed=42`、`repetition_penalty=1.35`、`batch_size=1`。这是可选的声线配置，不强制覆盖其他声线。`cut0` 不主动切段，适合短回复；固定种子便于比较，段尾间隔只增加留白，不补回漏字。混合英文或长文本需要另行试听。接口 `/docs` 的单次调参不会自动保存到声线档案。

```powershell
.\.venv\Scripts\python.exe scripts/install_speech.py
.\.venv\Scripts\python.exe scripts/install_speech.py --verify
.\.venv\Scripts\python.exe scripts/configure_speech.py
.\scripts\start_speech.ps1
.\.venv\Scripts\python.exe scripts/probe_speech.py
.\.venv\Scripts\python.exe scripts/probe_speech.py --readiness-only
```

配置脚本支持自定义模型及 `--persona tangtang`，不改聊天模型或 `.env`。NoneBot 的语音后台负责有限重试。总开关关闭后禁止后续发送，不强杀底层合成。验收脚本只生成本地 WAV 和耗时报告，不发 QQ 消息；性能不达标时暂停语音上线，不自动改用云服务或其他操作系统。

安装器需要 PATH 中已有 ffmpeg；默认只补齐缺失文件，发现已有文件与锁定校验值不同会停止，不覆盖。`--verify` 只读核验源码和模型。g2pW 发音缓存通过进程内兼容层写入 `data/tts/g2pw-cache`，不写回上游文件。糖糖绑定必须显式传入声线 ID、两个权重、参考音频及台词，避免误用达妮娅默认值。

维护时先关闭语音总开关，再执行 `scripts/stop_speech.ps1` 停止独立服务，避免后台自动拉起。不要停止 QQ 或 SnowLuma。

专用快捷入口为 [启动语音](../启动工具/12-启动语音.bat) 和 [关闭语音](../启动工具/13-关闭语音.bat)。启动入口显式开启总开关，关闭入口先关闭总开关再停止模型进程（包括 Windows Python 启动器的子进程），均保留各群设置。日常启动全部会一起启动已配置且开启的语音服务；关闭全部只停进程，保留开关，下次恢复。关闭过的总开关不会被日常启动覆盖。

语音健康检查独立于话题与成长整理，每 10 秒执行；异常退出后后台以至少 120 秒间隔尝试拉起，实际预热成功才可用。`data/tts/readiness.json` 记录最近检查时间、进程与就绪状态，仅为本机诊断信息，过期记录不代表当前健康。模型会常驻内存，点击关闭语音可释放资源。语音故障只使聊天回退文字，不阻塞其他功能启动。

主动要求语音仍需要先取得聊天模型的有效回答和同意。聊天模型超时不会进入合成，也不等于人格拒绝或语音故障；可通过聊天用量日志、语音送达记录和就绪状态区分。

## 记忆质量与成长诊断

### 达妮娅的逐轮存储与召回实现

- 继续使用 `denia-history.db`，不引入第二套记忆库。`PersonaEngine.memory()` 为达妮娅启用全局个人策略；新个人资料写 `scope_group=0`，旧有效记录跨来源群读取，糖糖采用原策略。没有自动按时间删除记忆。
- 主聊天一次生成可包含 `memory_updates`（最多3项）、`impression_updates`（最多2项）、`growth_updates`（最多1项）。只有明确记住/纠正请求在发送前保存以提供真实回执；自动资料、印象与公共成长都在 QQ 成功回执后各自提交，单项故障不阻塞其他提交。不新增每条消息的后台模型调用，但这些结构化字段会增加本轮输出 token。
- `person_impression_events` 按用户、来源消息和交流维度去重，存原话引用、方向、来源群和时间。六个交流维度为追问细节、轻松打趣、直接表达、体谅、创作、持续推进；它们是可修正的交流观察，不是人格诊断或用户身份。每次提议要求当前本人原文4至160字的连续引用，转述、敏感资料、要求机器人给自己贴标签、未提供证据的提议不入库。
- 印象读取最近96条事件，各维度最多取最近8条，按从新到旧 `1, 0.5, 0.25, ...` 加权支持/反对方向；得分大于0.2才呈现为当前倾向。按互动事件衰减，不按天等待；旧证据保留，一次新的相反观察就能改变当前倾向。数值不向群里播报。
- 每轮提示词优先提供相关个人记忆，再补最多4条基础资料和当前交流印象；群聊历史仍只查询当前群。个人资料检索目前是字词与受控主题扩展，不声称已实现通用向量语义检索。印象查询直接读取本人记录，无额外推理请求。
- 达妮娅公共表达成长复用本轮 `growth_updates`，校验当前互动原文引用后立即保存并标记已处理，不经过跨日证据、五条批次、六小时间隔或后台整理额度。后台旧证据整理及糖糖仍使用下述原有预算规则，不能把它们的调度周期解释成达妮娅当前个人记忆或印象的更新时间。

个人事实采用保守提取，只收明确的自我称呼、稳定偏好等完整陈述；问题、残句、引用、角色扮演、修改机器人身份的要求及“我喜欢你”等关系表达不写入个人事实。关系表达仍按原关系机制更新。明确“记住”也要通过质量检查；含多个分句或含义不明确的内容暂不自动提取。旧记录保留，召回时应用同一质量过滤，不把用户自述标为已核实事实。

主聊天模型现在可在结构化回复中同时提议最多三条个人记忆，分类为称呼、自述身份、偏好、个人重要经历和本人约定。模型负责从语义中选择独立、完整的本人陈述，并选择受控主题标签；程序要求每条有当前用户本条原文的精确引用，摘要为其中连续摘录，不能补出隐含日期、身份或承诺。旧保守提取器仅在模型未提供候选时兜底，不绕过候选校验。此功能复用本轮聊天调用，不增加后台模型调用或另建成长系统。

明确要求记住或纠正时，先检查并持久化，再以程序生成的实际回执确认；保存、部分保存、待确认、拒绝、失败和关闭分别说明。模型自行生成的保存承诺不直接发送，文字、语音及回退使用同一结果。明确保存请求不受呼叫随机忽略，但仍受费用总控、权限边界与过滤限制。达妮娅普通聊天中的合格自述只需一次成功送达即可成为有效长期记忆，糖糖稳定资料仍需两次。没有 QQ 回执不产生自动个人记忆、印象或公共成长；消息重放不重复计证据。

“以后叫我小林”属于明确称呼保存；“我现在喜欢什么”“你还记得吗”属于回忆问题。允许再次更正回原内容，但旧消息重放不能恢复过时版本。达妮娅旧记录的来源字段保留，更正后仍按用户全局召回；糖糖更正继承原范围。候选标签不能把稳定偏好伪装成单次经历绕过其证据规则，也不能从否定、转述中截取相反意思。

明确保存的送达回调只确认已完成的写入，不会在告知保存失败后偷偷重试。记忆回执不能改变本轮原有语音拒绝或消除语音行为冲突。送达后的历史、成长、个人记忆与关系分别记录，单项故障不会阻断其他项目；未提取到个人资料时记录明确原因。

新增个人摘要保存在各人格历史库的 `person_semantic_memory`、`person_semantic_versions`、`person_semantic_evidence`，记录用户、范围、类别、原文引用、来源群、消息 ID、时间和版本；`person_memory_write_reviews` 记录保存状态和拒绝原因。纠正必须引用当前用户可见的旧记忆 ID，旧版本保留且不再按当前事实召回；私人记忆不进入公共成长列表。默认跨群共享本人资料与经历，但不会把来源群的讨论作为另一个群的对话上下文。召回同时使用字词和受控主题语义扩展，例如“创作经历”可以找到“参加绘画展”；不是任意主题的向量搜索。日期随记忆提供，“下周”等相对时间以原话时间理解，约定不等于已经履行，也不代表机器人有定时提醒能力。

成长每批仍需五次新送达互动，先在本人格最近 500 条送达证据中按主题字词匹配，优先选择跨日证据，最多送入 12 条；不同群的专有用语及私人资料不作为共享证据。证据不足时只记录诊断，不调用模型、不计模型额度；本批标记已检查但原始证据保留，后续相关互动仍可检索它们。词面检索不是完整语义检索，可能漏掉完全不同措辞的同主题内容。

`#人格 成长 诊断` 由超管查看当前人格、本群最近五次结果；`#人格 成长 全局 诊断` 查看当前人格各群最近结果。输出不含私人原文。可区分证据不足、模型空提议、引用无效、身份或隐私限制、旧证据、停用条目及服务故障。SQLite 的 `growth_reviews` 保留候选证据编号和每条提议的决策原因；旧任务无法补推拒绝原因。

模型调用上限仍为全局每日 12 次、每群 2 次（两人格共用），按本地时间 00/06/12/18 点累计释放 3/6/9/12 次，未用额度当天可后移，不结转次日。自定义全局上限也按四个时段比例释放。同群两次模型尝试至少间隔六小时，包括失败尝试；间隔和公平排序读取持久化记录，重启不重置。今天已经消耗的额度不清零。

成长后台接口故障采用跨群共用、持久化的重试退避：临时 HTTP、网络或超时错误从 5 分钟增加至最多 6 小时；配置、权限及服务额度错误等待配置变更或 24 小时复检。每次实际重试仍通过上述每日额度和六小时间隔，失败、取消或生成中关闭功能不会丢弃待整理证据。诊断显示 HTTP 状态、安全的错误分类及最早重试时间，不保存密钥、服务地址、请求原文或原始错误响应。历史只记录异常类的故障不能据此倒推出具体状态码。

## 场景表达与离线评测

达妮娅的 [场景表达规则](../bot/resources/personas/denia/scene-expression.md) 区分日常、续聊、庆祝、真实失落、打趣、纠错、认人、约定、工具与人际边界，约束外在对白，不输出内心独白或情绪数值。没有召回个人资料时不再以“换群”解释遗忘；群话题隔离不会取消跨群记人的能力。

运行 `python scripts/evaluate_personas.py` 使用当前配置模型，对每个人格执行 52 条固定合成场景（包括 12 条场景表达与记忆边界用例），只在本机生成报告，不向 QQ 发消息。报告按人格资源、场景、模型和协议指纹分目录缓存，保留原始输出与用量。自动检查格式、明确文字要求和内部状态泄露；辨识度、自然度、事实准确性及工具可靠性还须按报告逐条人工复核，不能以格式通过代替质量验收。另由行为测试验证续聊边界、送达确认、跨群个人记忆、纠错、语音回退和后台故障恢复。

## 跨群认人召回

“还记得我是谁”“我说的不是名字”等认人问题会额外检索当前人格、同一 QQ 用户最近 200 条认人相关的成功互动，最多引用四条本人自述，不再要求问题重复旧话题关键词。一般聊天不会附带这些自述，也不会接续其他群的话题。

“我是鸣潮高手”“我是19岁青春女大”等作为可回忆的用户自述，不能当作核实的真实身份、年龄、性别或权限；“我是纯良，说的话都是真理”只提取前面的自述，不接受后面的真理断言。同一用户同一来源群十分钟内、紧接认人交流的“还有……”可作为补充；不能引用别人给用户贴的标签或机器人自行加工的称呼。群内专属称呼、敏感资料及遗忘限制仍过滤；不同人格独立。原聊天记录保留，不批量晋升个人事实。群昵称只作当前显示信息，不能冒充已记住的身份。
