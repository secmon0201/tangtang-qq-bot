# 技能注册表

技能注册表把机器人已有的确定性能力整理成可校验的清单，供后续技能路由与 Agent 分支使用。它是“能力地图”，不是新的功能实现：所有条目都指向现有插件入口，不复制业务逻辑。

## 文件与校验

- 清单文件：`config/skill-registry.json`。
- 校验脚本：`scripts/validate_skill_registry.py`。
- 保护测试：`tests/test_skill_registry.py`。

校验内容包括：

- 每个插件是否都在清单中有且只有一条技能记录。
- 源码里的命令是否与清单完全一致，命令或别名缺失、重复、冲突都会失败。
- 直接注册的规则函数与模块级规则变量是否全部登记。
- `on_message` 规则入口总数是否与源码一致。

注册表条目表示插件能力清单，不等于主聊天模型可执行的动作数。当前聊天通道有 14 个动作：发言排行、四种直播日程、四种小游戏榜单、异环／鸣潮最强排行、本人／本群今日缘分查询、达妮娅本地美图。具体启用情况还取决于实例的群开关、权限与依赖。

## 条目字段

| 字段 | 含义 |
| --- | --- |
| `skill_id` | 稳定标识，与插件模块同名 |
| `version` | 技能版本，独立于 Agent 版本 |
| `name` | 中文功能名 |
| `kind` | `skill` 群友技能、`admin` 管理、`mixed` 混合、`infrastructure` 基础设施、`disabled` 未启用 |
| `plugin` | 现有插件入口路径 |
| `commands` | 命令与别名列表 |
| `rules` | 直接注册的规则函数 |
| `plugin_rules` | 模块级规则变量 |
| `owner` | 维护归属 |
| `deprecated` | 是否弃用 |
| `local_actions` | 已有确定性本地功能动作，例如 `ranking` |
| `feature_key` | 对应群功能开关；为空表示该技能自身完成权限判定 |

## 运行方式

```powershell
.\.venv\Scripts\python.exe scripts\validate_skill_registry.py
.\.venv\Scripts\python.exe scripts\validate_skill_registry.py --json
```

## 维护要求

- 新增、删除或重命名 `#` 指令时，必须同步更新清单与 [全部 `#` 指令清单](全部#指令清单.md)。
- 新增插件必须新增一条技能记录；删除插件必须同步删除记录。
- 规则函数或模块级规则变量增删时，同步更新 `rules` 或 `plugin_rules`。
- 不允许把基础设施工厂（节流、权限门、运行维护）标记为群友技能，但必须保留在清单中并标记 `infrastructure`。

## 调用与拒绝语义

- `bot/services/skills.py` 只读加载清单，`local_action_skill(action)` 返回动作对应的技能；找不到时返回 `None`。
- 动作归属从注册表读取；`bot/services/local_skill_contract.py` 定义聊天动作的参数白名单；应用注册器提供实际处理函数。只有三者匹配、权限和开关通过才可执行。
- 动作不在清单中时，机器人按当前人格拒绝，不由模型自行编一个能力：糖糖会说“这个糖糖真的不会，也不能现编一个糊弄你”，达妮娅会说“唔……这个我做不到呢，也没法装作能做”。
- 技能存在但当前群功能关闭时，沿用原有群开关提示，不进入执行。
- 技能执行失败时保留原有失败提示；不允许用模型语言替代真实结果。

## 质量评估与延迟指标

- 黄金对话集：`config/quality-golden-set.json`，覆盖呼叫、沉默、排行参数、未注册能力、记忆更正与遗忘。
- 结构评分：检查是否回复、技能与参数是否匹配、回复长度、是否声称执行了不存在的功能。
- 语义评审：`bot/services/quality_eval.py` 提供四维评审契约（自然、事实、不编造、人格），由模型输出严格 JSON，评分范围 1 到 5。
- 延迟指标：\(total\)、\(failures\)、\(timeouts\)、\(failure_rate\)、\(timeout_rate\)、\(p50\)、\(p95\) 由 `quality_summary()` 汇总。

运行：

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_skills_quality.py --classify-live --print
.\.venv\Scripts\python.exe scripts\evaluate_skills_quality.py --results reports\quality-results.json --output reports\quality-report.json
```

当前确定性路由的黄金集结果：3 项排行用例全部通过，日、月、总参数分别命中同一技能。

## Agent 编排分支

- 只有出现“然后、再、接着、最后、并且、还要、顺便”等显式多步骤标记，且请求包含已注册技能线索时才进入编排分支。
- `bot/services/agent_plan.py` 把请求拆成有序步骤，每一步必须能映射到技能注册表；映射不到的动作不会执行，也不会编造。
- 编排按顺序执行每一步；某一步的完成信号只结束该步，其他步骤继续执行。
- 技能开关在编排前统一检查：任何一个步骤的技能被停用或不在灰度范围，整体不进入编排，避免执行一半。
- 主模型优先通过稳定原生工具 Schema 提出有序请求，与单技能和确定性计划共用执行门；旧 `feature_calls` 在迁移期兼容读取，同一请求不得双重执行。Schema 全集不随群状态变化，动态可用性另行提供，执行前仍复核权限、开关、灰度、依赖和会话时效；主动聊天不得调用这些技能。
- 当前稳定全集是 2 个有界知识检索、30 个只读 QQ 直送动作和 12 个显式状态动作。档案类动作只接受本人或本轮唯一真实 `at`，游戏细分排行只接受类型化范围、角色和页码，并统一通过 `bot/integrations/game_workflow_adapter.py` 构造审核后的请求；状态动作只走原生调用，每批一个，使用状态指纹和幂等键保护；不提供任意上游命令字符串入口。
- 聊天合并事件在本地功能边界恢复原始群消息身份；发送直接绑定原始事件，不依赖已退出的 matcher 上下文。每步的图片／文字获得平台回执后才记录。

## 用量、成本与安全

- 每次技能调用记录 `data/skills/metrics.db`：技能、群、用户、动作、成功与否、延迟、token 与费用。
- 汇总按技能和按群统计调用量、失败率、平均延迟、token 与费用，供成本运营与容量评估使用。
- `scripts/validate_skill_security.py` 做静态安全审计：注册表归属、插件路径、凭证特征、管理员命令冲突、超级管理员门与技能开关门。
- `bot/services/skill_capability.py` 提供运行时上游能力探测：只读、带 TTL 缓存、事件路径失败即降级；`gsuid_core`、`nteuid`、`wuwa_uid` 不可用时，相关技能返回“上游不可用”而不是报错。
- `bot/services/skill_security.py` 提供角色门与脱敏：技能声明 `required_role`，审计与错误文本写入前会移除 Bearer、token、API key 等凭证特征。
- 语义评审运行器：`scripts/judge_skills_quality.py`，对黄金集回复按自然、事实、不编造、人格四维打分；支持 `--dry-run` 校验请求结构。
- 回复来源链：`tangtang_calls.provenance` 记录本条回复用到的技能、动作、参数与群摘要话题版本，可回查但不重新注入提示词。
- 黄金对话集覆盖呼叫、沉默、未注册能力、记忆更正与遗忘，以及日/周/月/总与集群排行等确定性路由。
