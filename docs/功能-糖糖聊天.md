# 糖糖 AI 聊天功能说明

糖糖 AI 聊天是一个完全独立的模块：被 @ 或消息里出现“糖糖”时，由糖糖人格决定是否接话、怎么接话。它与随机表情、随机复读、三连复读完全并行，互不干预。

开启主动回复后，即使没人呼叫，糖糖也会对启用群内的普通聊天按概率尝试主动接话；命中后仍由糖糖人格判断 `[接话]` 或 `[沉默]`。

## 触发

- @ 机器人。
- 消息文本包含呼叫词（默认“糖糖”，`TANGTANG_CALL_KEYWORD` 可改）。
- 只对 `TANGTANG_GROUP_IDS` 配置的管理群生效，私聊不处理。
- “糖糖”已从嘉然主题别名中移除，它只是机器人名字/呼叫词。

## 主动回复（可选）

主动回复处理的是“没有被 @、也没有包含呼叫词”的普通群消息，由以下参数共同控制频率：

- `TANGTANG_PROACTIVE_ENABLED`：总开关，默认关闭；
- `TANGTANG_PROACTIVE_PROBABILITY`：每条合格普通消息触发一次“主动接话尝试”的概率；
- `TANGTANG_PROACTIVE_COOLDOWN_SECONDS`：同一群两次主动尝试之间的最小间隔；
- `TANGTANG_PROACTIVE_MESSAGE_INTERVAL`：同一群两次主动尝试之间至少隔多少条群消息。

后三项均使用逗号分隔值，并严格按 `TANGTANG_GROUP_IDS` 的配置顺序逐群映射。例如有七个有效群时，每项应写七个值；当前默认是每群 `5% / 1800 秒 / 35 条`。

触发尝试后会调用一次模型，由糖糖按 `[接话]`/`[沉默]` 决定是否真的回复；回复不引用原消息。硬/软黑名单、被动过滤名单和机器人自身消息同样不参与主动回复。它与随机表情、随机复读、三连复读并行，同一条消息可能同时触发复读和糖糖主动回复；需要时可通过复读概率/冷却/间隔单独调低。

超级管理员可用以下指令实时调整，参数会同时写回 `.env`：

```text
#糖糖主动回复 状态
#糖糖主动回复 开启
#糖糖主动回复 关闭
#糖糖主动回复 概率 5%
#糖糖主动回复 冷却 30
#糖糖主动回复 间隔 50
```

## 行为链路

1. 呼叫被识别。
2. 用户消息与该群糖糖最近 10 条历史输出完全一致 → 视为复读糖糖，直接跳过。
3. 同群相同呼叫在 60 秒内重复出现 → 仅保留首条，后续直接跳过。
4. 硬表（`hard_blacklist.txt`）命中 → 完全不回复、不调模型。
5. 本地预筛：消息里是否有“直播/发言/排行/活动/日程/海岸”等功能线索。
   - 没有 → 直接进入普通聊天流程。
   - 有 → 调用一次小模型做三档意图判断（clear/maybe/chat），同时现编糖糖话术。
6. 三档结果：
   - `clear`（语义明确）→ 先发糖糖现编的一句话，再调用对应本地 `#` 命令。
   - `maybe`（接近明确）→ 先发一句中立、模棱两可的现编话术，再执行功能。
   - `chat`（不明确）→ 不执行功能，继续普通聊天流程。
7. 按 `TANGTANG_IGNORE_PROBABILITY`（默认 10%）掷一次“不理人”，命中 → 完全不回复、不调模型。
8. 软表（`soft_blacklist.txt`）命中后，按 `TANGTANG_SOFT_BLACKLIST_IGNORE_PROBABILITY`（默认 0%）再独立掷一次“不理人”；未命中才不调模型并从 `lines.txt` 随机回一句台词。
9. 纯“糖糖”/纯 @ 无内容 → 从 `lines.txt` 随机回一句台词。
10. 其余呼叫：
   - D 模式（默认）：单次调用模型，第一行输出 `[接话]` 或 `[沉默]`，接话时第二行起是正文。
   - C 模式：本地规则先分类——明确提问/请求 → 必答；闲聊感叹 → 按 `TANGTANG_C_PROBABILITY` 接话；接话内容仍全部由模型生成。

## 本地功能呼叫

呼叫糖糖时，机器人会先判断这句话是不是想调用本地功能，而不是只认固定句式。判断采用“本地预筛 + 模型三档分类”：

| 档位 | 语义 | 行为 |
| --- | --- | --- |
| 明确 | 直接要求查看某功能 | 先发一句糖糖式话术，再执行功能 |
| 接近明确 | 像在问、但意思已经偏向某功能 | 先发一句中立模糊的现编话术，再执行功能 |
| 不明确 | 只是聊天或评价 | 不执行，继续普通聊天 |

支持的功能和自然说法示例：

| 自然说法 | 对应命令 |
| --- | --- |
| `糖糖，看一下今天有谁在播？` | `#今日直播` |
| `糖糖，明天有人直播吗` | `#明日直播` |
| `糖糖，看下这周直播日程` | `#本周直播` |
| `糖糖，枝江日程 / 枝江直播` | `#枝江直播` |
| `糖糖，看看现在有哪些活动` | `#活动大厅` |
| `糖糖，今天群里发言情况怎么样` | `#发言排行`（默认日） |
| `糖糖，看一下a海岸这个月的发言榜` | `#A海岸发言排行 月` |

时间词会自动抽成范围：今天/现在=日，这周/本周=周，这个月/本月=月，总/累计=总；没提时默认日。提到“a海岸/海岸”的发言榜走 A海岸排行。个人发言排行已关闭，即使呼叫中出现“我/本人/自己/某人”或 @ 成员，识别到发言排行时也只查询群排行。

执行时仍然调用现有 `#` 命令的同一套逻辑，权限、群范围和图片回退完全保留，不影响原有命令。功能路由的判断话术由模型现编，只有带功能线索的消息会多消耗一次小模型调用；不明确的呼叫仍然回到原聊天流程。

## 本地枝江知识注入

模型回复前，糖糖会用当前呼叫消息检索本地枝江百科数据库（`bot/resources/zhijiang_encyclopedia.json`）：

- 命中时，把最多 3 条词条摘要（合计约 700 字内）作为 `[本地枝江知识]` 段落注入提示词，并优先于群聊气氛和互动历史保留。
- 检索只返回未标记违禁品的词条；与珈乐相关的违禁词条不会注入提示词，也不会被模型作为本地资料看到。
- 未命中或消息与枝江资料无关时，不注入任何本地知识段落，不影响普通聊天。
- 本地功能路由（直播/活动/排行）不受影响，仍然先走原命令逻辑。
- 知识词条存放在 SQLite（`data/knowledge/knowledge.db`），启动时从 JSON 播种；通过审核命令收录的新词条即时生效，不需要重启。直接修改 JSON 播种内容仍需重启。

## 本地鸣潮梗文化注入

模型回复前，糖糖会用当前呼叫消息同时检索本地鸣潮梗文化库（`bot/resources/mingchao_meme_culture.json`）：

- 命中时，把最多 3 条词条摘要（合计约 700 字内）作为 `[本地鸣潮梗文化]` 段落注入提示词。
- 与 `[本地枝江知识]` 一起优先于群聊气氛和互动历史保留，两份本地知识合计上限约 1200 字；空间不足时先压缩群聊气氛、再压缩历史。
- 检索只返回未标记违禁品的词条；鸣潮梗库当前不含珈乐相关内容，且与珈乐相关的枝江词条仍被过滤，不会注入提示词。
- 未命中或消息与鸣潮梗无关时，不注入该段落，不影响普通聊天。
- 梗库与枝江百科共用 `data/knowledge/knowledge.db`，只读取 `approved` 词条；审核收录的新词条即时生效。

## Agent 工具检索（工具调用）

除了预先注入本地资料，糖糖还支持让模型自己决定“要不要查、查什么”：

- 模型调用时附带两个本地查询工具：`search_zhijiang_knowledge`（枝江百科）和 `search_mingchao_meme_culture`（鸣潮梗库）。
- 模型认为资料不够时自主调用工具，机器人在本地执行检索并把结果（同样过滤违禁品、单次结果约 700 字内）返回模型，再让它继续回答；最多循环 `TANGTANG_TOOL_LOOP_MAX` 轮。
- 命中工具时回复会多 1-2 次模型调用，延迟大致翻倍（当前实测模型回复中位约 2.3 秒，翻倍约 4-6 秒，属可接受范围）。
- 工具结果与预注入共用同一套本地库和违禁过滤，珈乐相关词条不会出现在工具返回里；工具层还有一道关键词兜底过滤。
- 如果 API 不接受工具参数，会自动回退为原来的单次生成，不影响正常回复。
- `TANGTANG_TOOLS_ENABLED=false` 可整体关闭；默认开启。

## 黑梗与旧曲版本应对

对枝江社区中的黑梗，糖糖不再“装傻”，而是按本地规则直接回应：

- 被屏蔽的旧成员相关称呼（含其粉丝名）被提及时，由代码层向模型注入应对指示：用模型自然表达的类似台词（原则固定为“不谈这个fifa人物”方向），不展开、不解释、不输出历史细节。
- 提及李滇滇时，同样由模型自然表达类似“人各有志，各自安好”的话，不评价个人选择。
- “毒唯”“著名唯粉”等贴吧/社区黑话已作为词义词条收录进枝江百科库；糖糖可以解释公开词义，但以否定态度表态或直接不接，不站队、不传播人身攻击。
- 涉及已停止活动成员的五人曲或四人曲，最初版本已无法复刻；引用时以现役三人组（贝拉、嘉然、乃琳）或枝江娱乐新五人组的新演绎为准。本地已收录《Quiet》《超级敏感》《除夕》《传说的世界》等现行版本参考；未检索到新版本时明说未检索到，不推荐旧版。

## 互动历史与上下文

- 糖糖成功回复（模型回复、主动回复、台词回复和本地功能都算）时，记录：时间、群号、用户 QQ、消息 ID、呼叫原文、回复文本、回复类型（模型/主动/台词/本地功能）、模式。
- 查看：`python scripts/tangtang_history.py QQ号 [--group 群号] [--limit 条数]`；主动、台词和本地功能会分别带“主动”“台词”“本地功能”标记。
- 注入上下文时只用“模型回复”部分（含主动回复）：默认最近 10 条、合计不超过 1000 字（`TANGTANG_HISTORY_MESSAGES`、`TANGTANG_HISTORY_CHARS`）。
- 呼叫时还会带上该群最近 10 条群消息（仅内存、不落盘）作为群聊气氛。
- 每用户不设保留上限；如需清理，删除 `tangtang.db` 即可（会清空全部历史）。

## 提示词结构

每次模型调用，正文提示词按优先级包含：

- `[本地枝江知识]` / `[本地鸣潮梗文化]`：命中本地资料时注入（各自最多 3 条、约 700 字，两份合计约 1200 字）。
- `[最近群聊气氛]`：该群最近 10 条消息（`昵称: 内容`，仅内存）。
- `[你与该群友的成功互动历史]`：该群友最近 10 条模型回复（合计 ≤1000 字）。
- `[当前呼叫]`：说话人昵称、被@状态、消息媒体（图片/表情/语音等）、引用消息、本条消息文字。

“当前呼叫”和输出格式永远完整保留；空间不足时优先保留本地知识，再压缩群聊气氛、再压缩历史。

硬/软黑名单全部由代码层在调用前拦截，模型只会收到通过过滤的 normal 消息；人格文件不重复承载黑名单规则，避免提示词膨胀。

## 台词池规范

- 每行一句，一句话不超过 15 个字（含标点）。
- 台词不强制自称“糖糖”，可以有“在呢”“换个话题吧”这类直接口吻。
- 增删改后保存即生效；测试会校验条数和字数，改完建议跑 `pytest tests/test_tangtang_chat.py` 确认。

## 词表格式

- 每行一个词或短语，`#` 开头是注释，空行忽略，保存即生效。
- 普通行 = 包含匹配（不分大小写），只要消息里出现这个词就算命中。
- `re:` 开头的行 = 正则表达式（自动忽略大小写），例如 `re:wxid_[A-Za-z0-9_-]+`。
- 正则写错会被忽略并记录警告，不影响其他词条。
- 建议不要启用过宽的正则（如 QQ 号、URL 全匹配），会误伤正常聊天；`hard_blacklist.txt` 和 `soft_blacklist.txt` 里已把这类示例注释掉，需要时自行取消注释。

## 用量记录

每次模型调用（含判定为沉默的调用）、主动回复真实触发结果、功能路由判断和本地功能执行都会追加一行到 `data/tangtang/usage/` 当日文件，字段：时间、群号、用户 QQ、事件（reply/proactive_reply/silent/skip/hard_block/proactive_hard_block/proactive_skip/canned/feature_router/feature/error/in_flight）、模式、模型、延迟、各 token 数、detail（命中的黑名单词/正则）。主动回复的冷却/间隔/概率未命中不会逐条记录；只记录真正触发后的结果，不记消息原文。

## 与旧功能的关系

- 随机表情、随机复读、三连复读完全不受影响，一条消息可能同时出现复读和糖糖回复。
- 开启主动回复后，未呼叫的普通消息也可能出现糖糖主动回复；与复读类被动互动的重叠可通过各自概率/冷却调整。
- 被动过滤名单中的用户不会触发糖糖回复（沿用现有过滤约定）。
- 旧 AI 群聊助手（`ai.py` 及 `AI_*` 配置）已整体移除；糖糖不依赖任何旧 AI 配置、数据库或代码。

## 与 .env 的同步

- 糖糖与画像的 `TANGTANG_*`、`PROFILE_*` 参数直接读 `.env`，保存即热更新；
- `TANGTANG_PROACTIVE_PROBABILITY`、`TANGTANG_PROACTIVE_COOLDOWN_SECONDS` 和 `TANGTANG_PROACTIVE_MESSAGE_INTERVAL` 都是逗号分隔列表，按 `TANGTANG_GROUP_IDS` 的顺序逐群对应；每个有效群必须恰好有一个值；
- `#糖糖主动回复` 指令修改主动回复参数时会将同一个值写入全部糖糖群的对应列表项；需要不同群采用不同值时，直接编辑 `.env` 中的列表；
- `#功能范围` 与 `#整点报时 范围` 等指令修改的功能群列表，在写入 SQLite 的同时会实时写回 `.env` 对应键（`DUPLICATE_GROUP_IDS`、`GAME_GROUP_IDS`、`ACTIVITY_GROUP_IDS`、`BOT_RANDOM_REACTION_GROUP_IDS`、`HOURLY_ANNOUNCEMENT_GROUP_IDS`），重启后仍保持一致；
- 随机复读和三连复读的概率、冷却、间隔、开关均为逗号分隔列表，按 `BOT_RANDOM_REACTION_GROUP_IDS` 的顺序逐群对应；按群指令修改时会同步更新 `.env` 中该群对应的一项，并持久化到 SQLite。

## 如何开启思考模式

把 `TANGTANG_REASONING_EFFORT` 从 `none` 改为 `low`、`high` 或 `max` 即可（`.env` 保存即热更新）。`responses` 和 `chat_completions` 两种接口风格都会生效：关闭时发送 `thinking.type=disabled`；开启时发送 `thinking.type=enabled`，`responses` 风格带 `reasoning.effort`，`chat_completions` 风格带顶层 `reasoning_effort`。只接受官方取值 `none/low/high/max`，其他值会导致配置校验失败、功能自动关闭。

注意：思考模式会额外消耗推理 token，回复延迟也会变高；如果只是日常群聊，建议保持 `none`。
