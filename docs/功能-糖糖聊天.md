# 糖糖 AI 聊天功能说明

实时聊天现已固定为[达妮娅人格与独立语音](功能-人格与语音.md)，呼叫词为“娅娅”，仅真实 @ 算作 @ 呼叫。糖糖旧历史、选择和资源保留，但不会进入后续聊天模型。文件名和 `TANGTANG_*` 配置前缀属于兼容接口，不代表仍可选择糖糖对话。

糖糖 AI 聊天是一个完全独立的模块：被 @ 或消息里出现“糖糖”时，由糖糖人格决定是否接话、怎么接话。它与随机表情、随机复读、三连复读完全并行，互不干预。

开启主动回复后，即使没人呼叫，糖糖也会对启用群内的普通聊天按概率尝试主动接话；命中后仍由糖糖人格判断 `[接话]` 或 `[沉默]`。

两种聊天能力都使用 SQLite 机器人级总控保护 Token 成本。被呼叫会话必须同时满足 `#系统设置 被呼叫会话` 总控和当前群“被呼叫会话”开关为开；糖糖主动聊天必须同时满足 `#系统设置 糖糖主动聊天` 总控和当前群“糖糖主动聊天”开关为开。任意一层关闭都会阻止新的模型调用，且不会覆盖另一层保存的状态。

## 触发

- @ 机器人。
- 消息文本包含呼叫词（默认“糖糖”，`TANGTANG_CALL_KEYWORD` 可改）。
- 只对 `TANGTANG_GROUP_IDS` 配置的管理群生效，私聊不处理。
- “糖糖”已从嘉然主题别名中移除，它只是机器人名字/呼叫词。

## 主动回复（可选）

主动回复处理的是“没有被 @、也没有包含呼叫词”的普通群消息。每群在本机 `data/tangtang/proactive.db` 固定选择 `legacy`（旧规则）、`active_v1`（活跃群）或 `low_traffic_v1`（低流量群），不自动按人数分档。未配置时兼容旧规则；维护者可以指定未来接管群的默认策略。任何策略都尊重群开关，关闭的群不会被初始化或低流量补偿重新打开。

活跃群：每人每分钟最多贡献一次热度，半衰期5分钟；每15秒抽签，按贡献速率R的0.3、1.5、3分档，低于0.3不抽签，其余强度为12/24/48次每小时（每15秒约4.88%/9.52%/18.13%）。这些是冷却结束后的抽签速度，不是每小时实际模型调用数。尝试冷却15分钟；最新有效消息≤90秒且近3分钟至少2条文字，允许同一人；每日每群最多60次尝试。

低流量群：10分钟没有有效文字后开始新发言段；一条至少6个有效字符或近5分钟2条即可，单人也能触发。每段70%进入模型判断；连续两段仅因随机落空，第三段免抽签。每段最多一次机会、冷却30分钟、每群每日最多12次。模型沉默不算随机落空，也不会追着同一段重试。没有新消息时不发送定时问候。

两套新策略的静默段为本地02:00—08:00，全局每日最多400次主动尝试，给已开启的低流量群各保留12次容量。额度与冷却按群共用，不随人格资源版本变化或进程重启清零；进入评估后失败或沉默仍计次数。自然日按配置时区重置。明确@与正确呼叫不使用这些主动限制，但仍受原有聊天总控和费用设置保护。

定时器只提交现有有界聊天队列，群忙或队列满不补排过期主动消息。送达前再次检查人格、配置、策略版本和新鲜度，包括迟到语音；使用最近5分钟最多20条公共上下文，并保留原有输入长度限制。新策略尝试、模型开始、沉默、送达、失败和不确定结果记录于独立账本；仅成功送达仍按既有流程进入人格历史和成长证据。

旧规则保留以下参数，修改它们不会改变两套新策略的固定阈值：

- `TANGTANG_PROACTIVE_ENABLED`：总开关，默认关闭；
- `TANGTANG_PROACTIVE_PROBABILITY`：每条合格普通消息触发一次“主动接话尝试”的概率；
- `TANGTANG_PROACTIVE_COOLDOWN_SECONDS`：同一群两次主动尝试之间的最小间隔；
- `TANGTANG_PROACTIVE_MESSAGE_INTERVAL`：同一群两次主动尝试之间至少隔多少条群消息。

后三项均使用逗号分隔值，并严格按 `TANGTANG_GROUP_IDS` 的配置顺序逐群映射。例如有七个有效群时，每项应写七个值；当前默认是每群 `50% / 900 秒 / 30 条`。

触发尝试后会调用一次模型，由糖糖按 `[接话]`/`[沉默]` 决定是否真的回复；回复不引用原消息。硬/软黑名单、被动过滤名单和机器人自身消息同样不参与主动回复。它与随机表情、随机复读、三连复读并行，同一条消息可能同时触发复读和糖糖主动回复；需要时可通过复读概率/冷却/间隔单独调低。

本群开关由群主、群管理员或超级管理员使用 `#群设置 糖糖主动聊天 开|关` 调整。超级管理员可用以下指令维护机器人级参数，参数会写回 `.env`：

```text
#糖糖主动回复 状态
#糖糖主动回复 概率 50%
#糖糖主动回复 冷却 30
#糖糖主动回复 间隔 50
#主动回复 策略 活跃群
#主动回复 策略 低流量群
#主动回复 策略 旧规则 全部
```

策略命令只限超级管理员，可加已接管群号或“全部”；不加目标则操作当前群。策略修改立即使旧策略未送达内容失效，保留已有冷却和历史。`#主动回复 状态` 同时显示新策略、群开关、热度和今日结果。维护者也可使用 `.\.venv\Scripts\python.exe scripts/manage_proactive.py --all` 查看；`--strategy legacy --all --default --apply` 可整体回退旧策略，无需重启。新参数恢复时再按本机固定分组设回对应策略。

代码回退使用部署前Git提交；数据库、`.env` 和研究资料不在Git中。不要用恢复旧数据库代替策略回退，否则会丢失部署后历史。只在代码故障时回退提交并仅重启NoneBot。

其中 `#糖糖主动回复 开启|关闭` 是 `.env` 参数开关，不替代 SQLite 成本总控。超级管理员私聊使用以下系统命令进行即时总控：

```text
#系统设置 被呼叫会话 状态|开|关
#系统设置 糖糖主动聊天 状态|开|关
```

两个系统总控保存到 SQLite，修改后立即影响新消息，不需要重启；已经发出的模型请求不会被强行中断。

## 模型档案与切换

糖糖支持任意数量的编号模型档案。端点、模型 ID 和密钥只能由维护者手动编辑 `.env`，不能通过 QQ 录入；超级管理员只能在已登记档案之间切换：

```text
#糖糖模型 状态
#糖糖模型 模型1
#糖糖模型 模型2
```

档案使用 `TANGTANG_MODEL_PROFILE_<编号>_*` 配置，编号可以不连续。`NAME` 是 QQ 指令使用的档案名；每个档案独立配置 `PROVIDER`、`API_URL`、`API_KEY`、`API_STYLE`、`MODEL`、`REASONING_EFFORT` 和可选的 `VISION_DETAIL`。`TANGTANG_MODEL_ACTIVE_PROFILE` 保存当前档案名，切换后热更新，不需要重启。状态回复只展示档案名、提供方、模型 ID 和接口风格，不展示 API 地址或密钥。未配置任何档案时继续兼容原有单模型 `TANGTANG_API_*` 配置。

## 行为链路

1. 呼叫被识别。
2. 用户消息与该群糖糖最近 10 条历史输出完全一致 → 视为复读糖糖，直接跳过。
3. 同群相同呼叫在 60 秒内重复出现 → 仅保留首条，后续直接跳过。
4. 硬表（`hard_blacklist.txt`）命中 → 完全不回复、不调模型。
5. 本地预筛：消息里是否有“直播/发言/排行/日程/集群”等功能线索。
   - 没有 → 直接进入普通聊天流程。
   - 有 → 调用一次小模型做三档意图判断（clear/maybe/chat），同时现编糖糖话术。
6. 三档结果：
   - `clear`（语义明确）→ 先发糖糖现编的一句话，再调用对应本地 `#` 命令。
   - `maybe`（接近明确）→ 先发一句中立、模棱两可的现编话术，再执行功能。
   - `chat`（不明确）→ 不执行功能，继续普通聊天流程。
7. 按 `TANGTANG_IGNORE_PROBABILITY`（默认 5%）掷一次“不理人”，命中 → 完全不回复、不调模型。
8. 软表（`soft_blacklist.txt`）命中后，按 `TANGTANG_SOFT_BLACKLIST_IGNORE_PROBABILITY`（默认 0%）再独立掷一次“不理人”；未命中才不调模型并从 `lines.txt` 随机回一句台词。
9. 纯“糖糖”/纯 @ 无内容 → 从 `lines.txt` 随机回一句台词。
10. 其余呼叫：
   - D 模式（默认）：单次调用模型，第一行输出 `[接话]` 或 `[沉默]`，接话时后续每个 `[消息]` 会作为一条独立 QQ 消息发送。
   - C 模式：本地规则先分类——明确提问/请求 → 必答；闲聊感叹 → 按 `TANGTANG_C_PROBABILITY` 接话；接话内容仍全部由模型生成。

## 本地功能呼叫

呼叫糖糖时，机器人会先判断这句话是不是想调用本地功能，而不是只认固定句式。判断采用“本地预筛 + 模型三档分类”：

| 档位 | 语义 | 行为 |
| --- | --- | --- |
| 明确 | 直接要求查看某功能 | 先发一句糖糖式话术，再执行功能 |
| 接近明确 | 像在问、但意思已经偏向某功能 | 先发一句中立模糊的现编话术，再执行功能 |
| 不明确 | 只是聊天或评价 | 不执行，继续普通聊天 |

支持的功能和自然说法示例：

| 自然说法 | 对应命令 |
| --- | --- |
| `糖糖，看一下今天有谁在播？` | `#今日直播` |
| `糖糖，明天有人直播吗` | `#明日直播` |
| `糖糖，看下这周直播日程` | `#本周直播` |
| `糖糖，枝江日程 / 枝江直播` | `#枝江直播` |
| `糖糖，今天群里发言情况怎么样` | `#发言排行`（默认日） |
| `糖糖，看一下这个集群本月的发言榜` | `#集群发言排行 月` |

时间词会自动抽成范围：今天/现在=日，这周/本周=周，这个月/本月=月，总/累计=总；没提时默认日。普通说法查询当前群，明确说“集群发言榜”才查询当前集群。个人发言排行已关闭，即使呼叫中出现“我/本人/自己/某人”或 @ 成员，识别到发言排行时也只查询群排行。

执行时仍然调用现有 `#` 命令的同一套逻辑，权限、群范围和图片回退完全保留，不影响原有命令。功能路由的判断话术由模型现编，只有带功能线索的消息会多消耗一次小模型调用；不明确的呼叫仍然回到原聊天流程。

## 本地枝江知识注入

模型回复前，糖糖会用当前呼叫消息检索本地枝江百科数据库（`bot/resources/zhijiang_encyclopedia.json`）：

- 命中时，把最多 3 条词条摘要（合计约 700 字内）作为 `[本地枝江知识]` 段落注入提示词，并优先于群聊气氛和互动历史保留。
- 检索只返回未标记违禁品的词条；与珈乐相关的违禁词条不会注入提示词，也不会被模型作为本地资料看到。
- 未命中或消息与枝江资料无关时，不注入任何本地知识段落，不影响普通聊天。
- 本地功能路由（直播/排行）不受影响，仍然先走原命令逻辑。
- 知识词条存放在 SQLite（`data/knowledge/knowledge.db`），启动时从 JSON 播种；通过审核命令收录的新词条即时生效，不需要重启。直接修改 JSON 播种内容仍需重启。

## 本地鸣潮梗文化注入

模型回复前，糖糖会用当前呼叫消息同时检索本地鸣潮梗文化库（`bot/resources/mingchao_meme_culture.json`）：

- 命中时，把最多 3 条词条摘要（合计约 700 字内）作为 `[本地鸣潮梗文化]` 段落注入提示词。
- 与 `[本地枝江知识]` 一起优先于群聊气氛和互动历史保留，两份本地知识合计上限约 1200 字；空间不足时先压缩群聊气氛、再压缩历史。
- 检索只返回未标记违禁品的词条；鸣潮梗库当前不含珈乐相关内容，且与珈乐相关的枝江词条仍被过滤，不会注入提示词。
- 未命中或消息与鸣潮梗无关时，不注入该段落，不影响普通聊天。
- 梗库与枝江百科共用 `data/knowledge/knowledge.db`，只读取 `approved` 词条；审核收录的新词条即时生效。

## Agent 工具检索（工具调用）

除了预先注入本地资料，糖糖还支持让模型自己决定“要不要查、查什么”：

- 稳定工具全集现为 44 项：两个返回有界模型数据的本地检索工具、30 个直接送达 QQ 的只读动作，以及 12 个明确改变缘分／小游戏状态的动作。工具 Schema 不按群开关或依赖状态增删；本轮可用性和状态版本放在动态执行上下文，执行时仍重新授权。
- 模型认为资料不够时自主调用工具，机器人在本地执行检索并把结果（同样过滤违禁品、单次结果约 700 字内）返回模型，再让它继续回答；最多循环 `TANGTANG_TOOL_LOOP_MAX` 轮。
- 命中工具时回复会多 1-2 次模型调用，延迟大致翻倍（当前实测模型回复中位约 2.3 秒，翻倍约 4-6 秒，属可接受范围）。
- 工具结果与预注入共用同一套本地库和违禁过滤，珈乐相关词条不会出现在工具返回里；工具层还有一道关键词兜底过滤。
- 如果 API 不接受工具参数，会自动回退为原来的单次生成，不影响正常回复。
- `TANGTANG_TOOLS_ENABLED=false` 可整体关闭；默认开启。

## 黑梗与旧曲版本应对

对枝江社区中的黑梗，糖糖不再“装傻”，而是按本地规则直接回应：

- 被屏蔽的旧成员相关称呼（含其粉丝名）被提及时，由代码层向模型注入应对指示：用模型自然表达的类似台词（原则固定为“不谈这个fifa人物”方向），不展开、不解释、不输出历史细节。
- 提及李滇滇时，同样由模型自然表达类似“人各有志，各自安好”的话，不评价个人选择。
- “毒唯”“著名唯粉”等贴吧/社区黑话已作为词义词条收录进枝江百科库；糖糖可以解释公开词义，但以否定态度表态或直接不接，不站队、不传播人身攻击。
- 涉及已停止活动成员的五人曲或四人曲，最初版本已无法复刻；引用时以现役三人组（贝拉、嘉然、乃琳）或枝江娱乐新五人组的新演绎为准。本地已收录《Quiet》《超级敏感》《除夕》《传说的世界》等现行版本参考；未检索到新版本时明说未检索到，不推荐旧版。

## 文件布局

| 文件 | 用途 |
| --- | --- |
| `bot/resources/tangtang/persona.md` | 聊天人格，每次模型调用注入 |
| `bot/resources/tangtang/hard_blacklist.txt` | 硬表：每行一个词/短语，`#` 为注释 |
| `bot/resources/tangtang/soft_blacklist.txt` | 软表：每行一个词/短语，`#` 为注释 |
| `bot/resources/tangtang/lines.txt` | 台词池：每行一句（不超过 15 字，可不含自称），初始 100 句 |
| `data/tangtang/tangtang.db` | 互动历史（独立 SQLite/WAL，只属于本模块） |
| `data/tangtang/usage/YYYY-MM-DD.jsonl` | token 用量与主动回复判定记录（不含消息内容） |
| `scripts/tangtang_history.py` | 本地查看某用户与糖糖的互动记录 |

## 互动历史与上下文

- 糖糖成功回复（模型回复、主动回复、台词回复和本地功能都算）时，记录：时间、群号、用户 QQ、消息 ID、呼叫原文、回复文本、回复类型（模型/主动/台词/本地功能）、模式。
- 查看：`python scripts/tangtang_history.py QQ号 [--group 群号] [--limit 条数]`；主动、台词和本地功能会分别带“主动”“台词”“本地功能”标记。
- 注入上下文时只用“模型回复”部分（含主动回复）：默认最近 10 条；`TANGTANG_HISTORY_CHARS=0` 时不再按字符裁剪，原文完整保留在本地 SQLite。
- 呼叫时还会带上该群最近若干条群消息作为群聊气氛；条数由 `TANGTANG_GROUP_CONTEXT_MESSAGES` 控制。
- Agent v2 另在当前人格的历史数据库中维护 `chat_context_sessions`、`chat_context_turns`、`chat_context_snapshots` 和 `chat_context_compaction_jobs`。会话按当前人格数据库、群和用户隔离；会话游标记录已经确认送达的群消息位置。达妮娅的个人长期记忆仍遵守其独立跨群身份边界，但原始聊天上下文不会跨群。
- 只有 QQ 平台返回有效消息回执后，本轮 user、tool call/result 和实际送达 assistant 文本才以 `confirmed` 原子提交。沉默、失败或无回执只写 `audit`，不会进入下一轮活跃窗口；相同 request/sequence 重试幂等。
- Agent v2 的活跃窗口按完整确认请求计数，不按 user/tool/assistant 项数硬切。30 轮以内不压缩；31 至 50 轮只在输入达到 12000 token，或供应商不报告缓存且序列化输入达到 12000 字符时压缩；超过 50 轮必定入队。压缩成功后保留最近 30 个完整轮次，形成 30～50 轮的代际窗口。
- 同一代内，第一次请求带最多 30 条群聊气氛基线；后续请求只带该群-用户会话自上次确认送达后的新增群消息，以及本轮动态个人状态和当前输入。它们只追加在旧请求之后，上一轮请求是下一轮请求的严格前缀。发送失败、沉默或无回执不推进群消息游标；压缩成功时允许一次有意的前缀重建，压缩失败不推进快照游标，也不拆开工具调用所属轮次。
- 压缩使用当前活动模型、`reasoning_effort=low`、45 秒超时和最多 1600 输出 token，固定输出 `facts / commitments / unresolved / topic_progress / source_turn_ids / scope / revision`。任务有租约、代次、指数退避和来源 hash；JSON 或来源校验失败时保留上一快照且不推进版本。
- 快照只是一份派生索引。原始聊天、确认轮次、记忆证据和旧快照不会因压缩自动删除；清理数据库是独立的破坏性运维，不属于上下文压缩或回退。

## 群聊话题摘要

- 群摘要按“人格 + 群”隔离，只描述群里讨论过什么、聊到哪一步；它不是个人长期记忆，也不能用来推断某个人的性格。
- 群消息完整落库后由独立后台 worker 增量处理：摘要读取共享的原始群消息库，而不是人格交互日志；每种话题读取旧摘要加新增消息，合并后写入新版本。没有新增消息时不会重复调用模型。
- 群处理游标与整批话题更新原子提交；模型失败、JSON 不合格或校验失败时保留原文和游标，持久化退避后重试。
- 只处理最近 `TANGTANG_GROUP_SUMMARY_MAX_AGE_HOURS` 小时内的消息；更早的积压直接推进游标跳过，不调用模型，也不生成话题。原文仍完整保存在 SQLite 中，需要时可按来源回查。切换摘要来源时游标重新定位到新来源尾部，不追旧积压，也不删除已有话题。
- 同一批消息可同时维护多个话题；旧话题冷却后仍保留，后续重新聊到同一话题时继续沿用原话题，不会重新建档。
- 一次模型请求同时完成本批消息的话题归属和摘要更新；每个旧话题每批最多更新一次。所有消息必须明确归档或标记为无状态变化的插话，否则整批不提交。
- 每个群最多保留 `TANGTANG_GROUP_SUMMARY_TOPIC_LIMIT`（默认 200）个未归档话题，按活跃状态、版本和最近更新时间保留，超出的话题自动归档；已归档话题不再参与提示词注入，但历史版本和来源仍保留。
- 注入提示词时按当前消息选 1～`TANGTANG_GROUP_SUMMARY_INJECT_TOPICS` 个相关话题，格式为 `[当前群聊话题摘要]`，排在最近群聊气氛之前。摘要中的未决事项会一并提交。
- 群摘要只注入达妮娅人格的对话；糖糖人格继续使用自己的最近群聊气氛和互动历史，不读取群话题摘要。
- 后台摘要使用当前活动模型档案，`reasoning_effort=low`，默认累计 40 条或等待 240 秒可处理，成功后至少间隔 240 秒。排队等待和 120 秒执行时限分开计时，失败只影响摘要更新。小时预算、历史整理限额及调整方式见[后台整理成本控制](后台整理成本控制.md)。

## 聊天可调用的确定性技能

被呼叫时，以下能力不需要 `#` 前缀，也不需要背参数，模型与本地规则会把口语归一化到已注册技能：

- 发言排行：说“今天/这周/这个月/累计的发言排行”即可，也支持“这周谁最能聊”“集群发言排行”。昨日、上周不是这项榜单的参数，不能拿当前榜替代。
- 直播日程：“今天有谁在播”“明天直播安排”“本周日程”“枝江日程”。
- 小游戏榜单：“看看转盘榜”“炸弹总榜”“骰子榜”“猜数榜”，默认本群，总榜必须明确提出；受技能和小游戏群开关约束。
- 帮助与状态：普通帮助、小游戏帮助、A-SOUL 帮助、本群公开功能状态、当前人格状态、本人印象和枝江日程状态。
- 发言档案：本群发言记录、关键词搜索及已有画像。目标只能是本人或当前请求中唯一真实 `@` 的成员；模型不能提供 QQ 号，画像工具不会触发新画像生成。
- 游戏只读排行：“看一下异环最强排行”“异环薄荷排行”“鸣潮今汐评分排行”“鸣潮今汐声骸排行”“鸣潮练度排行”，支持本群与明确总榜；同时可查看项目自有 NTE/鸣潮帮助。
- 缘分查询：“看看我今天的缘分”“看看本群缘分”，输出已有的个人／本群今日图片。两个只读查询动作本身不改变关系，也不触发随机互动；原 `#` 指令继续保留。
- 显式缘分操作：“帮我抽今日缘分”“强取 @成员”“解除今天的缘分”。强取只认本轮唯一真实 `@`，清缘不开放。
- 显式小游戏操作：俄罗斯转盘装填／开枪、普通或成语炸弹装填／传递、骰子开局、猜数字开局／提交。目标、数字、成语、模式和时长都有封闭 Schema；一批只执行一个状态动作。
- 达妮娅美图：“要看美图”“要一个娅娅的美图”“想看你的自拍”“发一张照片”，从本地收录中随机发送一张；最近 10 张降权，详见 [达妮娅美图](功能-达妮娅美图.md)。

不在注册表里的请求会明确拒绝，不会现场编造；“先看排行，然后看直播”这类显式多步骤请求按顺序依次执行。

### 模型请求调用本地技能

被呼叫和接续对话的主模型可通过原生工具提出最多六个有序动作。完整 44 项 Schema 是稳定前缀的一部分；`[本地技能调用协议]` 只作为动态可用性说明和只读旧模型兼容。明确只读表达仍可由本地直接解析；旧模型在统一 JSON 合同里提出的 `feature_calls` / `feature_call` 在 Q8 稳定前继续读取，但不能执行 Q6 写动作，同一请求出现原生工具调用时也不会再执行旧字段：

```json
{"decision":"reply","messages":["唔，我去看看。"],"voice":"text",
 "feature_calls":[{"action":"ranking","args":"周","cluster":false},
                  {"action":"week_live","args":"","cluster":false}]}
```

服务层按下面的顺序处理：

1. 校验完整的动作、参数和回复结构，拒绝不存在的能力、错误类型、越界范围和跨群参数。
2. 整批检查权限、群开关、技能灰度与依赖；每步执行时再检查，失效的会话停止发送。主动聊天与沉默决策不能执行。
3. 原生 direct-QQ 工具不把图片或档案原文回灌模型，也不需要第二次模型请求；旧协议可发送符合当前人格的过渡语。
4. 恢复合并消息的原始 QQ 群事件，调用既有功能，按顺序发送实际图片／文字；只将获得平台回执的输出写入功能历史和确认上下文。异常明确反馈，不将过渡语记成查询成功。
5. 状态动作在模型请求前记录 SQLite 状态指纹，批量预检、逐步执行和插件群锁内各复核一次；先占用幂等键再调用业务服务。同批多个状态动作整批拒绝，状态已变化或相同请求重放都不会修改数据。

这条通道让“谁最能聊”“这周直播什么”这类口语也能落到已注册技能，而不是由模型自行回答；模型仍然只能申请调用，不能凭空生成数据。

例如“娅娅，告诉我这周谁最能聊，顺便看看这周直播什么”会依次请求本群周榜和本周直播图片。含无法识别部分的组合请求交给主模型整体理解，不能默默丢掉其中一段。档案查询只允许本人或本轮真实 `@` 目标，并且档案原文、画像正文和图片不回灌模型；公告发布仍未开放。旧的直接指令保留各自入口与权限。

## 提示词结构

每次模型调用，正文提示词按优先级包含：

- `[当前群聊话题摘要]`：与该消息相关的群话题摘要和未决事项，只代表群聊公共场景。
- `[本地枝江知识]` / `[本地鸣潮梗文化]`：命中本地资料时注入（各自最多 3 条、约 700 字，两份合计约 1200 字）。
- `[最近群聊气氛]`：该群最近 `TANGTANG_GROUP_CONTEXT_MESSAGES` 条消息（`昵称: 内容`，仅内存）。
- `[你与该群友的成功互动历史]`：该群友最近 `TANGTANG_HISTORY_MESSAGES` 条模型回复。
- `[当前呼叫]`：说话人昵称、被@状态、消息媒体（图片/表情/语音等）、引用消息、本条消息文字。

“当前呼叫”和输出格式永远完整保留。`TANGTANG_MAX_INPUT_CHARS=0` 时取消提示词字符预算；大于 0 时空间不足会优先保留本地知识，再压缩群聊气氛、再压缩历史。

硬/软词语黑名单由代码层处理，与用户身份黑名单独立。用户身份黑名单取全局主动过滤、全局被动过滤和本群过滤的并集：禁止呼叫、续聊、主动接话、命令和自动互动，但发言统计继续计数。黑名单用户的文本、图片和别人引用的该用户消息不进入模型上下文；群话题摘要排除含其原始证据的旧话题。排队执行、模型请求和回复发送会复核名单；名单变化使旧会话前缀失效，保留数据库历史而不继续注入。

## 图片理解

- 对话模型使用 API 标识 `deepseek-flash`（DeepSeek V4.1 Flash）。当前消息和引用消息中的 OneBot 图片段会经过大小、像素、格式和公网来源校验，再作为真实视觉内容提交给模型。
- 被动呼叫新增读取四个来源：呼叫消息本身、明确引用的消息、呼叫者在当前群的上一条消息、当前群在呼叫之前的上一条消息。两个“上一条”相同时去重；按消息位置选取，不向前寻找最近带图消息，也不跨群。文本与图片分开发送仍可命中用户上一条。明确引用不受消息距离限制。
- 主动接话只新增读取实际命中消息自身的图片，不补取邻近消息或其引用图片。图片来源先按用户黑名单过滤，再去重；被过滤的前驱不向更早消息补位。
- 引用原文和原发送者放入本轮末尾的独立引用资料，即使此前已出现在固定历史中也重新附加；引用只是资料，不能授权工具执行。
- 当前消息、被引用消息和最近群聊上下文中的每张图片都会分别携带原发送者昵称；图片标签紧贴对应图片提交给模型，不会把引用消息的发送者错误套到其他上下文图片上。
- 不抓取正文中的任意 URL，不允许回环、局域网、链路本地或其他非公网地址，避免把模型图片功能变成内网请求入口。
- 统一使用 `detail: high`（等价于 `original`），仅在 `user` 消息中提供图片。按整个请求的历史图片加新增图片计数：少于 15 张最长边 8192px，15 张及以上最长边 4096px。低于上限保持原尺寸和原始字节；超过才等比例缩小，不裁切、不放大。限制依据：[DeepSeek 官方视觉文档](https://api-docs.deepseek.com/zh-cn/guides/vision)。
- 支持 JPEG、PNG、GIF、WebP；外部 URL 最长 8192 字符，单图最多 32 MiB、整个请求最多 600 张、图片总量最多 64 MiB，包含 base64 与文字的 JSON 请求体最多 48 MiB。当前不用 Files API。额外保留 1 亿像素的本地解码保护；格式、大小或下载校验失败会明确标记，不猜图。
- v2 对话将已读图片随原轮次保存在本地 SQLite 去重图片表中，重启后仍可恢复。新增图片不会删除或替换旧图片，已超出前驱选取范围的旧图片仍按历史保留；稳定前缀不反复重排或重编码。正常上下文压缩、黑名单变更及接口硬限制除外：达到 15 张时旧大图也必须缩到 4096px；请求体超限时停止该次请求，保留历史，不自动删旧图给新图腾位置。
- 文字里的 `[图片]` 只表示该位置存在图片，不代表糖糖看到了内容；未作为视觉输入提供或读取失败时，糖糖必须明确说不知道，不能猜测。
- 读取失败会在提示词中明确标为“图片读取失败”。图片观察属于本次感知，不会自动写入用户长期记忆。

## 自然多消息回复

- 模型用 `[消息]` 明确划分消息气泡；发送层不会按逗号或句号机械切句。
- 被呼叫回复只在第一条引用原消息，后续消息普通发送；主动回复全部不引用。
- 普通聊天默认只发一条，确有两个意思时才发第二条；即使模型输出更多，发送层也只保留前两条。三条及以上只在对方明确要求详细分析、教程或完整梳理时开放，并仍受 `TANGTANG_REPLY_MAX_BUBBLES` 限制。
- 普通回复以 4-12 字为中心，单条超过 20 字会降低权重，但不会被机械截断；明确要求详细说明时允许完整回答。默认省略主语，能用残句就不补成书面完整句，短句句尾通常不加句号。
- 语气词不每条都带、不习惯性单独成条，偶尔一条纯语气词可以；不句句自称“糖糖”。知识检索结果也优先压成一句群聊回答，而不是复述成报告。
- 每条之间默认等待 500-1400 毫秒。同一轮消息严格顺序发送；中途失败会停止后续发送，并把已送达、失败和未尝试部分分别记入数据库。

## 去 AI 腔

- 达妮娅和兼容保留的糖糖共用发送前清理，覆盖呼叫、续聊和主动聊天：去掉客服收尾（“希望以上能帮到你”“如有问题欢迎随时问我”“很高兴帮到你”）、捧场前缀（“好问题”“你说得太对了”“完全正确”）、假坦白开头（“说实话”“讲真”“说真的”）、无出处说法（“众所周知”“有研究表明”“专家表示”）和书面填充（“综上所述”“值得注意的是”等），并把堆叠的“可能/大概/也许”收敛成一个、把重复的问号、叹号等收敛成单个。
- 规则以中文版 op7418/Humanizer-zh（MIT 许可，<https://github.com/op7418/Humanizer-zh>）为基准，其本身翻译自 blader/humanizer；只保留适合中文短句群聊的安全子集，不增加模型改写请求。保留“据我所知、基于可用信息、根据目前公开的信息”等事实边界，也保留自然语气词、省略号和真实的接受或拒绝。含引号、代码标记或引用块的气泡保守跳过通用清理。达妮娅另在通用清理之前规范对白破折号：句中换成逗号，句首、句尾及已有标点旁的装饰破折号删除；原文引用、代码和链接中的破折号保留，普通连字符、参数和数值范围不改。文字、语音输入与语音备用回复采用同一处理，纯破折号气泡丢弃，历史只记录实际送达内容。
- 该库“被动语态/缺失主语”规则被有意反转：糖糖的群聊风格就是要像普通群友一样省略主语，因此不会强制补全主语。
- 空气泡被丢弃，全部清空时沿用沉默处理（旧版无角色上下文的强制回复场景会退回台词池）。开关为 `TANGTANG_HUMANIZE_ENABLED`，默认开启，同时控制发送前清理与近期重复提醒；关闭后人格资源本身的表达指导仍然存在。
- 近期重复提醒仅统计当前人格、当前群最近 24 小时最多 8 次已发送模型回复，包含主动聊天，排除固定台词、功能返回、发送失败和当前黑名单用户的记录。以“唔”开头至少 3 次、破折号至少 2 次、省略号至少 3 次、“收下”式或“当没看到／听到”式表达各至少 2 次时，提示本轮自然换一种表达。它是生成提醒，不是禁词或发送配额。
- 每轮只读一次历史；仅将不超过 200 字的固定类别提醒放入动态状态，shadow 与实际请求共用，不复制原文、身份，不改变静态前缀或工具 Schema。读取失败省略提醒，不重试生成、不阻塞其他聊天。人格文件变更会正常创建新上下文版本，旧历史保留。
- 风格效果使用 [report_reply_style.py](../scripts/report_reply_style.py) 按明确起止时间只读统计已发送回复，按呼叫、续聊、主动聊天分别报告；以每次回复为单位，各表达类别可以重叠。部署后至少观察 24 小时且累计至少 200 次回复，再结合各场景合计 30 条上下文人工复查；代码测试通过不代表自然度或频率目标已经达成。回退清理与提醒可关闭现有开关，回退人格表达需恢复对应资源，均不删除历史或记忆。

## 人格与长期记忆

- `self.md`、`soul.md`、`identity.md` 分别保存不可被对话直接改写的 SELF、价值边界和稳定身份；内容变更会在 `tangtang_self_versions` 中留下版本。
- 同一人格按用户账号跨群共享稳定资料和熟悉程度，群内称呼、约定和话题仍按群隔离。明确要求“记住”且通过质量检查的稳定个人事实立即生效；普通稳定偏好先作为候选，至少两次独立互动后才晋升，重复消息不计多次证据。
- 密码、验证码、身份证、银行卡、详细住址、健康、政治、宗教、性取向和真实姓名等内容不会被自动记忆。
- “忘记……”默认对该人格所有群中的本人资料生效，旧历史不能自动重新记起；“只在本群别提……”仅限制本群；“恢复记忆……”可由本人恢复。不影响其他用户或另一个人格，也不物理破坏审计记录。详见 [人格与语音](功能-人格与语音.md)。
- 关系熟悉度和群内人格状态每次只允许很小变化，只影响语气，不允许单条消息重写糖糖人格。

## 台词池规范

- 每行一句，一句话不超过 15 个字（含标点）。
- 台词不强制自称“糖糖”，可以有“在呢”“换个话题吧”这类直接口吻。
- 增删改后保存即生效；测试会校验条数和字数，改完建议跑 `pytest tests/test_tangtang_chat.py` 确认。

## 词表格式

- 每行一个词或短语，`#` 开头是注释，空行忽略，保存即生效。
- 普通行 = 包含匹配（不分大小写），只要消息里出现这个词就算命中。
- `re:` 开头的行 = 正则表达式（自动忽略大小写），例如 `re:wxid_[A-Za-z0-9_-]+`。
- 正则写错会被忽略并记录警告，不影响其他词条。
- 建议不要启用过宽的正则（如 QQ 号、URL 全匹配），会误伤正常聊天；`hard_blacklist.txt` 和 `soft_blacklist.txt` 里已把这类示例注释掉，需要时自行取消注释。

## 用量记录

每次模型调用（含判定为沉默的调用）、主动回复真实触发结果、功能路由判断和本地功能执行都会追加一行到 `data/tangtang/usage/` 当日文件。记录包含时间、事件、模式、模型、延迟、输入/输出/推理 token、缓存 read/write/miss、工具回合、稳定前缀与工具 Schema hash、各上下文层字符数和不可逆请求 trace。供应商不返回缓存字段时写 `cache_status=unsupported`，不会用零伪装成未命中。日志不保存群号、用户 QQ、消息号、原始请求号、消息正文、提示词、端点或密钥；`detail` 只保存受控状态码和类型。主动回复的冷却/间隔/概率未命中不会逐条记录，只记录真正触发后的结果。

聊天、功能识别、人格后台和画像模型的每次 HTTP 请求携带 `X-Request-Timeout-Ms`，值为本次客户端超时与 30 秒的较小值。支持该请求头的本地转发服务必须在期限内结束整条请求链路，超时中止上游连接，不因切换渠道重新计时；客户端提前断开也取消转发。此期限按单次 HTTP 请求计算，画像任务的多次调用与原有重试仍分别计时。直接连接不支持该请求头的接口时，仍由原有客户端超时控制；上线前需同步更新本地转发服务。

## 热更新 vs 重启

| 内容 | 方式 |
| --- | --- |
| `TANGTANG_*` 环境变量 | 热更新（mtime 检测，改完保存即生效） |
| `persona.md`、两份词表、`lines.txt` | 热更新（每次使用前重读） |
| 代码/插件改动、文件路径变更 | 需要重启 NoneBot |

## 与旧功能的关系

- 随机表情、随机复读、三连复读完全不受影响，一条消息可能同时出现复读和糖糖回复。
- 开启主动回复后，未呼叫的普通消息也可能出现糖糖主动回复；与复读类被动互动的重叠可通过各自概率/冷却调整。
- 全局主动／被动过滤和本群过滤名单中的用户不能触发回复或功能互动，也不进入对话文本、图片上下文；日常发言计数保留。
- 旧 AI 群聊助手（`ai.py` 及 `AI_*` 配置）已整体移除；糖糖不依赖任何旧 AI 配置、数据库或代码。

## 与 .env 的同步

- 糖糖与画像的 `TANGTANG_*`、`PROFILE_*` 参数直接读 `.env`，保存即热更新；
- `#糖糖模型 <档案名>` 只更新 `TANGTANG_MODEL_ACTIVE_PROFILE`；档案内容仍只能手动维护，QQ 回复不会显示端点或密钥；
- 被呼叫会话和糖糖主动聊天的机器人级成本总控保存在 SQLite，由 `#系统设置` 热更新；群级意图同样保存在 SQLite；
- `TANGTANG_PROACTIVE_PROBABILITY`、`TANGTANG_PROACTIVE_COOLDOWN_SECONDS` 和 `TANGTANG_PROACTIVE_MESSAGE_INTERVAL` 都是逗号分隔列表，按 `TANGTANG_GROUP_IDS` 的顺序逐群对应；每个有效群必须恰好有一个值；
- `#糖糖主动回复` 指令修改主动回复参数时会将同一个值写入全部糖糖群的对应列表项；需要不同群采用不同值时，直接编辑 `.env` 中的列表；
- 群登记、群域和功能开关由 `#群设置` / `#系统设置` 写入 SQLite，不反写 `.env`；旧群列表只作为首次迁移种子；
- 随机复读和三连复读的逐群运行参数持久化到 SQLite；`.env` 列表只用于旧配置迁移和机器级默认值。

## 如何开启思考模式

把 `TANGTANG_REASONING_EFFORT` 从 `none` 改为 `low`、`high` 或 `max` 即可（`.env` 保存即热更新）。`responses` 和 `chat_completions` 两种接口风格都会生效：关闭时发送 `thinking.type=disabled`；开启时发送 `thinking.type=enabled`，`responses` 风格带 `reasoning.effort`，`chat_completions` 风格带顶层 `reasoning_effort`。只接受官方取值 `none/low/high/max`，其他值会导致配置校验失败、功能自动关闭。

注意：思考模式会额外消耗推理 token，回复延迟也会变高；如果只是日常群聊，建议保持 `none`。
