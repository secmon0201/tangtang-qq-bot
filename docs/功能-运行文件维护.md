# 功能：运行文件维护

机器人启动时立即执行一次运行文件回收，此后每 6 小时执行一次。维护只处理可重建缓存、网页截图和游戏日志，不读取或删除玩家数据、业务数据库、登录状态与灾备文件。

## 保留策略

| 范围 | 策略 | 明确保留 |
| --- | --- | --- |
| `data/avatar_cache` 与 `groups` | 每个 QQ 只保留当前会被读取的一张头像；刷新成功后立即删除全部旧版本 | 当前头像 |
| `data/reports/asoul_html` | 使用 `REPORT_RETENTION_HOURS`，默认 24 小时；即使全部过期也保留最新一张 | 最新截图 |
| `data/reports/community_html` | 使用 `REPORT_RETENTION_HOURS`，默认 24 小时；即使全部过期也保留最新一张 | 最新截图 |
| `GsUID.Core/data/logs` | 先删除超过 30 天的日志，再按最旧优先压缩到 256 MiB 以内 | 最新日志文件 |

游戏日志治理完全由项目侧只读定位并删除日志文件，不修改 `GsUID.Core`、NTEUID 或 XutheringWavesUID 源码。`GsUID.Core/data/GsData.db`、玩家目录及其他游戏数据不在清理根目录内。

每轮结果写入 NoneBot 日志，包含各范围扫描数、删除数和释放空间。单个正被占用的文件若因 Windows 文件锁无法删除，会在下一轮重试，不阻塞其他机器人功能。

实现和边界测试见 `bot/services/runtime_retention.py`、`bot/plugins/runtime_maintenance.py` 与 `tests/test_runtime_retention.py`。
