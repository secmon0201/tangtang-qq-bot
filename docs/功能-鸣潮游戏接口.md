# 鸣潮游戏接口

## 功能边界

鸣潮使用 XutheringWavesUID，上游普通查询、登录、面板、抽卡和攻略命令继续由 GsUID Core 处理。项目侧只接管 `ww` 命令门、帮助图和排行榜；兼容 `#ww`、`ww`、`ww ` 及大小写变体。原神等其他游戏前缀保持禁用。

鸣潮是一项默认开启的独立群功能：新加入的受管群和升级前已存在的受管群都会单独保存 `ww=开`，不继承也不改写 NTE 的群开关。本群管理员可用 `#群设置 鸣潮 开|关` 或 `#开关鸣潮` 修改当前群开关。超级管理员私聊 `#系统设置 游戏接口 开|关` 控制 NTE 与鸣潮共用的全局运行条件；全局关闭不会覆盖任何群设置。

## 排行榜

- `#ww<角色>排行`、`#ww<角色>声骸排行`、`#ww练度排行`、`#ww最强排行`：只看当前群。
- 对应的 `总排行`：只看当前机器人本地保存的全部鸣潮绑定与面板缓存。
- 支持 `页2` 或 `第2页`，每页最多 100 条；本人不在当前页时追加真实名次。
- 不提供 A 海岸鸣潮榜，不请求上游公共总榜，也不会把私有集群当作鸣潮统计范围。

榜单保留角色、等级、共鸣链、武器、武器等级、谐振等级、声骸套装和评分，并补充 QQ 头像、QQ 昵称、UID、来源群和群代称。数据读取链为 `GsData.db:wavesbind`、`data/XutheringWavesUID/players/<uid>/charListData.json` 和压缩或明文 `rawData.json`，全部只读。

## 帮助

`#ww帮助` / `ww帮助` 生成项目重构帮助图；`#ww原版帮助` 使用 `scripts/export_wuwa_original_help.py` 生成的本地上游快照。管理员和 Bot 主人命令不进入普通帮助图。

## 登录地址

`#ww登录` 使用 `https://tangtang.secmon.cn/waves/i/<临时令牌>`。固定隧道启动脚本会把 XutheringWavesUID 的 `WavesLoginUrl` 写为该 HTTPS 域名，并打开 `WavesLoginUrlSelf`，然后按需重启 Core 使配置生效。

统一网关只向 Core 转发鸣潮临时登录页及其提交接口；`/waves/panel-edit/*`、`/waves/gacha/*`、`/waves/fonts/*`、外置登录服务接口、`/ws/*` 和 `/api/*` 均不公开。手机号、验证码、邮箱、密码、Cookie 和登录态只在用户浏览器、Core 与库洛登录接口之间处理，不经过 NoneBot，也不写入项目日志。

## 既有数据导入

外部数据尚未提供时不得执行真实导入。收到既有 Bot 的 `GsData.db` 和 `XutheringWavesUID/players` 后，先运行 dry-run：

```powershell
.\.venv\Scripts\python.exe scripts\import_wuwa_data.py --source-db 'D:\旧机器人\data\GsData.db'
```

审计结果只输出表行数、用户数、UID 数、玩家目录数和冲突摘要，不输出 Cookie、Token 或登录信息。只有确认来源严格限于 A 海岸五群后，先停止 GsUID Core，再增加 `--apply`；工具会先备份目标数据库和冲突玩家目录，再按自然键合并且不复制源表自增 ID。导入完成并验证表行数与榜单后再启动 Core。

## 上游边界

不得修改或提交 `GsUID.Core`、XutheringWavesUID 及其数据库、玩家缓存和登录状态。上游版本只记录在 `config/upstream-lock.json`，更新后运行 `scripts/validate_upstream_lock.py` 与 `scripts/validate_nte_mode.py`。
