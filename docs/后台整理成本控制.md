# 后台整理成本控制

群摘要、个人事实、个人画像共享请求记账方式，各自使用滚动一小时预算。前台聊天和识图不占这些预算。原始消息、证据、画像版本均保留；预算不足只是推迟分析。

## 实际行为

- 群摘要默认 Low，一群一批一次请求，模型同时判断话题归属并返回各话题更新。不再逐话题单独调用路由器、Max 摘要及即时格式修复。完整验证所有来源恰好覆盖一次后，整批摘要和游标在同一事务提交。
- 群消息累计 40 条或最老消息等待 240 秒后可处理，成功后至少等待 240 秒。每批默认最多 60 条，且不超过原有配置的读取上限；新增原文通常不超过 18000 字符。单条超长消息完整保留并独占一批，不为限制预算裁掉证据。候选旧话题最多 12 个，按本批内容相关性优先。
- 群摘要失败按群持久化退避：60 秒起，指数增长到 1 小时，并逐步缩小重试批次；网络和服务权限错误另受上游熔断控制。重启不会清空退避。既有 6 小时待处理消息时效规则保留，跳过只推进摘要游标，不删除原始消息。
- 个人事实继续无思考。前台成功聊天的提取回执继续复用。后台优先直接交流和近 24 小时证据；普通旁听至少等待 180 秒，最多合并同一人、同一群、同一时效类别的 48 条消息及 12000 字符。不会把不同群的原始会话混成同一批，也不按短消息长度判定无价值。
- 画像继续无思考，发生变化的结论仍独立复核。初次画像和直接交流优先；已有画像的普通更新默认间隔 900 秒，失败重试和已生成草稿的复核除外。九次优先调度后给最久等待者一次机会，历史调用仍受独立预算约束。
- 画像优先选择近 24 小时的未处理证据；没有这些证据时才选择历史批次，避免新消息夹带大量历史积压绕过历史限额。旧结论引用的原文可作为核对上下文带入，但不据此推进尚未读完的原文覆盖范围，也不用于把历史批次误标成实时批次。
- 草稿与上一份已审画像完全相同时，仅确认本批证据已分析，不创建重复画像版本，也不复核没有改变的结论。证据版本、租约及黑名单仍须校验。
- 画像内容校验失败回到草稿阶段，跨草稿/复核保留尝试计数，三次内容失败后保留失败任务及上次有效画像。网络失败复用已验证草稿；恢复时使用相同证据页，不错移长消息的截取位置。
- 个人记忆 SQL 约束冲突按单项保存点回滚并记录 `memory_constraint_conflict`，其他有效项可以提交，失败来源继续待处理；本地数据库错误不再触发模型权限故障的全天暂停。启动仅恢复旧版本遗留的 `background_internal_error` 熔断，不清除认证/额度错误。
- 排队最长 45 秒，取得容量后再计实际请求时限。群摘要为 120 秒，事实及画像为 60 秒；后台共享一个请求槽，前台有优先权。本地排队超时记为 `deferred_queue`，未发请求、不占付费预算、不触发上游故障熔断。事实租约为 180 秒，画像租约为 300 秒，覆盖排队、生成和复核。

## 初始小时预算

| 类型 | 最多尝试数 | Token 预算 |
| --- | ---: | ---: |
| 群摘要 | 120 | 600000 |
| 个人事实 | 60 | 300000 |
| 画像草稿及复核合计 | 80 | 800000 |
| 超过 24 小时的事实及画像证据，合计额外限制 | 12 | 150000 |

历史批次同时占所属任务预算和历史预算。请求发出前按 UTF-8 输入字节数加输出上限保守预留，返回后用供应商报告的 Token 结算；失败、取消或无用量报告时保留预留值。因此它是费用控制的近似上界，不是货币账单，缓存折扣也不等于少占输入 Token。限制是上限而非要消耗完的配额，不承诺固定节省比例。

## 查看与调整

```powershell
.\.venv\Scripts\python.exe scripts\background_work_policy.py --hours 1
.\.venv\Scripts\python.exe scripts\background_work_policy.py --set summary_wait_seconds 300
.\.venv\Scripts\python.exe scripts\background_work_policy.py --set history_requests 8
```

默认只读输出，`--set` 才写入 `data/personas/state.db` 的 `background_work_policy`，现有进程下轮读取即生效。请求或 Token 预算设为 0 会暂停对应类别的付费整理。恢复默认值时将该键设回本页值即可；不要删除来源表、游标或历史版本来重置费用。

请求账本 `background_work_calls` 每次尝试只占一行，记录任务类别、证据批次哈希、来源数量、是否历史、时间、结果和用量，不存提示词或 API key。`jobs.usage.background_request_id` 关联具体返回请求，画像发布记录用批次哈希关联。`returned` 仅表示模型已返回，是否发布应结合 `jobs` 和任务队列判断，不把两处日志相加当成请求数。可用 `--since` 指定含时区的 ISO 起点复核部署窗口。

验收先验证原子提交、回放幂等、否定更正、跨用户/跨群隔离、预算持久化和失败恢复，再比较相同消息量下的费用、学习延迟和更正遗漏率。测试通过和请求量下降不能单独证明记忆质量保持不变。
