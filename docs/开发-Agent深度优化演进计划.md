# 开发：Agent 深度优化演进计划

本文是达妮娅/糖糖聊天运行时在完成 Q0～Q8 基础架构改造后，开展深层次性能、可用性与成本优化的演进台账。本文严格遵守架构分层原则，不记录实例群号、用户真实身份、API 密钥、端点或聊天正文。

## 前置基准（Q0～Q8 达成状态）

截至 2026-10-03，前置 Agent 上下文与工具调用改造已全面验收闭环：
1. **Schema 稳定收敛**：36 项原生工具（2 知识检索、22 只读读取、12 显式状态操作）全部类型化并在模型端稳定运行，单批次最多单写、防重入、防跨群串扰。
2. **缓存优化打通**：在 GPT-5.6 Luna（模型 3）端点下，实盘生产缓存命中时中位数达到 **81.45%**（峰值 95.9%），加权覆盖率 63.39%，同场景非缓存输入压降超 80%。
3. **呼叫鲁棒性加固**：呼叫忽略率清零（100% 呼叫响应），并引入 2 次指数退避短重试（1.0s, 2.0s）抑制偶发 502/网络抖动，最终失败静默丢弃，消除机械兜底语。

## 不变边界与工程红线

- 所有现有 # 指令继续保留，自然语言工具入口与指令入口底层复用同一业务处理器。
- 严禁向模型注入管理、维护、清理、封禁或直接执行系统/上游命令的能力；模型提出工具调用不等于已授权。
- 保护上游独立性：不修改 GsUID.Core、NTEUID 或 XutheringWavesUID 源码；适配器只读且快速失败。
- 零敏感信息泄露：生产 usage 报告只记录聚合统计与脱敏哈希，不持久化正文、群号或密钥。
- 运维约束：普通改动仅平滑重启 NoneBot；严禁重启 SnowLuma 或 QQNT 进程，严禁破坏既有登录态。

### 阶段一（Q9）：彻底退役旧版 eature_calls 提示词与兼容协议残余

- **背景与痛点**：
  在 Q0～Q8 阶段为保证灰度兼容，系统仍保留了部分历史 eature_calls 规则与防御分支。目前 36 个原生工具已 100% 稳定运行，旧协议说明在每次请求中产生不必要的静态 Token 消耗（约 400～600 Token）。
- **实施内容**：
  1. **Prompt 瘦身**：从 System Prompt 及对话上下文构造中彻底剔除旧版 eature_calls 指南文本，净化模型注意力；
  2. **协议收拢**：将响应解析层中的 eature_calls 降级为只读防御兜底（不再主动引导模型输出），完全收敛至 OpenAI 原生 	ool_calls 标准协议；
  3. **用例与文档对齐**：更新契约测试，确保已有 1600+ 项测试用例全部通过。
- **验收指标**：
  - System Prompt 静态 Token 减少 400+；
  - 36 个原生工具全部正常响应；
  - 完整门禁与测试套件 100% 通过。

### 阶段二（Q10）：Cache TTL 智能续热与冷启动消除（Smart Cache Warmer）

- **背景与痛点**：
  当前实盘中 ~22.7% 的未命中请求主要发生在群内长时间静默（超过 5～10 分钟）后，供应商端 Prompt Cache TTL 过期所致，导致活跃群突发交流的首句需消耗全量冷启动 Token 并伴随较高延迟。
- **实施内容**：
  1. **活跃群识别**：统计日间（09:00～23:30）高频交互群会话热度，仅对有对话预期的活跃群进行保活；
  2. **影子心跳续热**：采用极低 Token 消耗的轻量前缀探针请求（零业务负载、不发 QQ 消息、仅发送系统前缀与空上下文），在 TTL 临界前周期性续热；
  3. **安全与静默约束**：夜间（23:30～09:00）完全静默；遇到不可用或非活跃群自动跳过，严格限制单日探针预算。
- **验收指标**：
  - 活跃群白天首句冷启动缓存命中率提升至 80%+；
  - 全量加权缓存覆盖率由 63.39% 提升至 80%+；
  - 探针日志完全脱敏且不产生任何用户可见副作用。

### 阶段三（Q11）：自适应滑动窗口熔断降级与多模型故障自动逃生（Circuit Breaker）

- **背景与痛点**：
  目前模型 3（GPT-5.6 Luna）遇到上游偶发 502/超时已实现 2 次短重试，但若遭遇分钟级上游服务中断，仍会导致请求静默失败。
- **实施内容**：
  1. **滑动窗口熔断器**：在 TangtangProvider 引入状态机（Closed / Open / Half-Open），统计最近 1 分钟内的 502/504/超时错误频次；
  2. **故障平滑逃生**：当连续失败达到阈值（如连续 3 次）时触发熔断，后续请求自动无缝降级到备选模型 Profile（如模型 4 或模型 1），确保聊天不中断；
  3. **后台自愈探测**：熔断期间由后台轻量心跳探针探测主模型连通性；一旦连续 2 次成功，熔断器自动半开并恢复模型 3。
- **验收指标**：
  - 模拟上游长时间故障时，群聊自动降级无丢包；
  - 主模型恢复后无缝切回，无需人工重启或修改配置。

### 阶段四（Q12）：细粒度语义感知压缩与长对话 Token 预算控制（Semantic Compaction）

- **背景与痛点**：
  当前历史压缩机制主要按固定轮次进行粗粒度摘要，超长对话（30～50 轮以上）累积仍可能消耗过多 Token。
- **实施内容**：
  1. **Token 预算感知驱动**：不仅依据轮次，而是根据实时 Token 水位动态评估压缩时机；
  2. **关键语义资产保护**：在压缩摘要算法中，强制保护用户个性称谓、情感羁绊标签、当前核心事件及未结上下文，剔除陈旧工具状态与闲聊废话；
  3. **持久化快照增量演进**：保持快照派生特性，超长会话（>50 轮）的上下文 Token 消耗稳定收敛在预设的安全常数区间。
- **验收指标**：
  - 50 轮持续对话的非缓存增量输入波动范围可控；
  - 用户画像与群聊记忆关键事实保真度 100%。

## 阶段验收与推进原则

1. **单阶段自闭环**：每一阶段必须包含代码修改、自动化测试、真实/合成回放与全套工程校验器验证，严禁跨阶段堆积。
2. **可逆回退保障**：每个功能改动均提供配置开关或原子撤销手段，上线出现非预期行为可在 1 分钟内回退。
3. **分步实施**：按照 Q9 -> Q10 -> Q11 -> Q12 严格单线推进。
