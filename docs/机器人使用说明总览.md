# QQ 群机器人使用说明总览

本文档是本项目当前版本的统一操作手册。项目运行在 Windows 本机，技术链路为 `NoneBot2 -> OneBot v11 -> NapCat/QQNT`，业务数据保存在本地 SQLite。

NapCat 连接维护由 NoneBot 本地定时任务负责：默认每 30 秒检查一次 OneBot 反向 WebSocket，并在“已连接后断开”时将时间、QQ.exe 进程快照和恢复耗时写入 SQLite。它不尝试绕过 QQ 登录验证，也不保存 OneBot Token 或 NapCat 日志原文。超级管理员可通过 `#NapCat维护状态` 和 `#NapCat离线记录 [1-20]` 查询。

## 1. 重要规则

- 群内和私聊的全部机器人命令统一使用 `#指令 [参数]`；普通用户、活动管理员和超级管理员使用相同前缀，再由命令检查各自权限。
- 不再使用 `@机器人 命令`、无前缀命令或按身份区分前缀。
- 普通群消息不会被机器人读取，也不会触发命令。
- 被动互动是唯一允许读取指定群普通发言的功能，且只在已启用的被动互动群生效。
- 报名和取消报名成功后，机器人只给原消息添加“续标识”表情，不发送文字确认。
- 普通聊天中的 @ 提及不作为命令前缀；命令结果仍以文字或图片反馈为准。
- 所有业务功能范围都必须是 `MANAGED_GROUP_IDS` 的子集。`MANAGED_GROUP_IDS` 仍需在 `.env` 中维护，最多 10 个群。
- 热更新的范围、被动互动参数和过滤名单会永久写入 SQLite，重启后保留。
- QQ 扫码、滑块、设备验证等安全验证必须人工完成。本项目不绕过登录验证，也不提供反检测、注入伪装或指纹伪造方案。
- 普通用户可发送 `#帮助` 获取长图片总览；发送 `#帮助文字` 会以合并转发提供仅含可复制指令的文字版，避免刷屏。

## 2. 首次安装与配置

在项目根目录打开 PowerShell：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

编辑 `.env`，至少确认以下项目：

```dotenv
MANAGED_GROUP_IDS=群号1,群号2
BOT_OPERATOR_IDS=管理员QQ号1,管理员QQ号2
ACTIVITY_ADMIN_IDS=活动管理员QQ号1,活动管理员QQ号2
ACTIVITY_ADMIN_BLACKLIST_IDS=不自动获得活动管理员权限的QQ号1
NAPCAT_QQ_ID=机器人QQ号
BOT_COMMAND_PREFIX=#
BOT_REQUIRE_MENTION=false
BOT_RESPONSE_DELAY_MIN_SECONDS=2
BOT_RESPONSE_DELAY_MAX_SECONDS=5
BOT_COMMAND_RESPONSE_DELAY_MIN_SECONDS=1
BOT_COMMAND_RESPONSE_DELAY_MAX_SECONDS=2
BOT_ONEBOT_API_MIN_INTERVAL_SECONDS=2
```

`MANAGED_GROUP_IDS` 是最高层的管理范围，不能通过群内命令修改；修改后需要重启机器人。统计、查重、游戏、活动、被动互动和整点报时的具体范围均可以通过超级管理员命令热更新。`HOURLY_ANNOUNCEMENT_*` 只作为整点报时的初始配置，运行中以 SQLite 和管理员命令为准。`ACTIVITY_ADMIN_IDS` 用于额外指定活动管理员；活动有效群内的群主和群管理员默认也拥有活动管理员权限，`ACTIVITY_ADMIN_BLACKLIST_IDS` 可排除指定 QQ。它们均属于启动身份配置，修改 `.env` 后需要重启；活动管理员不等同于超级管理员，也不能管理别人创建的活动。

机器人不从 `.env` 读取 QQ 密码。先使用 NapCat/QQNT 完成人工登录，然后在 NapCat 中配置反向 WebSocket：

```text
ws://127.0.0.1:8080/onebot/v11/ws
```

修改 `HOST` 或 `PORT` 后，NapCat 的反向 WebSocket 地址也必须同步修改。

启动前建议验证配置：

```powershell
.venv\Scripts\python.exe scripts\validate_qq_config.py --env .env
```

## 3. 启动、关闭与守护

### 一键启动

双击项目根目录的 `start_bot_and_napcat.bat`。它会：

1. 启动 GsUID Core；
2. 启动 NoneBot 机器人；
3. 启动配置的 NapCat/QQ；
4. 未被用户主动禁用时启动 NTE 登录隧道；
5. 启动 NapCat watchdog 守护窗口。

如果 QQ 要求扫码、滑块或设备验证，在 NapCat/QQ 窗口中手动完成。批处理不会绕过验证。

### 一键重启

双击 `restart_bot_and_napcat.bat`。它会按“关闭整套环境 -> 等待端口释放 -> 启动 Core、机器人和 NapCat -> 按原选择启动 NTE 登录隧道 -> 启动 watchdog”的顺序执行。普通 Python 代码更新只需使用 `restart_nonebot.bat`，这样不会中断 QQ/NapCat。

### 一键关闭

双击 `stop_bot_and_napcat.bat`。它会关闭 watchdog、NTE 登录隧道、能够确认归属的 NapCat QQ、机器人和 GsUID Core，同时保留隧道原本的启用选择。不会调用 `NapCat.Shell\KillQQ.bat`，也不会关闭无法确认属于本项目的其他 QQ。

只启动或关闭守护程序：

```text
start_watchdog.bat
stop_watchdog.bat
```

### 手动运行机器人

前台运行：

```powershell
.\scripts\start.ps1 -Foreground
```

后台运行并查看日志：

```powershell
.\scripts\start.ps1
Get-Content .\logs\bot.out.log -Wait
```

手动停止、备份：

```powershell
.\scripts\stop.ps1
.\scripts\backup.ps1
```

### watchdog 行为

watchdog 每 30 秒检查一次机器人监听和 OneBot 连接。连续 3 次检查失败后才恢复，机器人恢复冷却 5 分钟，NapCat 恢复冷却 15 分钟。处于扫码或验证状态的 QQ 不会被反复关闭重启。

日志位置：`logs\napcat-watchdog.log`。

一次性只读检查：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\watch_napcat.ps1 -Once
```

watchdog 只能恢复本地进程，不能处理扫码、滑块、设备验证或账号封禁。

## 4. 群内消息与响应逻辑

标准格式：

```text
#命令 参数
```

例如：

```text
#活动大厅
#报名 500
#机器人状态
```

机器人识别到 # 命令后会按响应延迟配置等待一段时间，OneBot API 调用之间也有最小间隔。不要通过高频轮询或连续重发实现秒回。

非命令普通消息：

- 不会触发以 # 开头的普通命令、活动、查重或游戏；
- 只有被动互动范围内的群会进入随机表情/随机复读处理；
- 被动互动会阻断该条消息继续进入其他命令处理；
- 机器人自身发言、过滤名单用户不参与被动互动。

## 5. 跨群活动

活动只在活动功能范围内的群可用。所有角色统一使用 # 前缀，也支持 `#报名517`、`#报名 517`、`#报名：517` 和 `#报名#517`。超级管理员、`ACTIVITY_ADMIN_IDS` 中的活动管理员，以及活动有效群内的群主和群管理员都可以创建活动；`ACTIVITY_ADMIN_BLACKLIST_IDS` 中的成员不会获得自动活动管理员权限。配置的活动管理员可以私聊管理自己创建的活动；自动识别的群管理员需在活动有效群内使用管理命令。超级管理员可以管理全部活动，活动管理员不能管理他人活动。

常用命令：

```text
#活动帮助
#活动管理员帮助
#活动大厅
#活动详情 ID
#查看名单 ID
#获奖名单 ID
#报名 ID
#取消报名 ID
#我的活动
```

创建活动格式：

```text
#创建活动 活动名：周末联动
开始时间：2026-07-20 20:00
结束时间：2026-07-20 22:00
类型：通报
说明：周末团建
参与群：1067772451,278824712
隐私：公开
```

示例：

```text
#创建活动 活动名：跨群抽奖
开始时间：2026-07-20 20:00
结束时间：2026-07-20 22:00
类型：抽奖
说明：报名抽奖
奖项：一等奖=1；二等奖=2
参与群：1067772451,278824712
隐私：脱敏
```

管理活动：

```text
#修改活动 活动ID：517
活动名：新标题
结束时间：2026-07-20 22:30
隐私：公开
#提前结束 ID
#取消活动 ID [原因]
```

修改活动时，每项单独换行；未填写或留空的字段保持原值，例如：

```text
#修改活动 活动ID：500
活动名：新标题
说明：新说明
```

参与群、活动类型、奖项和公开/脱敏设置都可以修改；进行中的活动仅超级管理员可以修改，普通用户和活动管理员均不能修改。修改后会向所有参与群发送最新活动信息；修改参与群后，退出的群只收到“该活动已不支持本群”的图片，新加入和原有群收到完整活动更新图片。活动 ID 从 500 起连续生成，旧 ID 不会因重启改变。`取消活动` 是软删除，会冻结报名并保留审计记录；不会物理删除活动。报名、重复报名和取消报名只在原消息添加“续标识”表情。活动大厅、详情、名单和状态通知使用本地生成的图片或合并转发。

## 6. 被动互动

### 启用和移除群

推荐使用统一的功能范围命令：

```text
#功能范围 被动 添加 QQ群号
#功能范围 被动 移除 QQ群号
#功能范围 被动 列表
```

也支持专用命令：

```text
#被动互动群 添加 QQ群号
#被动互动群 移除 QQ群号
#被动互动群 列表
```

移除就是使用 `移除` 或 `删除`，不是再次添加。目标群必须已经在 `MANAGED_GROUP_IDS` 中。

### 查看逐群状态

```text
#被动互动状态
#被动互动状态 QQ群号
#功能范围 列表
```

反馈会尽量显示群头像、群名称和群号，并列出该群的互动状态。每个群都有独立配置，不会因为修改一个群而影响其他群。

### 随机表情

```text
#表情命中率 QQ群号 30%
#表情冷却 QQ群号 10
```

命中率单位为百分比，冷却单位为秒。当前实现允许管理员自行调整范围，不强制最低值；建议表情冷却至少 10 秒，避免过密发送。

### 随机复读

```text
#复读命中率 QQ群号 10%
#复读冷却 QQ群号 15
#复读间隔 QQ群号 50
```

命中率单位为百分比，冷却单位为分钟，间隔单位为消息条数。只有纯文本且长度合适的消息才可能复读。建议复读冷却至少 15 分钟、消息间隔至少 50 条，但这些建议不是强制限制。

### 三连复读

```text
#三连复读 QQ群号 开启
#三连复读 QQ群号 关闭
#三连复读 QQ群号 状态
#三连复读 QQ群号 概率 30%
#三连复读 列表
```

同一群连续出现三条相同纯文本时，开启后机器人按该群的命中概率额外复读一次，默认 30%。该复读不占用随机复读冷却，也不会刷新随机复读冷却；概率未命中时，这条消息仍可正常进入随机复读判断。过滤名单用户和机器人自身消息不会参与三连判断。

### 糖糖主动回复

在“糖糖”/@ 被动呼叫之外，糖糖还可以对未呼叫的普通群消息按概率主动接话。主动回复由超级管理员控制：

```text
#糖糖主动回复 状态
#糖糖主动回复 开启
#糖糖主动回复 关闭
#糖糖主动回复 概率 5%
#糖糖主动回复 冷却 30
#糖糖主动回复 间隔 50
```

命中率、冷却和消息间隔同时决定主动回复频率。`TANGTANG_PROACTIVE_PROBABILITY`、`TANGTANG_PROACTIVE_COOLDOWN_SECONDS` 和 `TANGTANG_PROACTIVE_MESSAGE_INTERVAL` 均按 `TANGTANG_GROUP_IDS` 顺序使用逗号分隔列表逐群配置。上述指令会将同一值写入全部主动群；要设置不同群参数，直接编辑 `.env` 中对应列表项。随机复读与三连复读也按 `BOT_RANDOM_REACTION_GROUP_IDS` 的顺序使用同样的逐群列表，群内管理指令只更新当前群的列表项和 SQLite 记录。主动回复与随机表情、随机复读、三连复读并行，同一条消息可能同时触发；可通过复读侧概率/冷却/间隔单独调低。被动过滤名单用户和机器人自身消息不参与。

### 主动与被动过滤名单

```text
#主动过滤 QQ号1,QQ号2,QQ号3
#移除主动过滤 QQ号1,QQ号2,QQ号3
#主动过滤 列表

#被动过滤 QQ号1,QQ号2,QQ号3
#移除被动过滤 QQ号1,QQ号2,QQ号3
#被动过滤 列表
```

两份名单互不影响，支持英文逗号、中文逗号或空格批量分隔 QQ 号，名单变更即时生效并永久保存。

- 主动过滤：被过滤用户发送的所有 `#` 指令，包括小游戏操作，都会静默无效。为避免超级管理员误加自己后无法恢复，过滤管理指令仍允许该超级管理员使用。
- 被动过滤：被过滤用户不会触发随机表情、随机复读、三连复读或 `@机器人` 的自动表情；其消息也不会进入糖糖聊天记忆。

## 7. 整点报时

整点报时默认关闭，分段文案池位于 `bot\resources\zhijiang_hourly_copy.json`，花名分类位于 `bot\resources\zhijiang_character_aliases.json`。四个时段各有前、中、后三段素材，每个分段至少维护 100 条独立素材；运行时随机组合并随机填充分类花名，理论组合数由 `python scripts/generate_hourly_copy.py` 校验。开启后，机器人只会在指定时段的整点向指定群发送一条文案；每个群每个整点最多一条。

管理员命令：

```text
#整点报时 状态
#整点报时 开启
#整点报时 关闭
#整点报时 时段 09:00 23:00
#整点报时 范围 添加 QQ群号
#整点报时 范围 移除 QQ群号
#整点报时 范围 列表
```

也可以使用统一的功能范围命令：

```text
#功能范围 整点报时 添加 QQ群号
#功能范围 整点报时 移除 QQ群号
#功能范围 列表
```

时间段支持跨午夜配置，例如 `22:00 02:00` 表示 22 点、23 点、0 点、1 点和 2 点。发送任务每 30 秒检查一次；整点发送失败后，只在该整点后的 5 分钟内按配置有限重试，最多 3 次，重启不会重复发送同一群同一整点的成功记录。

启停、时段和群范围都会永久保存到 SQLite。管理员反馈会显示群头像、群名和群号。文案池修改后需要重启机器人才能重新加载，未来可再增加文案池热更新命令。

## 8. 其他功能命令

### 管理员帮助和状态

```text
#管理员帮助
#机器人状态
```

`#帮助` 面向普通用户，覆盖活动、日程、小游戏及已启用的 A 海岸统计；`#帮助文字` 以合并转发提供可复制的纯指令文字；`活动帮助` 面向活动使用说明；`活动管理员帮助` 面向 `ACTIVITY_ADMIN_IDS`；`管理员帮助` 和 `超级管理员帮助` 面向 `BOT_OPERATOR_IDS`。普通用户帮助不会展示高权限管理命令。

### 查重

查重命令只在查重功能范围内响应，且需要操作者权限：

```text
#查重1 群号1 群号2 [群号3 ...]
#查重2 起点群号 目标群号1 [目标群号2 ...]
#查重3 群号1 群号2 [群号3 ...]
#查重4 起点群号 目标群号1 [目标群号2 ...]
```

`查重1/2` 使用查重白名单，`查重3/4` 忽略白名单。旧命令 `查重` 兼容 `查重2`。

查重白名单：

```text
#白名单 添加 QQ号 [备注]
#白名单 删除 QQ号
#白名单 列表
```

### 统计

A海岸实时发言统计默认开启，只监听固定的五个 A海岸群：1128870029、1077416717、1083457871、1090284567、278824712。它不保存消息内容，只以 QQ 号聚合每日发言次数并更新最后昵称。其他群不计数。A海岸群内所有用户都可使用 `#发言排行 日|周|月|总` 查询本群，或使用 `#A海岸发言排行 日|周|月|总` 查询五群合并榜；两者均不需要超级管理员权限。两类榜单均取前 100，A海岸榜会显示用户所在群聊但不显示 QQ 号。

### 游戏扩展

#### 枝江直播自动防护

机器人会从 `ASoul-Calendar` 使用的公开 JSON 日程源读取精确到分钟的 Bilibili 直播预告。默认启动即刷新、每 5 分钟更新，开播时关闭小游戏全局总开关，最后一场开播后 60 分钟自动恢复；同一小时内的新开播会刷新倒计时。该开关只拦截本地小游戏，不影响异环游戏接口（`#nte`）。数据异常或网络失败时保留本地有效缓存，不会误改游戏开关。超级管理员仍可用 `#总游戏开` 提前恢复。

群内可用 `#枝江直播` 查看未来 7 天缓存、`#枝江直播 状态` 查看自动暂停状态；超级管理员可用 `#刷新枝江直播` 立即更新。枝江百科功能当前已屏蔽，待资料完善后再开放。完整数据来源、配置项与事实边界见：[枝江直播与百科资料说明](枝江直播与百科资料说明.md)。

游戏功能由本地 GenshinUID Core 承载，当前只启用异环，识别 NTE 前缀（可带或不带 `#`，大小写不敏感）；原神、鸣潮保持关闭。具体命令以 [GenshinUID 游戏插件使用维护手册](GenshinUID游戏插件使用维护手册.md) 为准。Core 使用本地 `127.0.0.1:8765`，与 QQ/NapCat 的 `127.0.0.1:8080` 分开。

### 糖糖聊天与发言画像

糖糖负责群聊回复，并把启用群的发言原文持久化到本地聊天记录库（`tangtang.db`）。A 海岸发言画像直接读取这份历史：A 海岸群内可使用 `#发言画像 QQ号`、`#画像 QQ号`，或以单个 `@成员` 替代 QQ 号；超级管理员私聊可使用 QQ 号形式。画像要求超过 100 条已存档纯文本发言，小雷达与发言倾向按全部历史记录计算；没有新增发言时会直接返回既有画像，不重复调用 AI。画像 AI 复用糖糖接口与思考配置，`PROFILE_*` 可独立覆盖，上限默认 16000。数据范围、画像更新方式和隐私规则见 [AI 发言画像说明](AI发言画像说明.md)。API 密钥不得提交到 Git、日志或数据库。

## 9. 热更新和永久保存

范围和被动互动管理命令需要由 `.env` 中 `BOT_OPERATOR_IDS` 的 QQ 执行。成功后会立即更新内存状态，并写入数据库；活动创建/活动自身管理则按活动权限单独判断：

- `功能范围 ...`：查重、游戏、活动、被动互动的群范围；A海岸统计范围固定，不能热更新；
- `被动互动群 ...`：被动互动群范围；
- `表情命中率`、`表情冷却`：逐群随机表情参数；
- `复读命中率`、`复读冷却`、`复读间隔`：逐群随机复读参数；
- `三连复读`：逐群开关和命中概率；
- `糖糖主动回复`：全局主动回复开关、概率、冷却和消息间隔（写回 `.env`）；
- `整点报时`：全局启停与时间段；
- `功能范围 整点报时`：整点报时群范围；
- `主动过滤`、`被动过滤`：两份独立的全局过滤名单；
- `白名单`：查重白名单。
- `ACTIVITY_ADMIN_IDS` 中的活动管理员：可以创建活动，并修改、取消、提前结束自己创建的活动；不能管理其他创建者的活动。

重启机器人后这些设置会从 SQLite 恢复。数据库路径由 `.env` 的 `BOT_DB_PATH` 或项目默认配置决定，通常位于 `data` 目录。修改 `MANAGED_GROUP_IDS`、机器人账号、OneBot 地址或代码级功能开关后，需要重启。

## 10. 备份与日志

备份数据库和运行数据：

```powershell
.\scripts\backup.ps1
```

常用日志：

```text
logs\bot.out.log       机器人标准输出
logs\bot.err.log       机器人错误输出
logs\napcat-watchdog.log  NapCat watchdog
data\                  SQLite、报告、头像缓存等本地数据
```

不要把 `.env`、Token、Cookie、密码或扫码信息发到群里，也不要将其提交到 Git。群聊原文不会作为统计数据持久化；三连复读的短期判断状态只保存在内存。

### Codex 测试群通知

启用 `CODEX_COMPLETION_NOTIFY_ENABLED=true` 后，机器人仅在本机接口接到请求时，向 `.env` 固定配置的群和超级管理员发送通知。目标群必须属于 `MANAGED_GROUP_IDS`，目标账号必须属于 `BOT_OPERATOR_IDS`，启动和配置校验都会检查；接口仅允许 `HOST=127.0.0.1`、`localhost` 或 `::1`。

Codex 任务完成后，通知会先将最终交付内容发送为可展开的“Codex 执行结果”合并转发，再 `@` 超级管理员提示查看。调用方必须显式传入最终面向用户的结论、改动和验证结果；脚本不会自行读取思考过程、终端日志或群聊内容。

同一组开关还提供 `scripts\notify_test_group.py`，用于把测试用例、完成通知或普通通知连同项目目录内的 PNG/JPG/GIF/WebP 图片，作为“测试群通知”合并转发到固定群。它不接收群号或 QQ 号，也不允许工作区外附件：

```powershell
.venv\Scripts\python.exe scripts\notify_test_group.py `
  --kind test-case --title "登录冒烟" --body "预期：登录成功后进入首页。" `
  --image .\data\reports\login.png
```

### Codex 远程持续任务

超级管理员可用 `#Codex <需求>` 新建待启动任务，再用 `#启动Codex ID` 正式执行。后续使用 `#Codex 续 ID <补充需求>` 会恢复同一 Codex 会话，不会丢失该任务的上下文；还可使用 `#暂停Codex ID`、`#取消Codex ID`、`#Codex 状态 ID`、`#Codex 列表`、`#Codex 结果 ID` 和 `#Codex 重试 ID` 管理任务。worker 作为 NoneBot 的本机常驻服务运行，同一时间只处理一个任务；完整流程、状态和维护方法见 [Codex远程持续任务操作手册](Codex远程持续任务操作手册.md)。

在项目根目录执行：

```powershell
.venv\Scripts\python.exe scripts\notify_codex_completion.py `
  "Codex 已执行完成，完整结果请展开合并转发查看。" `
  --details "这里填写最终交付内容。"
```

内容较长时使用 UTF-8 文件，脚本会自动把不超过 24000 字的内容分成每页约 2000 字的合并转发节点：

```powershell
.venv\Scripts\python.exe scripts\notify_codex_completion.py `
  "Codex 已执行完成，完整结果请展开合并转发查看。" `
  --details-file .\最终交付内容.md
```

该脚本不接收群号或 QQ 号参数，固定目标不可由调用方改写；它使用本机 `.env` 中的专用令牌，留空时使用 OneBot 访问令牌。

## 11. 验收检查

修改配置或升级代码后，建议按顺序执行：

```powershell
.venv\Scripts\python.exe scripts\validate_qq_config.py --env .env
.venv\Scripts\python.exe -m pytest
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\watch_napcat.ps1 -Once
```

预期结果：配置校验通过，测试全部通过，watchdog 报告机器人监听和 OneBot 连接状态正常。NapCat 登录是否成功仍需在 QQ/NapCat 窗口和 OneBot 连接日志中人工确认。

## 12. 常见问题

### 机器人没有回复

确认消息以 `#` 开头、群在 `MANAGED_GROUP_IDS` 内、功能范围已启用，并检查 OneBot 反向 WebSocket 是否连接到 `127.0.0.1:8080`。普通用户、活动管理员、超级管理员都使用同一种 # 前缀；权限不足时机器人会直接提示。普通非命令消息按各功能规则处理。

### 被动互动没有触发

执行 `#被动互动状态`，确认目标群已加入且参数不是 0。随机表情还受命中率和冷却影响，随机复读还需要满足纯文本、消息间隔和冷却条件；过滤名单用户不会触发。

### 整点报时没有发送

执行 `#整点报时 状态`，确认功能已开启、目标群已加入、当前时间落在配置时段内，并确认机器人在整点后 5 分钟内在线。每个群每个整点只发送一条；已成功发送的整点不会重复发送。

### 重启后热更新丢失

确认机器人使用的数据库路径没有改变，并检查 `data` 目录下的 SQLite 文件是否仍在。不要用临时数据库路径启动第二个机器人实例。

### 账号需要扫码或被下线

这是 QQ/NapCat 登录状态或平台安全验证问题，watchdog 不会绕过验证。完成扫码或设备验证后再检查 OneBot 连接；不要通过高频重试、注入方式轮换、指纹伪造或代理规避来处理。

### 活动长消息发送失败

程序会记录失败并在维护周期内有限重试，超过次数后使用逐页图片回退。不要手动连续重发同一命令；先检查 NapCat 在线状态、OneBot 连接和日志中的首次失败时间。

### 需要彻底关闭

优先双击 `stop_bot_and_napcat.bat`。如果仍有残留，先运行一次 watchdog 状态检查，再根据进程 PID 和命令行确认归属后处理；不要直接使用 `NapCat.Shell\KillQQ.bat`，以免误关其他 QQ。
