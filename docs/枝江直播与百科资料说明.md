# 枝江直播防护与本地百科

## 日程源

机器人使用 `ASoul-Calendar` 实际读取的公开基础数据：

- 主数据：<https://raw.githubusercontent.com/Evelynall/ASoul-Data/main/base-schedules.json>
- 日程前端与数据格式：<https://github.com/Evelynall/ASoul-Calendar>
- 原始枝江日程站：<https://asoul.love/>

选择 JSON 数据源而不是直接抓取网页，是因为它提供每条日程的 `date`、`time`、`category`、`title` 与 `liveRoomUrl`，可稳定解析到分钟；`ASoul-Calendar` 自身也通过此基础数据加载日程。机器人只接受 `liveRoomUrl` 是 `live.bilibili.com` 的项目，线下活动、空间链接和录播链接都不会触发小游戏防护。

这是粉丝维护的公开预告数据，不是官方直播状态接口。机器人不会把抓取失败、空响应或格式异常解释成“没有直播”，而是保留上一次有效缓存；官方动态仍是信息最终依据。

## 自动规则

1. 启动时立刻刷新，之后默认每 5 分钟刷新一次；配置可改为任意 1 至 1440 分钟，5 分钟比“每小时一次”更能覆盖临时新增预告。
2. 缓存范围是当前时刻到未来 7 天，同时保留刚开始且尚在暂停窗口内的直播。缓存和已处理日程都写入本地 SQLite，因此短暂网络故障或机器人重启不会丢失已知保护窗口。
3. 到达日程开始时间后，机器人关闭现有的“小游戏全局总开关”。该开关只拦截本地小游戏，不影响异环游戏接口（`#nte`）；默认暂停 60 分钟，且不会记录或跳转录播链接。
4. 同一小时内有下一场开播时，以最后一场的开始时间重新计算 60 分钟倒计时。
5. 倒计时到期时，若小游戏总开关仍关闭，机器人自动开启它。超级管理员可在直播期间执行 `#总游戏开` 主动恢复；已处理的同一场直播不会再次关闭小游戏。
6. 日程刷新失败时不改变小游戏总开关，也不清空上次有效日程。

## 配置

`.env` 中的默认值：

```dotenv
ZHIJIANG_LIVE_GUARD_ENABLED=true
ZHIJIANG_SCHEDULE_URL=https://raw.githubusercontent.com/Evelynall/ASoul-Data/main/base-schedules.json
ZHIJIANG_SCHEDULE_REFRESH_MINUTES=5
ZHIJIANG_LIVE_PAUSE_MINUTES=60
ZHIJIANG_SCHEDULE_LOOKAHEAD_DAYS=7
ZHIJIANG_SCHEDULE_TIMEOUT=15
```

修改配置后重启 NoneBot。`ZHIJIANG_SCHEDULE_URL` 必须是 HTTP(S) 地址；禁止使用本地文件路径。需要停用自动防护时将 `ZHIJIANG_LIVE_GUARD_ENABLED=false`。

## 命令

- `#枝江直播`：查看缓存中未来 7 天、可识别的直播预告。
- `#枝江直播 状态`：查看防护开关、当前小游戏总开关、自动暂停截止时间和最近刷新状态。
- `#刷新枝江直播`：仅超级管理员可立即刷新；失败时会明确说明已继续使用本地缓存。
- `#总游戏开`：仅超级管理员可人工提前打开全局小游戏。
- `#总游戏关`：仅超级管理员可人工关闭全局小游戏。
- 枝江百科命令当前已屏蔽，等待资料完善后再恢复开放。

全部 `on_command` 命令固定使用 `#` 前缀。

## 本地百科来源与边界

本地检索资料在 `bot/resources/zhijiang_encyclopedia.json`，每一条都保留来源名称、URL 和适用说明。当前初始资料来自：

- <https://nav.asoul.us.kg/>：导航站，用于定位官方账号、日程和百科资料站。
- <https://wiki.asoul.us.kg/>：一个魂维基，覆盖团体介绍、成员角色页、枝江设定和按年份整理的公开事件。
- <https://wikisite.asoul.us.kg/>：导航站收录的社群事件资料站；其立场性内容不作为机器人事实库的直接结论。
- <https://zh.moegirl.org.cn/>：萌娘百科，用于核对企划沿革、二期生（闪耀舞台）角色页、公开歌曲与时间线；属于粉丝维护资料站。

资料库只收录可追溯的公开时间线、角色公开介绍和明确标注为社群语境的词汇。不会记录或推断中之人身份、隐私、争议的未经证实细节；世界观条目会保留“官方细节有限”的说明。

与珈乐相关的词条在库内标记为违禁品：数据保留在本地资料库中用于内部维护，但不会进入对外检索结果，也不会注入糖糖聊天模型的提示词；检索建议词同样不包含珈乐相关内容。

## 本地知识存储（SQLite）与审核

- 枝江百科和鸣潮梗库已统一迁入 `data/knowledge/knowledge.db` 的 `knowledge_entries` 表，两个 JSON 资源文件只作为首次播种来源。
- 每条词条带 `status`（approved/pending）、`source_priority`（0=本地整理、1=联网检索经人工审核、10=联网待审）、`updated_at`、`conflict_note` 字段；糖糖的预注入和查询工具只读取 `approved` 词条。
- 联网热更按仲裁链执行：本地已审核词条 > 联网检索经人工审核 > 联网待审 > 模型内部知识。联网提案不会自动覆盖本地词条，与现有词条冲突时写入 `conflict_note` 由管理员判断。
- 重叠条目不重复存储：事实类词条（直播时间线、大事记）以枝江百科为主，梗文化词条以鸣潮梗库为主，两边通过 `related_ids` 交叉引用；糖糖命中时会显示“相关词条”提示，模型可继续查另一侧。
- 管理员审核命令（仅超级管理员）：`#收录待审` 查看队列，`#收录确认 <编号>` 收录，`#收录拒绝 <编号>` 归档拒绝。
- 含珈乐等违禁内容的提案会被直接拒绝，不会进入数据库。

## 文件化审核流程（推荐）

除群内命令外，知识审核以 `data/knowledge/` 下三份 Markdown 文档为主：

- `收录待审.md`：待审核队列的完整文档，机器人每次启动和每次命令变更后自动重写，直接整块复制条目即可。
- `收录确认.md`：把待审中可以通过的条目整块复制进来；机器人每次启动会处理并清空。
- `收录拒绝.md`：把待审中不能通过的条目整块复制进来；机器人每次启动会归档并清空。
- `收录拒绝归档.md`：拒绝内容的常驻归档，每次启动和每次拒绝后刷新；不会进入糖糖检索，用于统计和重复内容自动拒绝。
- 误拒或需要重新考虑时，用 `#收录恢复待审 <编号>` 把归档拒绝的词条恢复到待审；直接编辑或删除归档文档不会生效，归档文档只是数据库镜像。

每次启动时的处理顺序：

1. 读取 `收录确认.md` 和 `收录拒绝.md`：确认的条目收录进知识库（approved），拒绝的条目归档为 rejected（保留在库中用于统计和去重）。
2. 清空这两份文档。
3. 对比 `收录待审.md` 对应的待审队列：凡是在确认/拒绝文档中出现过的内容（按 entry_id 或标题匹配），从待审中移除；没被处理过的条目保留，等待下次确认或否决。
4. 重写 `收录待审.md`。

拒绝过的内容后续再次出现（相同 entry_id 或相同标题）会被直接拒绝，不会重新进入待审；含珈乐等违禁内容的条目同样不会进入数据库。

枝江百科还包含行为规则类词条（不对外输出违禁历史，仅描述应对口径）：黑梗应对规则、李滇滇应对、毒唯/著名唯粉等黑话词义，以及老团曲版本覆盖原则与《Quiet》《超级敏感》《除夕》《传说的世界》等现行版本参考。这些词条与普通百科词条一样由 JSON 播种、SQLite 生效；被屏蔽成员相关提问由聊天代码注入应对指示，再由模型自然生成类似台词，原则固定。
