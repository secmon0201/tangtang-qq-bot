# 公开展示站模块化维护

## 目标与边界

公开展示站采用“构建时模块化、运行时纯静态”的结构。维护者可以独立处理页面、板块、共享布局、脚本、样式和更新日志，浏览器仍只接收完整 HTML、一个合并 CSS 和一个合并 JavaScript 文件，不依赖客户端动态拼装。

`site-src/` 是完整维护源，其中 `static/` 保存图片、vendor 和响应头输入；`site/` 只是当前线上兼容产物，构建器不会从它反向取源。公网网关只读取 `site/` 或 `data/public-site-releases/` 中由发布器完整生成的版本，不公开 `site-src/`、构建清单、仓库文档或运行数据。

## 增删查改

查看所有页面及板块顺序：

```powershell
.\.venv\Scripts\python.exe scripts\manage_public_site.py list
```

修改板块内容只编辑对应的 `site-src/pages/<页面>/<板块>.html`。页面标题、描述、路由和导航标签使用 `update-page`；同页重排和跨页迁移统一使用 `move-section`，它只移动引用，不复制内容。`remove-section` 和 `remove-page` 只解除清单引用，不自动删除源文件，便于复核和恢复。

新增页面时先准备至少一个板块文件，再用 `add-page` 一次登记页面键、公开路由、输出路径、标题、描述和板块。构建器会把路由写进该版本的 `_site-manifest.json`，网关无需再维护第二份页面列表。

更新日志保存在 `site-src/content/releases.json`。使用 `add-release` 追加版本、日期、标题和一条或多条已发布变更；空列表继续生成当前“敬请期待”页面。

页面和板块清单也是静态资源所有权清单。构建器只读取已登记的页面、板块、共享组件、样式和脚本引用；解除板块引用后，该板块独占的图片不会继续进入新版本。每个板块源文件只能归属一个页面，构建验证会拒绝重复挂载。

## 暂存与发布

所有改动先构建到独立目录：

```powershell
.\.venv\Scripts\python.exe scripts\build_public_site.py --output <暂存目录>
```

初次框架迁移可额外使用 `--check-current`，确认各页面正文和主要元素数量与当前公开站一致。日常内容更新不应使用该选项，因为新内容本来就会与旧站不同。

发布器默认只验证，不切换线上版本：

```powershell
.\.venv\Scripts\python.exe scripts\publish_public_site.py
```

完成仓库验证、浏览器桌面/移动回归和人工复核后，才显式执行 `--apply`。发布器先生成完整版本目录，再通过 `os.replace` 原子替换 `data/public-site-current.txt`；网关在每次静态请求时读取当前指针，因此不会看到半成品目录。旧版本保留在 `data/public-site-releases/`，可通过 `--rollback <版本目录> --apply` 原子回退。

## 带宽、缓存与并发

构建阶段为 CSS、JavaScript、图片和 vendor 文件生成内容指纹；大于 512 字节且适合压缩的文本同时生成 Brotli 和 Gzip 版本。PNG 只有在无损 WebP 与原图尺寸、RGBA 像素完全一致且至少节省 10% 时才替换，GIF 动画和没有实际收益的图片保持原样。非首屏图片使用延迟加载，全部图片启用异步解码。

网关使用 HTTP/1.1，允许同一访客复用连接；内容指纹资源使用一年不可变缓存，HTML 每次验证但可通过 ETag 返回 304。客户端同时支持 Brotli 和 Gzip 时优先 Brotli，压缩表示使用独立 ETag。`.br`、`.gz` sidecar 不能直接通过 URL 下载。

网关默认最多同时处理 32 个客户端，等待中的 TCP backlog 为 128，客户端空闲超时 60 秒，单个代理请求体上限 32 MiB。并发槽位耗尽时快速返回 503 和 `Retry-After: 1`，防止慢连接无限创建线程并拖垮同域名下的公告、运营、今日老婆和 NTE 路由。可在启动固定隧道时显式调整：

```powershell
.\scripts\start_tangtang_named_tunnel.ps1 -GatewayMaxConcurrency 32 -GatewayClientTimeoutSeconds 60 -GatewayMaxRequestMB 32
```

普通内容更新不需要提高这些值。应先压测本机网关并观察 CPU、内存和上游响应，再决定是否调整；并发上限不是访问人数上限，完成一个请求后槽位立即复用。

只读压测不会写文件或改发布指针：

```powershell
.\.venv\Scripts\python.exe scripts\benchmark_public_site.py --url http://127.0.0.1:18769 --requests 100 --concurrency 8
.\.venv\Scripts\python.exe scripts\benchmark_public_site.py --url https://tangtang.secmon.cn --requests 100 --concurrency 8
```

输出包括吞吐、p50/p95、状态码、实际传输字节和内容编码。本机结果衡量网关与静态文件，公网结果还包含 Cloudflare 边缘、隧道和访问者网络，二者必须分开记录。

## 上线纪律

- 不在公网运行期间逐个编辑 `site/` 页面、脚本或样式。
- 不把临时截图、报告、构建目录或发布版本提交到 Git；它们位于已忽略的 `data/` 或系统临时目录。
- 新版本必须先通过仓库全部验证，再完成首页、目标页面、移动导航、弹窗/复制等相关交互回归。
- 发布前使用临时目录构建；不得为了预览创建或改写 `data/public-site-current.txt`，也不得在验证过程中重启正在服务的网关或 Named Tunnel。
- 新增页面或静态资源必须确认未知路径、路径穿越、README、环境配置、数据库和日志仍然被网关拒绝。
