# 运维：安装与运行

Windows 本机唯一运行方式。技术链路为 `QQ/SnowLuma -> OneBot v11 reverse WebSocket -> NoneBot2`，业务数据保存在本地 SQLite。

## 首次安装

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[dev]"
Copy-Item .env.example .env
.\scripts\install_snowluma.ps1
```

编辑 `.env`，至少确认 `MANAGED_GROUP_IDS`、`BOT_OPERATOR_IDS`、`QQ_ACCOUNT_ID`、`BOT_COMMAND_PREFIX=#`、`BOT_REQUIRE_MENTION=false` 和响应延迟参数。`MANAGED_GROUP_IDS` 只作为首次迁移种子，群数量不设上限；后续群登记和开关以 SQLite 为准。

SnowLuma 固定版本和发行包 SHA-256 位于 `config\snowluma-lock.json`。机器人不读取 QQ 密码；协议确认、初始密码修改、QQ 扫码、滑块、短信和设备验证都在 `http://127.0.0.1:5099` 由用户手动完成。SnowLuma 的 OneBot 客户端连接到 `ws://127.0.0.1:8080/onebot/v11/ws`。

启动前运行：

```powershell
.\.venv\Scripts\python.exe scripts\validate_qq_config.py --env .env
```

## 统一入口

| 入口 | 用途 | 是否影响 QQ/SnowLuma |
| --- | --- | --- |
| `启动工具\01-启动全部.bat` | 启动 Core、NoneBot、SnowLuma、网页隧道和 watchdog | 会启动 |
| `启动工具\02-重启全部.bat` | 完整关闭后重启全部项目组件 | 会重启 |
| `启动工具\03-关闭全部.bat` | 关闭全部可确认归属的项目组件 | 会关闭网关；不删除登录数据 |
| `启动工具\11-仅重启机器人.bat` | 普通 Python 代码更新后只重启 NoneBot | 不影响 |
| `启动工具\31-启动守护程序.bat` / `32-关闭守护程序.bat` | 单独启停 watchdog | 不重启/不关闭 QQ |

完整说明见 [启动工具说明](../启动工具/README.md)。

## 独立运维脚本

```powershell
.\scripts\start_qq_transport.ps1
.\scripts\stop_qq_transport.ps1
.\scripts\status_qq_transport.ps1
.\scripts\watch_qq_transport.ps1 -Once
```

`status_qq_transport.ps1` 同时检查已配置的网关进程、NoneBot 监听、OneBot 客户端数量、客户端进程归属和 SnowLuma WebUI。健康状态要求 8080 正在监听、已配置网关进程唯一、OneBot 客户端唯一且属于该网关，防止旧网关残留或双网关重复收发。

## watchdog 行为

每 30 秒检查机器人监听和 OneBot 连接；连续 3 次失败才恢复，机器人恢复冷却 5 分钟，QQ 传输恢复冷却 15 分钟。隧道恢复脚本最多运行 120 秒，超时后 watchdog 会记录失败并继续下一轮，不能阻塞机器人检查；Named Tunnel 恢复不会重启 Core。

`data\qq-transport-watchdog-state.json` 中的 `last_check_started_at` / `last_check_completed_at` 是守护心跳，正常运行时至少每 30 秒更新一次。网关进程仍在但 OneBot 离线时只记录并等待人工登录，不会反复关闭 QQ；发现唯一客户端不属于当前配置网关时也只报警，不会再拉起第二个网关。日志在 `logs\qq-transport-watchdog.log`。

## 消息与响应规则

- 命令统一 `#指令 [参数]`，不需要 @；普通群消息不触发命令，只有被动互动读取指定群普通发言。
- 响应和 OneBot API 调用受延迟/最小间隔约束，不要靠高频轮询或连续重发实现秒回。
- 文本、图片、GIF、本地文件、Base64、转发消息、网页截图和自动公告统一经 OneBot 平台门面发送，不依赖 SnowLuma 私有 API。

## 热更新与永久保存

群登记、群域、代称、功能开关、被动互动参数、整点报时、过滤名单和白名单写入 SQLite，重启后恢复；群级修改不反写 `.env`。修改账号、OneBot 地址或代码级机器参数后需重启 NoneBot。

```text
.\scripts\backup.ps1              备份主业务 SQLite，写入 data\backups
.\.venv\Scripts\python.exe scripts\audit_database_backups.py --output reports\database-backup-audit.json
logs\bot.out.log                  机器人标准输出
logs\bot.err.log                  机器人错误输出
logs\bot.lifecycle.log            机器人启停与日志归档记录
logs\history\                     最近 20 次 NoneBot 启动前的日志
logs\snowluma.out.log             SnowLuma 标准输出
logs\snowluma.err.log             SnowLuma 错误输出
```

不要把 `.env`、Token、Cookie、密码、恢复码或扫码信息发到群里或提交到 Git。

## 验收检查

```powershell
.\.venv\Scripts\python.exe scripts\validate_qq_config.py --env .env
.\.venv\Scripts\python.exe -m pytest
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\watch_qq_transport.ps1 -Once
```

SnowLuma 登录是否成功仍需结合 WebUI、`Bot ... connected` 日志以及群内 `#QQ平台自检` 确认。

## 常见问题

- 机器人没有回复：确认 `#` 前缀、该群已自动登记、对应 `#群设置` 开关已启用、8080 上只有一个 OneBot 客户端。
- watchdog 进程存在但没有恢复：检查 `data\qq-transport-watchdog-state.json` 的完成心跳；超过 180 秒未更新即视为卡死，使用 `32-关闭守护程序.bat` 后再用 `31-启动守护程序.bat` 恢复。
- SnowLuma WebUI 无法打开：运行 `status_qq_transport.ps1`，再检查 `logs\snowluma.out.log` 与 `logs\snowluma.err.log`。
- 机器人异常退出：先查看 `logs\bot.err.log`、`logs\bot.lifecycle.log` 和 `logs\history\`，不要在保存证据前清空日志。
- 被动互动没有触发：确认 `#群设置 被动互动` 已开启，再由超级管理员检查该群概率、冷却和间隔。
- 准时报点没有发送：确认本群开关、全局运行条件、时段和整点后 5 分钟内在线。
- 重启后热更新丢失：确认数据库路径未变，不要用临时数据库启动第二个实例。
- 账号需要扫码：watchdog 不绕过验证，人工完成后再检查连接。
- Core 无法连接：确认 Core 先启动且监听 8765，`gsuid_core_host/port/ws_token` 与 Core 一致。
- PowerShell 禁止运行脚本：使用 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`，关闭窗口后失效。
