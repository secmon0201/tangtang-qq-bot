# 运维：灾备与恢复

灾备目标是恢复业务数据、机器人参数和可重新登录的运行链；缓存、截图和普通日志不是恢复前提。QQ 登录、二维码、滑块、短信和设备验证仍须人工完成。

## 恢复资产

| 优先级 | 资产 | 用途 | 处置 |
| --- | --- | --- | --- |
| 必须 | `.env` | 账号、端口、群范围、模型和通知参数 | 仅本机/离线介质保存，不提交 Git |
| 必须 | `data/bot.db` | 群设置、权限、统计、小游戏和公告状态 | 使用 SQLite 在线备份 |
| 必须 | `data/tangtang/tangtang.db` | 糖糖会话与群消息历史 | 停止写入后复制或使用 SQLite 在线备份 |
| 必须 | `GsUID.Core/data/GsData.db` 与玩家目录 | NTE、鸣潮绑定和玩家数据 | 整体离线复制；不得由项目脚本写入上游库 |
| 必须 | 私有 Git 仓库 | 项目源码、固定版本、文档和恢复脚本 | 保持可构建提交 |
| 建议 | SnowLuma 本地配置 | OneBot 配置与本机注入设置 | 离线保存；登录状态失效时人工重新登录 |
| 备用 | `Lagrange.OneBot*` | SnowLuma 无法使用时的人工传输灾备 | 不与 SnowLuma 同时接入生产 QQ |
| 可重建 | `.venv`、头像缓存、截图、日志、下载包 | 环境与运行产物 | 不作为核心灾备资产 |

## 当前备份边界

`scripts/backup.ps1` 只为活动 `data/bot.db` 创建一致性 SQLite 快照，写入 `data/backups/bot-时间.db`。它不是全量灾备工具；糖糖数据库、GsUID 数据、SnowLuma 配置和 `.env` 必须按上表另行离线保管。

现有 `data/backups` 暂不自动删除。运行以下只读审计生成报告，只记录文件元数据、SHA-256、SQLite 完整性、表名和行数，不导出任何用户记录：

```powershell
.\.venv\Scripts\python.exe scripts\audit_database_backups.py --output reports\database-backup-audit.json
```

只有在审计报告确认恢复价值、时间点覆盖和异地副本后，才制定备份保留策略。不能因文件名相近或大小相同就认定为重复备份。

## 恢复顺序

1. 停止 NoneBot、watchdog、GsUID Core 和 QQ 传输，保留故障现场副本。
2. 校验候选数据库 `PRAGMA quick_check`，记录文件大小、时间和 SHA-256。
3. 将当前损坏文件移出活动路径，再复制候选数据库；不要直接覆盖唯一副本。
4. 从私有 Git 检出与备份时间相容的项目版本，恢复 `.env` 和必要的 SnowLuma 配置。
5. 人工完成 QQ/SnowLuma 登录，执行七项仓库检查并运行 `启动工具\01-启动全部.bat`。
6. 验证 8080、OneBot、Core、WebUI、关键表行数以及真实群内收发，再解除故障现场保留。

异环、公告和运营网页的 `21` 至 `27` 号 Quick Tunnel 入口只用于固定域名不可用时的临时灾备，不替代数据库和配置备份。
