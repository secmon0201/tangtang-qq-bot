# 运维：迁移与维护清单

## NapCat 到 SnowLuma

迁移采用可回滚的两阶段切换。业务参数、群开关、权限、统计、小游戏状态、公告状态和 AI 参数继续由原 `.env` 与 `data/bot.db` 提供，不复制或重建业务库。

### 1. 预安装与 WebUI 初始化

```powershell
.\scripts\prepare_snowluma_migration.ps1
```

该脚本执行配置校验、SQLite 备份、固定版本/哈希安装，并以“禁用 OneBot 客户端”模式启动 SnowLuma。此时 NapCat 仍是生产网关，不会产生双客户端或重复发言。

在 `http://127.0.0.1:5099` 手动阅读并接受 SnowLuma 协议、修改初始密码。不要在这一步把生产 QQ 同时接入两个网关。

### 2. 开始停机切换

```powershell
.\scripts\begin_snowluma_cutover.ps1 -StartCutover
```

脚本会备份数据库和 `.env`，停止 watchdog 与当前网关，将旧账号和维护周期无损写入通用变量，启用 SnowLuma 反向 WebSocket，并重启 NoneBot。随后在 SnowLuma WebUI 中手动接入 QQ、扫码并完成设备验证。

切换脚本在停旧网关前会检查 SnowLuma 预安装进程、WebUI 监听、协议确认记录和初始密码修改状态。任一项未完成都会直接拒绝切换，不改变当前生产链。

### 3. 完成切换

SnowLuma 显示 QQ 在线且 OneBot 已连接后运行：

```powershell
.\scripts\complete_snowluma_cutover.ps1
```

只有在 SnowLuma 进程恰好一个、8080 OneBot 客户端恰好一个且客户端 PID 属于 SnowLuma 时，脚本才会重启 NoneBot 并恢复 watchdog。

### 4. 实机验收

静态合同只能证明本项目调用的 OneBot 动作已在固定 SnowLuma 版本中核对；登录后的真实 QQ 会话仍须逐项实机验收。每一行都通过后才视为完成迁移：

| 能力面 | 原有功能与触发 | SnowLuma 依赖 | 验收标准 |
| --- | --- | --- | --- |
| 被动消息 | 群聊、私聊、@、回复、自然语言路由、群开关 | OneBot v11 消息事件与数组消息段 | 原消息只触发一次，文本、@ 和回复上下文完整 |
| 主动发送 | 全局公告、Codex 完成通知、管理命令、跨群发送 | `send_group_msg`、`send_private_msg` | 目标群/私聊准确，无重复发送，失败可见 |
| 后台公告 | 整点报时、A-SOUL/B站动态/视频/开播/评论、今日老婆集体轮次 | 后台调度器加主动发送动作 | 手动测试与下一次真实调度各成功一次，去重状态不丢失 |
| 图片与动图 | 本地 PNG、远程图片、GIF、Base64、全局图片公告 | OneBot `image` 消息段的 URL、`file:///` 与 Base64 | QQ 客户端能实际打开，透明图/GIF不退化，图片公告到达全部目标群 |
| 网页截图 | A-SOUL HTML 卡片、公告海报、排行/帮助/运营图 | Playwright 本地截图后按 `file:///` 图片发送 | 页面正常构建，截图非空、尺寸正确，发送后的图片可查看 |
| 复合消息 | 回复、@、群/私聊合并转发 | reply/at 节点与 `send_*_forward_msg` | 引用对象正确，转发节点顺序和发送者信息完整 |
| 群互动管理 | 表情回应、撤回、禁言小游戏 | `set_msg_emoji_like`、`delete_msg`、`set_group_ban` | 正负消息 ID 均可用；权限不足时明确失败，不误操作 |
| 群与成员数据 | `#QQ平台自检`、群设置、排行、今日老婆、成员同步、头像缓存 | `get_login_info`、群/成员查询动作 | 自检通过；群名、角色、成员数量和头像刷新正常 |
| 历史与网页凭据 | 活跃度恢复、历史消息回填、依赖 QQ 网页态的采集 | `get_group_msg_history(reverse_order=true)`、`get_cookies`、`get_csrf_token` | 历史顺序不重复；Cookie 与 CSRF 能完成真实请求，敏感值不进日志 |
| 游戏接口 | `#nte`/`nte`、`#ww`/`ww`、帮助、绑定、查询和排行 | OneBot 消息/媒体层；GsUID Core 仍为独立上游 | NTE 与鸣潮各完成帮助、查询和排行；Core 离线不阻塞其他功能 |
| 网站与隧道 | 公告页、运营页、排行页、固定 Tangtang 隧道 | 与 QQ 网关解耦；仅截图/链接发送经过 OneBot | 本地和固定公网地址可访问，旧路由仍按约定返回 404 |
| 运维恢复 | 启停、状态、管理器、watchdog、NoneBot 单独恢复、回滚 | 唯一 SnowLuma 进程和唯一归属正确的 OneBot 客户端 | PID、8080、日志和心跳正常；断线时等待人工登录，不拉起第二网关 |

切换失败时脚本会从时间戳备份精确恢复原 `.env`，停止 SnowLuma，再恢复 NoneBot、原 QQ 网关和 watchdog。若无法确认 SnowLuma 已停止，脚本不会启动旧网关，以避免双客户端，并会明确提示需要人工处理。

验收完成前保留 `scripts\switch_back_to_napcat.ps1` 和旧本地运行目录作为临时回滚。验收全部通过后，才删除旧运行目录、旧脚本、旧环境变量和旧日志/状态文件。

### NapCat 残留台账

| 类型 | 当前保留项 | 原因 | 删除条件 |
| --- | --- | --- | --- |
| 切换回滚 | `scripts\napcat_process.ps1`、`start_napcat_transport.ps1`、`stop_napcat_transport.ps1`、`switch_back_to_napcat.ps1` | SnowLuma 实机验收失败时恢复原生产网关 | 全部实机验收通过，并确认不再回滚 |
| 旧 watchdog 收尾 | `scripts\watch_napcat.ps1` 及 `stop_watchdog.ps1` 中的旧 PID 清理 | 停止迁移前遗留的旧守护进程，防止它重新拉起 NapCat | 切换后确认旧 watchdog/PID/state 均不存在 |
| 旧参数兼容 | `NAPCAT_QQ_ID`、`NAPCAT_DIR`、`NAPCAT_MAINTENANCE_*` 的只读回退 | 首次切换时把现有值无损转写为 `QQ_ACCOUNT_ID`、`SNOWLUMA_DIR`、`QQ_TRANSPORT_MAINTENANCE_*` | `.env` 已转写且回滚期结束 |
| 旧数据库迁移 | `napcat_connection_incidents` 到 `qq_transport_connection_incidents` 的一次性迁移 | 保存既有断线事件和恢复耗时 | 所有现有数据库均至少启动过一次新版机器人后，可在后续版本移除迁移代码 |
| 历史统计回填 | `backfill_bot_message_stats.py` 与 NapCat 日志解析器 | 仅用于读取 2026-07-28 起的旧本地发送日志，不在日常事件链运行 | 确认历史数据已回填且无需重建后归档 |

活动业务代码、游戏 smoke 工具、管理器、文档站和日常启动入口不得直接依赖 NapCat。仓库测试也不得读取被忽略的 `NapCat.Shell` 运行目录。

## 迁移到新电脑

1. 停止机器人和 QQ 传输 watchdog。
2. 从私有 Git 仓库检出源代码、`bot/resources`、`config`、脚本和文档；通过离线安全介质另行复制 `.env`、`data/bot.db`、SnowLuma 本地配置与 `GsUID.Core/data`。
3. 新电脑安装 Python 3.13+ 与 QQ，随后在项目根目录执行 `python -m venv .venv`、`.venv\Scripts\python.exe -m pip install -e ".[dev]"` 和 `scripts\install_snowluma.ps1`。
4. 检查 `.env` 中的绝对路径、账号和端口设置；不要将 `.env`、登录会话或数据库提交到 Git。
5. 人工完成 SnowLuma/QQ 登录，运行 `scripts/validate_qq_config.py`，再用 `启动工具\01-启动全部.bat` 启动。

## 不需要迁移

- `.venv`、`build`、`dist`、`__pycache__`、`.pytest_cache`：本机生成的 Python 环境和构建缓存。
- `logs`、根目录 `reports`：运行日志与测试/设计评审产物。
- `downloads`：可重新下载且会校验 SHA-256 的安装包。
- `.codex/runtime`：Codex 任务运行时缓存；确认没有待处理任务后可重新生成。
- 根目录 `backups`：迁移完成且确认无需回滚后可归档到安全介质。

## 日常维护

- 用 `scripts/backup.ps1` 备份 SQLite 数据库；备份会写入 `data/backups`。
- 用 `scripts/status_qq_transport.ps1` 检查网关、8080 监听、OneBot 客户端数量和 WebUI。
- 需要重新生成管理器时运行 `scripts/build_manager.ps1`。
- 运行测试使用 `.venv\Scripts\python.exe -m pytest`。
- 提交前执行 AGENTS.md 中的全部七项检查。
- `GsUID.Core` 与 UID 插件保持独立、干净；上游版本由 `config/upstream-lock.json` 记录。
- 功能说明集中在 `docs`；根目录只保留项目入口和配置文件。
