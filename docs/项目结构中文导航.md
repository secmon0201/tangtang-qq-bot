# 项目结构中文导航

代码和工具链继续使用稳定的英文路径；中文只用于用户入口、说明和功能标签，避免 Python 导入、第三方更新与 CI 因路径翻译发生兼容问题。

## 普通用户从哪里开始

- 双击操作统一进入根目录的 `启动工具` 文件夹。
- 使用说明从 `README.md` 和 `docs/README.md` 开始。
- 日常只改机器人代码时使用 `启动工具/11-仅重启机器人.bat`。

## 根目录分类

| 路径 | 中文含义 | Git 处理方式 |
| --- | --- | --- |
| `bot/` | 机器人自研代码与静态资源 | 提交 |
| `config/` | 非敏感上游版本锁 | 提交 |
| `scripts/` | 开发、校验、安装和底层运维脚本 | 提交 |
| `tests/` | 自动化测试与架构契约 | 提交 |
| `docs/` | 当前有效用户和维护文档 | 提交 |
| `启动工具/` | 中文用户可双击的操作入口 | 提交 |
| `GsUID.Core/` | 独立上游 Core 与 UID 插件运行目录 | 不提交 |
| `NapCat.Shell/`、`Lagrange*` | 独立 QQ 传输运行目录 | 不提交 |
| `data/`、`logs/`、`tools/` | 本机数据、日志和下载工具 | 不提交 |
| `.venv/` | Python 虚拟环境 | 不提交 |

## `bot` 内部分类

| 路径 | 责任 | 依赖规则 |
| --- | --- | --- |
| `bot/plugins/` | NoneBot 命令、事件和定时入口 | 可调用 application/services，不得互相导入 |
| `bot/application/` | 跨入口用例编排与插件注册表 | 可调用 services，不得反向依赖 plugins |
| `bot/services/` | 业务逻辑、数据访问、渲染和平台门面 | 不得依赖 plugins/application |
| `bot/integrations/` | 对 GsUID 等外部运行时的本地兼容 | 不修改上游源码 |
| `bot/resources/` | 可复现、项目自有的静态输入 | 不放运行缓存 |
| `bot/config.py` | 环境配置解析和边界校验 | `.env` 本身不进入 Git |
| `bot/db.py` | SQLite 模式与持久化入口 | 运行数据库位于 `data/` |

## 功能如何独立注册

`bot/application/plugin_registry.py` 是唯一插件注册清单。每项都有稳定 ID、中文名称、类别、传输模式、启用条件和必要的加载顺序约束。

- 新增功能：新增一个 `bot/plugins/*.py` 入口，并在注册表增加一项。
- 修改功能：优先只改对应 plugin/service 及其测试。
- 删除功能：同时删除插件、注册项、专属 service/resource/test/doc。
- 注册遗漏、重复注册、插件互相导入、反向依赖、循环依赖和大段重复实现都会由测试或架构验证器拒绝。

共享配置、数据库、权限、消息发送和图片基础设施是有意复用的公共能力，因此“完全零影响”不是现实承诺；可保证的是功能入口不互相导入、业务边界明确、共享契约有测试，单一功能变化不会要求复制或同步修改其他功能实现。
